Longformer 的长上下文建模

2022年4月15日
|

在大语言模型（large language model，LLM）与预训练语言模型的演进中，Transformer1 (§1) 架构凭借自注意力（self-attention）捕获全局上下文依赖的能力，奠定了现代文本建模的基石。然而，标准全自注意力的计算时间与注意力矩阵显存消耗随着序列长度呈现二次方（O(n^2)）增长。在常规深度学习框架实现下，早期的 BERT 与 RoBERTa 等主流预训练模型普遍受限于 512 个 token（模型处理的基本序列单位，词元）的输入上限。

面对长篇小说、学术论文或跨文档推理任务，512 token 的输入限制迫使工程实践依赖文本截断（truncation）、滑动分块（chunking）或两阶段检索过滤（two-stage retrieval）1 (§2)。简单截断容易丢弃尾部关键事实；分块独立编码在底层缺少跨块自注意力，后续需通过上层任务模型另行拼接整合；两阶段检索若在第一阶段召回偏差，则会引发级联错误。

为了在长文本场景下降低计算开销，Beltagy et al. 于 2020 年提出了 Longformer 架构1 (§1)。该架构设计了一种随输入长度呈线性（O(n)）扩展的稀疏注意力模式，结合局部滑动窗口与任务驱动的全局注意力。需要首先明确的是，论文包含两组独立的模型与任务设定：一组是在因果解码器下进行的字符级自回归语言建模（character-level autoregressive language modeling，评估输入可达 32,256 字符），另一组是在 RoBERTa 基础上继续预训练的双向掩码语言模型（输入长度扩展至 4,096 token）。两者的单位、注意力掩码与位置机制各有不同，单次前向可接入的上下文跨度也不等同于模型的持久记忆容量。

1. 全自注意力的计算与显存开销

标准 Transformer 编码器（encoder）计算注意力权重的核心机制，依赖查询（query，Q）、键（key，K）与值（value，V）的内积映射1 (§3.1)：

标准多头自注意力的核心计算形式：
Attention(Q, K, V) = softmax( (Q · K^T) / sqrt(d_k) ) · V

在包含 n 个 token 的输入序列中，矩阵乘法 Q · K^T 需要计算所有位置两两配对的标量积，生成一个维度为 n × n 的注意力矩阵。

图示说明：标准全自注意力在每对 token 之间均计算注意力权重，矩阵呈现完全填充的稠密方阵，注意力矩阵显存开销随序列长度二次方增长；局部滑动窗口注意力仅在由窗口大小 w 确定的对角线附近带状区域内计算注意力，其余元素无需显式计算或存储，从而将复杂度降低为随序列长度线性扩展。

这种全连接计算带来了双重约束1 (§1, §3.2)：

  1. 浮点运算量二次方增长：前向传播与反向传播的乘加运算次数随序列长度平方级攀升；
  2. 训练期激活值显存占用：在常规显式存储注意力矩阵的实现中，反向传播需要保留该 n × n 的中间分布矩阵。当序列长度从 512 扩展到 4,096 时，该矩阵的显存需求理论上增大为原本的 64 倍，在给定硬件显存条件下容易发生显存溢出（out-of-memory，OOM）。

2. 局部稀疏注意力：滑动窗口与多层感受野

为了降低显存与计算开销，Longformer 将密集的注意力矩阵进行结构化稀疏（sparsify）变换，仅保留局部和特定位置的连接1 (§3)。

2.1 滑动窗口注意力与感受野累积

在自然语言文本中，词义与句法依赖具有极强的局部聚集性（local context）1 (§3.1)。Longformer 采用滑动窗口注意力（sliding window attention）：围绕每个 token 设定一个固定大小为 w 的窗口，即每个 token 仅与其左侧及右侧各 w / 2 个相邻 token 计算注意力。

在窗口大小 w 固定且远小于 n 时，单层自注意力计算的复杂度为 O(n × w)，随序列长度 n 线性增长。

滑动窗口多层堆叠的感受野逐层累积路径：

  • 第 1 层（底层）：每个 token 在局部窗口 w 内仅与相邻 token 交互；
  • 第 2 层（中间层）：基于下层激活继续进行局部聚合，有效感受野扩展至 2 × w；
  • 第 3 层（较高层）：感受野进一步扩散至 3 × w，覆盖更广跨度；
  • 第 L 层（顶层）：堆叠 L 层后理论感受野范围达到 L × w。

类似卷积神经网络（convolutional neural network，CNN）通过多层小卷积核累积感受野（receptive field），在 Transformer 中堆叠 L 层窗口大小为 w 的滑动窗口层，顶层 token 的理论感受野范围可达到 L × w1 (§3.1)。

2.2 字符级实验中的层级窗口与空洞模式

在字符级自回归语言建模实验中（因果解码器，窗口仅关注当前位置之前的字符，采用相对正弦位置机制）1 (§4.1)，论文探索了层间窗口策略：

  • 底层小窗口、高层大窗口：底层抽取局部字符与词法特征，高层扩大窗口建模更广范围。在小模型基于 text8 数据集第一阶段训练 150K 步的开发集控制实验中，窗口从底层 32 递增至顶层 512 的配置取得了 1.21 的每字符比特数（bits per character，BPC，该指标越低越好），优于递减配置（1.24）与固定均值配置（1.23）1 (§4.2.2, Table 4)。论文指出该中间对比用于控制试验，不保证最终完全训练或其他模型的排序完全一致；
  • 空洞滑动窗口（dilated sliding window）：类似空洞卷积，在固定窗口大小 w 上引入跨步间距 d（dilation gap），理论感受野可扩展至 L × d × w1 (§3.1)。在上述字符实验的高层结构中，作者仅在 2 个注意力头上配置空洞，兼顾局部连续性与长距跨越，将 150K 步的开发集 BPC 由 1.21 降至 1.201 (§4.1, Table 4)。

注意文献中的限定与推测：论文作者特别指出，在从标准预训练模型（RoBERTa）权重进行继续预训练时，加入空洞模式反而降低了下游任务表现；作者推测（suspect）跳跃采样的空洞模式可能与 RoBERTa 原有的全密集预训练权重不兼容，若要生效可能需要从头训练（retraining from scratch）1 (§5, footnote 8)。

3. 任务归纳偏置：对称全局注意力与解耦投影

纯局部的滑动窗口虽实现了线性计算，但在双向编码器处理分类或问答等下游任务时，信息传递面临路径过长的问题。例如，分类任务需要将全篇信息汇聚到特定的 [CLS] 标记；问答任务需要让问题 token 与全文候选证据建立跨段交互1 (§3.1)。因果解码器不能配置对称全局连接以防泄露未来字符，而双向编码器则可根据任务预先指定少量全局位置。

3.1 对称全局注意力结构

Longformer 为此在双向编码器下游微调中引入了任务驱动的全局注意力（task-motivated global attention）1 (§3.1)：

  1. 对称交互：被赋予全局注意力的 token 会关注序列中的所有 token，同时全序列的所有 token 也都会关注该全局 token；
  2. 维持线性复杂度：当预设的全局 token 数量 g 较少且独立于序列总长 n 时，局部与全局组合后的总计算复杂度为 O(n × (w + g))，依然保持对序列长度 n 的线性扩展1 (§3.1)。

图示说明（仅适用于双向编码器设置）：在预设的少数全局位置（如分类任务的 [CLS] 或问答任务的问题 token）上，全局标记与序列中所有 token 建立双向对称注意力连接；其余普通 token 之间保留局部滑动窗口，并通过全局节点在两层中实现间接信息交换。由于全局标记数量固定且独立于序列总长 n，整体计算复杂度依然维持线性扩展。因果自回归解码器不适用此类无掩码对称全局连接，以防未来字符信息泄露。

3.2 独立线性投影设置与消融证据

为了给局部与全局两类不同模式提供建模灵活性，Longformer 为滑动窗口与全局注意力分别设置了两组独立的线性投影矩阵1 (§3.1)：

  • 局部滑动窗口投影：使用 Q_s, K_s, V_s 计算局部窗口内的注意力得分，负责建模相邻 token 的局部上下文；
  • 全局注意力独立投影：使用 Q_g, K_g, V_g 计算全局标记与全序列的对称交互得分，初始化时复制对应局部投影的初始权重。

在 WikiHop 多跳问答任务（开发集，默认 5 epoch）中，论文通过消融实验评估了上述结构变体1 (§5.3, Table 11)：

模型配置变体（WikiHop 开发集）准确率（Accuracy）相对 5 epoch 基准差异（Δ）
Longformer-base（完整版，5 epoch）73.8%基准（seqlen: 4,096）
移除全局注意力独立线性投影72.2%-1.6 个百分点
同时移除独立全局投影与全局注意力65.5%-8.3 个百分点
序列长度 512、window 配置68.8%-5.0 个百分点

实验数据显示，在 WikiHop 开发集上，若同时移除独立投影与全局注意力，准确率由 73.8% 降至 65.5%（下降 8.3 个百分点）；若保留全局注意力但强制共享同一组线性投影矩阵，准确率降至 72.2%（下降 1.6 个百分点）。该对照表明在此特定任务配置下，解耦独立投影与引入全局连接均带来了性能收益。

4. 算子实现与训练策略

稀疏注意力虽然降低了理论计算量，但在常见深度学习框架中需要解决非稠密矩阵的硬件执行效率问题。

4.1 带状矩阵乘法与 TVM 自定义算子

滑动窗口注意力在矩阵运算上对应带状矩阵乘法（banded matrix multiplication），即仅需计算对角线周围特定带状区域的元素1 (§3.2)。

若直接使用通用框架的高阶循环遍历实现，因无法有效调度 GPU 线程高并发，计算速度极慢；若先构造完整稠密掩码再相乘，又会重新承受二次方显存占用。为此，Longformer 借助深度学习编译器 TVM（Tensor Virtual Machine）编写带状矩阵计算逻辑，并编译生成优化的 CUDA 内核1 (§3.2)。

根据论文图 1 算子基准测试（Benchmark）1 (§1, Figure 1)，该 TVM 自定义算子使内存消耗随序列长度线性增长，其在测试硬件下的运行速度比 PyTorch 简单循环快近 6 倍，并接近针对稠密矩阵高度优化的全自注意力算子。

4.2 字符级自回归实验中的分阶段训练与精度设置

在字符级自回归语言建模训练中，若直接在长序列上从头开始训练，计算消耗依旧较大。论文发现模型需要先通过较多步数学习局部语境，随后再学习利用远距离依赖1 (§4.2)。

因此，该实验采用了分阶段训练策略（staged training procedure）1 (§4.2)：

  • 第 1 阶段：在序列长度 2,048、底层窗口 32 下开始迭代；
  • 后续阶段：逐步将序列长度与窗口大小翻倍，同时减半学习率；
  • 最终阶段：序列长度为 23,040，底层窗口扩大至 512，将开销最大的长序列训练推迟至最后阶段完成。

在数值精度方面，虽然实验采用了混合精度与梯度检查点（gradient checkpointing）以节省显存，但作者指出注意力得分的运算保持在 FP32 精度；论文实验观察到若在注意力算子中使用 FP16，在训练后期容易出现浮点溢出并产生 NaN1 (§4.2, footnote 5)。

4.3 位置嵌入扩展与继续预训练

为了让预训练上限为 512 的 RoBERTa 双向模型能够直接处理 4,096 token 的输入，Longformer 将 RoBERTa 原有的 512 个已训练位置嵌入（positional embedding）沿序列连续复制多次（copy position embeddings）1 (§5)。

基于局部相邻位置注意力偏好的观察，这种复制初始化在保留局部相对结构（分段边界除外）的同时避免了随机初始化带来的早期扰动。在掩码语言建模（masked language modeling，MLM）开发集上，未经更新时随机初始化的 BPC 为 10.299，而复制初始化则为 1.957（接近原版 RoBERTa 的 1.846），随后经过 65K 步继续预训练（continued pretraining）收敛至 1.7051 (§5, Table 6)。

5. 真实信息利用的边界

将注意力计算开销降至线性，使模型具备了接入数千 token 的物理可行性。然而，输入窗口可容纳的 token 数量，并不等同于模型实际能够提取并推理的信息量。论文在多个下游任务开发集上的系统对比，反映出长上下文收益的实际边界1 (§5.2)。

评测任务与数据集（开发集）RoBERTa-base 基线Longformer-base（4,096）
多跳问答 WikiHop (Acc)72.4%（分块拼接）75.0%（15 epoch，+2.6 个百分点）
篇章分类 Hyperpartisan (F1)87.4%（分块拼接）94.8%（+7.4 个百分点）
开放问答 TriviaQA (F1)74.3%（分块拼接）75.2%（+0.9 个百分点）
多跳问答 HotpotQA (Joint F1)63.5%（分块拼接）64.4%（+0.9 个百分点）
共指消解 OntoNotes (Avg F1)78.4%（分块段长 384）78.6%（无全局注意力，+0.2 个百分点）

从上述对比中，可以梳理出长上下文实际利用的几处边界：

5.1 收益分化：取决于任务的证据分布

在 RoBERTa 基线中，长文本被切分为最长片段（除共指任务调优为 384 外通常为 512）分别编码并拼接表征1 (§5.1)：

  1. 显著收益任务（WikiHop 与 Hyperpartisan）：证据分散在多个段落且需要跨段关联，Longformer 单次前向覆盖完整篇章带来了明显提升（WikiHop 提升 2.6 个百分点，Hyperpartisan 提升 7.4 个百分点）；
  2. 平缓收益任务（TriviaQA 与 OntoNotes）：在 TriviaQA 中，回答问题所需的证据往往集中在局部上下文内，单次窗口扩大的边际增益相对温和（提升 0.9 个百分点）；在 OntoNotes 共指消解中，语料中绝大多数指代词与其实体距离较短，分块拼接基线已能解决大部分情况，因此在扩大局部输入段长后（该任务未配置全局注意力），平均 F1 仅提升 0.2 个百分点。

5.2 篇章连贯性与结构归纳偏置

在 HotpotQA（干扰项开发集）中，模型需从 10 个维基百科段落中提取证据与答案（2 个段落相关，8 个为干扰项）1 (§5.1)。

Longformer-base 在该任务上的联合 F1 仅提升 0.9 个百分点（64.4% vs 63.5%），表现低于专门引入图神经网络（graph neural network，GNN）的多阶段流水线模型（如 HGN 73.0%、C2F 73.9%）1 (§5.2, Table 10)；对于 TAP2，原表仅给出答案 F1 79.4 与支撑证据 F1 86.2，未提供联合 F1 数据。

  • 非连贯篇章拼贴：作者推测，由于 10 个段落来自完全不同的文档，拼接后的输入缺乏自然文本的篇章连贯性，可能影响模型利用预训练中形成的长程上下文先验；
  • 实体图偏置的作用：作者认为图结构模型似乎编码了针对该任务的重要归纳偏置；作者在脚注 12 中同时指出，未来亦可通过在实体位置配置全局注意力来尝试编码此类结构先验。

5.3 稀疏连接的信息聚合边界

在纯局部配置中，远距离交互需要沿窗口逐层传递；加入全局节点后，两个普通 token 也可经全局节点在两层中进行间接信息交换。直接连接与理论可达性仍不保证下游任务能有效利用全部远端证据。

5.4 具体任务与显存边界

尽管稀疏机制将自注意力开销降至线性，但从张量规模看，前馈网络（feed-forward network，FFN）张量与多层隐层激活依然占据可观显存。在论文实验中，WikiHop 的 Longformer-large 模型因显存限制仅能输入首个 4,096 token 的序列（Appendix B WikiHop），而 TriviaQA 截断在 4,096 的原因则是为了避免训练时间过长（该实验中 large 模型在 8 张 V100 GPU 上运行 1 天）1 (Appendix B)。

6. 机制与权衡总结

在双向编码器的下游任务中，Longformer 结合局部窗口与少量任务全局位置；另一个字符级自回归实验使用仅看前文的滑动与空洞窗口。两者都减少了注意力连接，但长度单位、掩码与任务不同。输入窗口的扩大属于单次前向可接入文本范围的扩展，其对下游性能的实际提升依然受限于任务的证据分布结构、文本本身的连贯性以及具体的稀疏连接模式。理解局部稀疏化、全局连接通路与任务结构之间的匹配关系，是在长文本场景下合理利用该机制的必要前提。
