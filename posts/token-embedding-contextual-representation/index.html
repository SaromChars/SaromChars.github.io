从文本到上下文表示：Token、分词与嵌入

2022年3月7日
|

在上一篇讨论 Transformer 自注意力机制（self-attention）时，我们的推导从一个形状为 n × d_model 的输入表示矩阵 X 开始。自注意力层通过线性投影矩阵将其映射为查询（query，Q）、键（key，K）、值（value，V），再通过点积与加权求和，计算序列内部各位置之间的关联。

但在实际系统中，计算机与神经网络无法直接读取原始的自然语言字符串。一段像“Attention is all you need”或“今天天气真好”的文本，在进入注意力矩阵乘法之前，必须经过一条完整的转换链路：

原始文本 (String)
   │
   ▼
1. 分词器切分 (Tokenization) ─── 得到离散 token 序列: [token_1, token_2, ..., token_n]
   │
   ▼
2. 词表映射 (Vocabulary Lookup) ── 得到整数索引序列: [id_1, id_2, ..., id_n]
   │
   ▼
3. 嵌入层查表 (Embedding Lookup) ── 查取可学习嵌入矩阵 E 中的行向量: n × d_model
   │
   ▼
4. 注入位置信息 (Positional Encoding / Embedding) ── 叠加序列位置特征
   │
   ▼
5. Transformer 多层计算 ────── 生成随上下文动态演化的隐藏表示 (Contextual Representation)

图：从原始文本到嵌入向量与上下文表示的处理链路（教学示意）

这条链路中的每一步都有明确的数学形式与工程取舍。弄清符号如何变成离散编号、编号如何映射为稠密向量，以及静态向量如何在多层网络中被赋予上下文，是理解后续自回归生成与预训练（pretraining）过程的基础。

分词与 Token：文本切分的基本单元

将连续文本切分成离散符号的过程称为分词，负责这项任务的组件叫做分词器（tokenizer）。被切分出来的离散单元统称为 token（在自然语言处理中常作为模型处理的序列单位，中文文献中有时也称作“词元”）。

在自然语言处理早期，切分策略往往面临两难选择：

  • 以完整词为单位（Word-level）：例如在英文中按空格和标点切分单词。这种方案的缺陷在于词表难以闭合。语言中存在大量的派生词、屈折变化、复合词（如德语中的“Abwasserbehandlungsanlage”，意为污水处理厂）以及专有名词。如果要覆盖所有词汇，词表规模会膨胀到数百万，导致模型参数失控；而如果限制词表大小，未登录词（out-of-vocabulary，OOV）就会被粗暴地替换为统一的未知标记（如 [UNK]），丢失大量有效信息。
  • 以字符为单位（Character-level）：例如将文本彻底拆分为单个字母或单字。字符集通常较小（英文只有几十个字符），几乎不存在未登录词问题。但字符本身包含的语义信息过于稀疏，切分后的序列长度会成倍膨胀，这会使具有二次方计算复杂度的自注意力层承受极大的计算与显存压力。
  • 中文切分的特殊性：中文书写天然没有空格分隔，既可以按单字切分，也可以按词语切分。若完全按词切分，同样存在词表膨胀与未登录词问题；若完全按字切分，又无法直接体现多字词的紧凑结构。

为了平衡词表大小与序列长度，现代语言模型普遍采用子词（Subword）切分算法。子词的核心思想是：保留常见的高频完整词，而将罕见词拆分为若干更小、更基础的片段（子词）。

2015 年，Rico Sennrich 等人在论文《Neural Machine Translation of Rare Words with Subword Units》1 中，将数据压缩领域的字节对编码（Byte Pair Encoding，BPE）引入机器翻译的分词任务中。

BPE 算法的运作机制

BPE 是一种基于统计频率的贪心合并算法 1 (Sennrich et al., §3.2)：

  1. 初始化：首先提取训练语料中的所有词汇及其词频。将每个词拆分成单个字符构成的序列，并在词尾添加特殊终止标记（例如 </w>），以保留词边界信息。此时的基础词表仅由语料中出现的所有独立字符组成。
  2. 统计频次：遍历当前词表中的所有拆分序列，统计所有相邻符号对（symbol pairs）在全语料中出现的总频次。
  3. 合并最高频对：找出频次最高的一对相邻符号（假设为 'e' 和 'r'），将其合并为一个新的复合符号 'er'，并将新符号加入词表中。
  4. 迭代重复：在语料中将所有出现的该符号对替换为合并后的新符号，然后重新统计、选出下一个最高频对进行合并。这个循环持续进行，直到合并操作达到预设的次数，或者词表大小达到目标阈值。

通过这种方式，出现频率极高的词（如 the、is）在经过多次合并后会成为一个独立的完整 token；而罕见的生僻词（如 unhappiness）由于完整共现频率较低，在中间阶段停止合并，最终被切分为常见的子词组合（如 un + happi + ness）。

需要明确的是，Sennrich 等人（2016）是在神经机器翻译（neural machine translation，NMT）的背景下验证 BPE 的，其目的是解决跨语言翻译中的专有名词、复合词与生僻词处理问题。后续的大语言模型（large language model，LLM）虽然广泛采用了子词切分思想，但在实现上衍生出了不同方案：例如 BERT（Devlin et al., 2018）3 采用的是 WordPiece 算法；而在 GPT-3（Brown et al., 2020）4 中，分词器直接从字节表示出发运行字节级 BPE，合并后的 token 可以包含多个字节，这同样表明 token 并不等同于单个字节。因此，不能将 2016 年面向机器翻译的 BPE 论文等同于所有大语言模型的唯一实现。

关键结论：token 是模型处理序列时的离散符号单元，它既不必然等于一个完整的自然语言词，也不必然等于一个汉字、单个字母或单个字节。一段给定的文本究竟会被切分成怎样的 token 序列，完全取决于所选用的分词器规则及其预先构建的词表。

离散符号到数值索引：词表 ID 的含义与边界

在分词器构建完成后，会固定生成一个词表（Vocabulary，记作 V）。词表本质上是一个双向映射字典，记录了所有受支持的 token 与非负整数索引之间的对应关系：

Token 集合 ──────── 双向映射 ──────── 整数索引 (ID)
"[PAD]"     <─────────────────>     0
"[UNK]"     <─────────────────>     1
"the"       <─────────────────>     2
"river"     <─────────────────>     3
...
"apple"     <─────────────────>     1024
"orange"    <─────────────────>     1025
...

词表的大小即为词表包含的 token 总数 |V|，在主流模型中通常在 30,000 到 50,000 左右（部分多语言模型更大）。

当一段文本被切分为长度为 n 的 token 序列后，分词器会逐一查询词表，将符号序列转换为一个一维整数数组：

输入文本:  ["river", "bank"]
词表 ID:   [3, 852]

在这里，必须厘清关于词表 ID 的几条重要边界：

  1. ID 仅仅是离散的类别索引（categorical index）：整数数值的大小没有任何几何或代数含义。ID 为 1024 的 token 与 ID 为 1025 的 token，并不比 ID 为 8000 的 token 具有更接近的语义。
  2. ID 无法直接参与数值计算：我们不能对 ID 进行加减乘除（例如不能用 ID 1024 加上 1 来推断新概念），也不能把 ID 直接作为特征数值输入给神经网络的线性层。如果将整数标量直接输入线性层，网络会将数值大小当作物理量，赋予 8000 远大于 3 的权重影响，这在数学上完全背离了语言的符号性质。

为了让神经网络能够处理这些离散符号，我们需要将每个标量 ID 转化为连续高维向量空间中的一个点。

嵌入矩阵查表：可学习的静态词向量

将离散的整数 ID 转换为连续稠密向量的组件，就是嵌入层（embedding layer）。

在概念与参数构成上，嵌入层由一个可学习的权重矩阵构成，通常记为 E，其形状为：

E ∈ R^(|V| × d_model)

其中 |V| 表示词表的大小，d_model 表示模型的隐藏表征维度（例如在原版 Transformer 中为 512，在 BERT-Base 中为 768）。矩阵中的每一行，都对应词表中特定 ID 所代表的连续向量表示。

查表操作与 One-Hot 的等价性

当输入序列包含 n 个 token，其对应的整数 ID 序列为 [id_1, id_2, ..., id_n] 时，嵌入层的作用就是按索引提取矩阵 E 中的对应行：

e_1 = E[id_1]
e_2 = E[id_2]
...
e_n = E[id_n]

将这 n 个行向量按顺序堆叠，就得到了输入表示矩阵 X_emb ∈ R^(n × d_model)。

从线性代数的数学形式上，这一行抽取操作与 One-Hot 向量乘法是完全等价的：

设 p_i 是一个维度为 1 × |V| 的 One-Hot 向量，其中仅在第 id_i 个分量上取值为 1，其余 |V|-1 个分量均为 0。那么：

e_i = p_i * E

这个矩阵乘法在数学结果上恰好筛出了 E 的第 id_i 行。

在实现中，程序通常直接根据整数索引从嵌入矩阵中取出对应行，而无须显式构造 One-Hot 向量。不过需要注意，序列包含 n 个 token 时，输出的是 n 个 d_model 维的向量数据，因此实际涉及 n × d_model 个数值的读取与传输，按索引定位行并不意味着整体读取与构建成本是无视序列长度的绝对常数。

嵌入矩阵的参数性质

在 Vaswani 等人（2017）的 Transformer 架构中 2 (Vaswani et al., §3.4)，嵌入层具有以下参数特征：

  1. 可学习参数：矩阵 E 的所有分量都是模型的权重参数，在训练开始前随机初始化（或加载预训练权重），并在反向传播中随梯度更新不断调整位置。
  2. 权重共享与缩放：在原版 Transformer 中，输入嵌入层、输出嵌入层以及预测下一个 token 的线性变换矩阵（Pre-softmax linear transformation）共享同一套权重矩阵 E；同时，在嵌入层中将查表所得的权重乘以了缩放因子 sqrt(d_model)，以此让嵌入向量的模长与位置编码的数值尺度相匹配。
  3. 输入端的静态性：在特定模型权重固定的前提下，无论一个 token 出现在句首、句尾，还是出现在完全无关的话题中，只要它在输入嵌入层查表，取出的行向量 E[id] 就必然是完全相同、静态固定的。输入嵌入层本身不具备感知上下文的能力。

需要说明的是，嵌入向量的具体数值由模型训练优化决定，单个坐标轴并不单独对应孤立概念，静态向量间的空间距离也不自动等价于先验语义（后文将在概念辨析中具体讨论其几何边界）。

一个简化的数值教学示意

为了清晰展示从文本到矩阵的完整过程，以下构造一个手工设计的极简数值例子。

说明：本节用于展示维度与矩阵流向，分词切分、词表 ID 与行向量数值均为人工构造的教学示意，非真实分词器输出，亦非真实模型训练参数或实测数据；所有数值在本文内部保持自洽。

假设我们定义了一个微型词表，大小 |V| = 6，设定表征维度 d_model = 3：

词表 ID (Index)Token 字符串对应的嵌入行向量 (E 中的行)
0"[PAD]"[ 0.0, 0.0, 0.0]
1"河"[ 0.2, 0.8, -0.1]
2"水"[ 0.1, 0.9, 0.2]
3"浅"[-0.4, 0.5, 0.7]
4"苹果"[ 0.9, -0.3, 0.4]
5"手机"[ 0.8, -0.5, 0.6]

此时嵌入矩阵 E 是一个 6 × 3 的数值矩阵。

现在输入一段简短文本："河水浅"。

  1. 分词处理：分词器将其切分为 3 个 token：["河", "水", "浅"]，序列长度 n = 3。
  2. ID 映射：依次查询微型词表，得到离散 ID 序列：[1, 2, 3]。
  3. 嵌入查表：
    • 第 1 个 token "河"（ID=1）：提取 E[1]，得到 [ 0.2, 0.8, -0.1]
    • 第 2 个 token "水"（ID=2）：提取 E[2]，得到 [ 0.1, 0.9, 0.2]
    • 第 3 个 token "浅"（ID=3）：提取 E[3]，得到 [-0.4, 0.5, 0.7]
  4. 输出矩阵：将这 3 个行向量堆叠，得到形状为 3 × 3 的输入嵌入矩阵 X_emb：
X_emb = [
  [ 0.2,  0.8, -0.1],   # 对应 "河"
  [ 0.1,  0.9,  0.2],   # 对应 "水"
  [-0.4,  0.5,  0.7]    # 对应 "浅"
]

如果文本顺序颠倒为 "浅水河"，其离散 ID 为 [3, 2, 1]，查表所得的矩阵行也会相应颠倒。

注入位置信息：位置编码与位置嵌入

在上一篇中我们指出：在未加入位置信息且没有依赖位置的固定掩码（如因果掩码）的前提下，自注意力运算具有置换等变性（permutation equivariance）。若直接以未经位置修饰的嵌入矩阵行作为输入，模型在数学上无法辨别 token 在序列中的先后次序。

为了引入词序线索，原版 Transformer 与 BERT 采取了在网络底层将位置向量与 token 嵌入向量直接相加的方案：

X = X_emb + P

其中 P ∈ R^(n × d_model) 是位置表示矩阵。不同模型在位置表示的具体实现上有所不同：

  1. 固定正弦/余弦位置编码（positional encoding）： Vaswani 等人（2017）2 (Vaswani et al., §3.5) 采用固定的正弦与余弦周期函数直接计算各维度数值，无需引入额外的可学习参数。
  2. 可学习位置嵌入（positional embedding）： 在 BERT（Devlin et al., 2018）3 (Devlin et al., §3.2) 中，模型构造了一个可学习的位置嵌入矩阵，支持最长 512 个 token 的序列，输入序列中第 i 个位置直接查取对应的位置行向量与词向量相加。

两者的术语存在细微区分：通过固定数学函数直接计算的通常称为位置编码（positional encoding）；而作为模型参数随训练更新的通常称为位置嵌入（positional embedding）。需要说明的是，底层直接相加是原版 Transformer 与 BERT 的具体设计选择，并不代表所有后续注意力网络都必须采用完全相同的输入前相加结构。

Transformer 从静态词向量生成上下文表示

同一 token 在嵌入层查得相同的输入嵌入向量（input embedding）。经过自注意力与前馈网络的多层变换后，它的上下文表示（contextual representation）可以随语境改变。

自注意力的动态特征混合

回顾上一篇讨论过的自注意力计算核心公式 2 (Vaswani et al., §3.2.1)：

Attention(Q, K, V) = softmax( (Q * K^T) / sqrt(d_k) ) * V

在多头注意力（multi-head attention）中，每个注意力头在掩码允许的位置范围内计算注意力权重，并对对应位置的 Value 向量进行加权求和，随后将各头的输出拼接并通过线性投影整合。

随后的前馈网络（feed-forward network，FFN）、残差连接和层归一化在每一层持续复合这种变换。经过多层堆叠之后，顶层输出的隐藏状态向量 h_i 已经发生了显著变化：

  • 语境融合机制示意： 假设词表中包含单个 token "苹果"。在无因果掩码的双向编码器（bidirectional encoder）结构中，注意力机制允许每个位置同时与上下文各位置交互。
    • 在输入嵌入层查表时，无论语境如何，它取出的静态行向量都是同一行 E[ID_苹果]。
    • 当输入包含句子 "果农采摘了红富士苹果" 时，在双向自注意力计算中，在某个注意力头中，"苹果" 所在位置可能对同句中的 "果农"、"采摘" 或 "红富士" 等位置分配一定权重，从而在加权求和中汇入这些上下文位置的特征。
    • 当输入变为句子 "他在发布会购买了苹果笔记本" 时，若处于双向编码器下，"苹果" 同样可能关注到其右侧的 "笔记本" 以及左侧的 "购买" 等词项，进而融合不同的上下文信息。
    • 但需要特别注意：在带有因果掩码（causal mask）的单向自回归解码器（autoregressive decoder）中，位置 i 只能关注自身及左侧历史 token（位置 ≤ i），无法看到其右侧尚未生成的 token（例如处于 "苹果" 右侧的 "笔记本"）。上述语境差异仅作为双向注意力层信息聚合机制的原理演示，不代表特定模型在训练后必然产生某种预设的注意力权重或固定的语义空间位移。

架构约束对上下文可见性的影响

不同模型架构对上下文的捕获方式存在明确的结构差异：

  • 双向编码器（如 BERT）：Devlin 等人（2018）3 提出的 BERT 是深层双向 Transformer 编码器（bidirectional Transformer encoder）的代表例子。在 BERT 中，没有因果掩码遮挡，任何一个 token 都可以同时关注到它左侧和右侧的全部 token，因此每个位置的输出都是全向上下文融合的结果。
  • 单向自回归解码器（如 GPT）：以 GPT-3（Brown et al., 2020）4 为代表的自回归解码器，通过因果掩码限制了对右侧上下文的可见性，每个位置只能关注到历史 token，其表示由单向历史累积而成。

BERT 是双向 Transformer 编码器的典型例子，与自回归解码器在上下文可见性及训练目标上存在根本区别，不能将其结构直接套用到纯解码器模型中。

概念边界辨析

在日常技术讨论中，一些与“向量”相关的术语容易被模糊混用。在此需要做出严格的区分：

1. 输入嵌入 vs. 上下文隐藏状态 vs. 句段检索向量

  • 输入嵌入（Input Token Embedding）：是模型底层的可学习查表参数，属于 token 级别的静态映射。每个 token 的输入向量仅取决于其在词表中的索引，不随语境改变。
  • 上下文隐藏状态（Contextual Hidden State）：是文本输入模型后，各 Transformer 隐藏层输出的特征激活值，属于 token 级别的动态表示。序列包含多少个 token，对应层就会输出多少个上下文隐藏向量（形状为 n × d_model）。
  • 句段检索向量（Dense Retrieval Representation）：是指在稠密检索（dense retrieval）等方法中，用于表示整个句子或文本片段的定长向量表示。这类表示通常需要针对特定的语义相似度或检索任务进行专门的微调或训练。

常见概念混淆： 容易产生的一种误解是，认为直接将一个句子中所有 token 的输入嵌入或最终隐藏状态取平均（mean pooling），就能自然获得高质量的句段检索向量。事实上，输入嵌入、上下文隐藏状态与专门用于句段匹配的向量在设计目标上并不相同；未经针对性任务训练或评估，直接对 token 向量做简单平均并不能保证在下游检索任务中的表征质量。

2. 向量空间的几何距离不等于绝对语义真理

在连续向量空间中，两点之间的余弦相似度或欧氏距离，反映的是模型在特定训练目标与损失函数优化下形成的参数分布与特征关联。

余弦相似度较高，仅体现出对应符号或上下文状态在统计分布及网络内部信息处理中呈现出的相近模式；它并不等同于在自然语言中必然具有先验的语义等价关系。我们不能脱离具体的训练任务与模型结构，将几何距离或某个维度的坐标值单独视为客观恒定的“语义真理”。

总结

文本进入语言模型的全过程，是一条严谨的“离散符号结构化，连续向量动态化”的变换链：

  1. 分词阶段：通过 BPE 或 WordPiece 等子词切分算法，将连续文本切分为词表所收录的离散 token 序列，在词表规模与序列长度之间取得平衡。
  2. 编号阶段：将每个 token 映射为词表中的整数索引 ID。ID 是纯粹的类别标识，不含连续几何意义。
  3. 查表阶段：利用整数 ID 从可学习的输入嵌入矩阵中抽取对应的行向量，在底层通过高效的内存索引实现，概念上等价于 One-Hot 乘法。
  4. 位置融合：通过正弦位置编码或可学习位置嵌入，将位置序列信息叠加到静态词向量中，打破自注意力天然的置换等变性。
  5. 上下文表征：静态词向量进入 Transformer 多层结构后，自注意力机制根据 Query-Key 匹配权重动态聚合上下文 Value 向量，最终生成能够反映当前语境的丰富隐藏表示。

弄清了文本如何变为向量以及隐藏表示如何在上下文中演化，接下来便可以进一步探讨：模型如何利用这些隐藏状态预测下一个 token 的概率？自回归文本生成是如何一步步展开的？这将在本系列的下一篇文章中详细讨论。
