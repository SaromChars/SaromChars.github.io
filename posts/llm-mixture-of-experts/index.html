稀疏专家模型中的计算分配

2022年5月2日
|

在大语言模型（large language model，LLM）的参数扩展历程中，传统的稠密 Transformer 架构对每一个输入的 token（模型处理的序列单位，亦称词元；后续统一使用 token）通常在各层使用同一组网络参数1 (§1)。随着模型尺寸从亿级迈向百亿甚至千亿，前向与反向传播的浮点运算次数（floating point operations，FLOPs）随参数量线性膨胀，导致预训练（pretraining）与推理（inference）的算力成本极高。

为了在不按比例增加单 token 计算量的同时扩充模型容量，条件计算（conditional computation）演化出了混合专家模型（Mixture of Experts，MoE）范式。该机制保留注意力层不变，而将标准前馈网络（feed-forward network，FFN）替换为一组并行的专家网络，由轻量级的路由器（router）根据输入特征决定计算路径。

Fedus et al. (2021) 在固定版本（arXiv:2101.03961v1）中提出的 Switch Transformer 简化了此前的多专家路由策略。下文探讨单专家路由分配、专家容量控制、训练稳定化措施及其实际应用边界。

1. 单专家路由与计算解耦

早期的 MoE 探索（如 Shazeer et al., 2017）通常采用 Top-k 路由策略（例如选择 k=2 个专家），即每个 token 同时被派发给两个最佳专家计算后再做加权求和1 (§2.1)。该设计基于当时推测：路由器需要对比多个专家的打分并接收多路反向传播梯度，才能学到有效分配策略。

1.1 Switch 路由机制

Switch Transformer 抛弃了多专家组合假设，改为纯粹的单专家路由（Top-1 路由），将其命名为 Switch 层1 (§2.1)。对于维度为 d_model 的输入 token 表征 x，以及由 N 个专家组成的集合 {E_1, E_2, ..., E_N}，路由器权重矩阵 W_r 首先计算该 token 在各专家上的门控打分（logits）：

h(x) = W_r * x

随后通过软最大值（softmax）函数得到对全体 N 个专家的归一化概率分布：

p_i(x) = exp(h(x)_i) / sum_{j=1}^N exp(h(x)_j)

路由器选出概率最高的一位专家 k = argmax_i p_i(x)，该层的最终计算输出定义为所选专家的前馈变换结果乘以对应的门控概率：

y = p_k(x) * E_k(x)

将路由目标收敛为单专家带来了三项直接收益：

  1. 路由计算精简：仅需单次求极值，省去多专家加权融合的额外开销；
  2. 专家批容量需求降低：相比于将每个 token 同时派发给两名专家的 Top-2 配置，单专家路由让每个 token 仅产生一份前向计算，专家所需的最小批处理容量减半；
  3. 通信开销缩减：在分布式张量切分下，跨设备派发与聚合的数据包体积显著减少。

2. 静态硬件下的专家容量与溢出机制

在分布式硬件系统（如 TPUs 上的 Mesh-TensorFlow）中，为了优化硬件编译与张量执行效率，底层张量形状通常需在编译期静态确定1 (§2.2)。然而，动态路由可能导致大量 token 涌向少数热门专家，引起负载不均。

2.1 专家容量公式

为了在静态分配下处理动态路由，Switch Transformer 设定了专家容量（expert capacity），即每个专家在单次批处理中可容纳的 token 数量上限1 (§2.2, 式 3)：

expert_capacity = (tokens_per_batch / num_experts) * capacity_factor

其中：

  • tokens_per_batch / num_experts 代表理想均匀分配下每名专家分摊到的平均 token 槽位（此时容量因子 CF = 1.0）；
  • 容量因子（capacity factor，CF）大于 1.0 时为每名专家分配额外的冗余槽位，以容纳局部不均衡的峰值。

增大容量因子可以减少因分配不均导致的溢出，但过大的容量因子会引入更多空白填充，造成显存和计算浪费。

2.2 丢弃 token 与计算跳过

若分配给某位专家的 token 数超过其 expert_capacity，超出限额的 token 将成为丢弃 token（dropped tokens）1 (§2.2)。

这里的处理方式是跳过该层专家的前馈变换，该 token 的输入表征直接通过残差连接（residual connection）传递至下一层。残差直通保证了序列张量维度完整，但较高的丢弃率会削弱该层专家的实际计算效益。

3. 辅助负载均衡损失

单纯依靠主交叉熵损失（cross-entropy loss）可能导致网络退化为极端不平衡的分配模式。为此，Switch Transformer 在训练目标中引入了可微的辅助负载均衡损失（auxiliary load balancing loss）1 (§2.2, 式 4)。

对于包含 T 个 token 的批次与 N 个专家，设：

  • f_i 为在容量截断前由 Top-1 路由选定专家 i 的 token 比例（非可微）：
f_i = (1 / T) * sum_{x in Batch} 1{ argmax_j p_j(x) == i }
  • P_i 为路由器分配给专家 i 的门控概率在批次内的均值（可微）：
P_i = (1 / T) * sum_{x in Batch} p_i(x)

辅助损失定义为两向量的点积缩放：

loss_aux = alpha * N * sum_{i=1}^N (f_i * P_i)

当路由完全均匀时，f 与 P 的各分量均为 1/N，此时两向量点积和为 1/N。乘上专家总数 N 后，未乘 alpha 的均匀参考值为 1；完整辅助损失的均匀参考值为 alpha（在论文实验中为 0.01），不随专家数量缩放而变动。该辅助损失鼓励路由器朝着均匀分布优化，在提供有效均衡约束的同时未对主语言建模目标产生明显干扰。

4. 训练稳定化措施

稀疏架构中的离散硬路由切换可能增加训练的不稳定性，尤其在低精度格式下数值波动更容易被放大。Fedus et al. (2021) 验证了三项核心工程策略：

  1. 局部选择精度（Selective Precision）：在论文的 Switch-Base 实验中，全模型使用 16 位浮点（bfloat16）训练发生发散，而全使用 32 位浮点（float32）虽稳定但通信开销大1 (§2.4, Table 2)。作者采用局部选择精度策略：仅在设备局部的路由器函数内临时将输入转为 float32 计算门控打分，产出分配张量后立即转回 bfloat16。这一做法兼顾了数值稳定性与跨卡通信效率。
  2. 缩小参数初始化方差：标准 Transformer 权重通常从标准差为 sigma = sqrt(s / fan_in) 的截断正态分布中采样，默认尺度 s = 1.0。在 Switch Transformer 中，作者将初始化尺度缩小 10 倍（s = 0.1）1 (§2.4, Table 3)。实验表明该设置改善了早期模型质量并降低了不同随机种子之间的方差，作者报告其降低了训练失稳的可能性。
  3. 专家层特化丢弃法（Expert Dropout）：稀疏模型因总参数量大，在样本量受限的下游微调（fine-tuning）中容易过拟合。实验显示在全局统一提高丢弃法（dropout，训练时随机将部分激活置零）比例会导致下游任务成绩恶化1 (§2.4, Table 4)。作者在非专家层保持较低的丢弃率（0.1），仅在专家前馈网络的中间层使用较高的丢弃率（0.4），取得了更好的微调效果。

5. 实验证据与核心评测基准

为了检验 Switch 架构在相同算力条件下的有效性，论文以 T5 模型（Raffel et al., 2019）为基准展开了系统对比1 (§2.3)。

下表汇总了论文在 C4 数据集上的预训练收敛对比：

模型架构与配置100k 步负对数困惑度达到目标质量耗时
T5-Base (稠密基准)-1.731100k 步内未达标
MoE-Base (Top-2, CF=2.0)-1.54768.7 小时
Switch-Base (Top-1, CF=1.0)-1.56162.8 小时

该组实验的配置与条件如下：

  • 预训练在 C4 数据集上进行，以预测被遮盖的 token 片段为目标；
  • 所有模型在相同硬件环境（32 TPU 核心）下训练；
  • Switch-Base 与 T5-Base 具有相同的单 token 计算量（FLOP-matched），而 Top-2 MoE 每个 token 经过两个专家，计算量高于两者；
  • Switch-Base 与 MoE-Base 均配置 128 个专家，且在每隔一层的 FFN 处替换为专家层；
  • 目标质量阈值设定为负对数困惑度 -1.495（数值越大质量越优）；T5-Base 在测试的 100k 步内未能达到该阈值。

数据表明，在该实现与硬件条件下，Switch 在较低容量因子（CF=1.0）下运行良好。需要说明的是，测得的预训练速度优势取决于具体硬件与底层实现，不能直接推论为普遍的推理延迟收益1 (§2.3, Table 1)。

在下游微调任务中，稀疏模型的收益因任务性质而异1 (§4.1, Table 6)。在知识密集型任务（如闭卷 TriviaQA，精确匹配由 24.5% 升至 30.7%）和自然语言理解任务（如 SuperGLUE 均分由 75.1 升至 79.5）上，参数量更大的 Switch-Base 相比同算力的 T5-Base 表现出明显优势；而在 ARC Challenge 复杂推理任务上，该组 Switch-Base（32.8%）稍逊于 T5-Base（35.5%）。这些结果表明不同任务对参数量扩充的敏感度不同，不能据此简单归纳稀疏架构对推理任务的整体能力。

此外，针对海量参数部署困难的问题，论文验证了知识蒸馏（knowledge distillation）的可行性：以 3.8B Switch-Base 教师网络的非专家层权重初始化 223M 稠密学生，并结合软硬混合标签损失，参数量减少约 94%，在该 C4 实验中保留了教师相对 T5-Base 的负对数困惑度增益约 30%1 (§4.2, Table 7)。

6. 机制边界与权衡

稀疏专家模型在解耦参数规模与单步计算量方面展现了明显优势，但在工程实践中仍受制于以下边界：

6.1 专家权重的存储开销

虽然单 token 激活的计算量保持受控，但各专家的权重仍需占用存储和显存，具体开销取决于模型规模、存储精度与并行切分策略。论文报告的预训练提速是在特定硬件集群与实现下的结果，不保证在任意硬件配置上均能获得同等增益。

6.2 数据分布变化与路由负载

容量因子与丢弃机制在吞吐效率与 token 表达完整性之间存在固有权衡。若输入数据分布发生变化导致路由分配向局部专家过度倾斜，可能造成溢出丢弃率上升或部分计算单元闲置。

6.3 大规模训练的稳定性

虽然 Switch-Base 与包含 2048 个专家、1.6 万亿参数的 Switch-C 在实验中表现平稳，但在单 token 计算量更大的 Switch-XXL 变体中，作者依然观察到了间歇性的训练发散现象1 (§5.6, §8)。极大规模稀疏路由下的梯度动态与数值稳定性在当时仍属于未完全解决的前沿课题。
