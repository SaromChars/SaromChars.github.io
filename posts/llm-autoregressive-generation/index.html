大语言模型到底在预测什么？自回归生成与下一个 Token 概率

2022年3月11日
|

在前两篇讨论中，我们梳理了 Transformer 的自注意力（self-attention）机制以及分词器（tokenizer，按模型规则切分文本的组件）如何将原始字符串切分为离散 token（模型处理的序列单位，常称词元）、经嵌入（embedding）查表并演化为多层上下文表示（contextual representation）的过程。

但到目前为止，模型计算出的核心产物仍然是连续的高维隐层向量：输入长度为 n 的 token 序列，顶层输出对应的 n 个隐藏状态向量 [h_1, h_2, ..., h_n]，其中每个向量的维度为 d_model。

计算机与终端读者需要的不是高维浮点数，而是可读的自然语言文本。这就引出了大语言模型（large language model，LLM）在推理（inference）阶段的核心问题：

  1. 连续的隐藏状态向量如何重新映射回离散的词表符号？
  2. 模型如何利用这一映射结果逐步生成连贯的 token 序列？
  3. 为什么模型在训练（training）时可以全句并行，而在生成文本时必须一步一步地串行循环？
  4. 当模型计算出下一个 token 的概率分布后，我们究竟该以何种策略从中挑选 token？贪心搜索、随机采样、Top-k 与核采样（Top-p）各自解决了什么问题，又存在哪些局限？

本文将围绕纯解码器（Decoder-only）架构的自回归语言模型，顺着数据流向拆解从概率预测到文本生成的完整机制。

1. 从隐藏状态到词表概率：LM Head 与 Softmax

在纯解码器架构（例如 GPT 系列）中，当输入序列为 [x_1, x_2, ..., x_n] 时，因果掩码机制保证了第 i 个位置的隐藏状态 h_i ∈ R^(d_model) 仅聚合了自身及之前所有历史 token 的信息。

为了预测接在第 n 个 token 之后的下一个 token，模型需要利用最后一个位置的顶层隐藏状态 h_n。

1.1 线性投影（LM Head）与未归一化分数（Logits）

将隐藏维度 d_model 重新映射到全词表空间 |V| 的组件，通常被称为语言模型头（Language Model Head，简称 LM Head）。它本质上是一个无激活函数的线性变换层：

z = h_n * W_vocab + b_vocab

其中：

  • h_n ∈ R^(1 × d_model) 是最后一个位置的输出向量；
  • W_vocab ∈ R^(d_model × |V|) 是可学习的词表投影矩阵；
  • b_vocab ∈ R^(1 × |V|) 是可选的偏置项（部分模型省略）；
  • z ∈ R^(1 × |V|) 是各词项对应的未归一化分数（logits）。

词表中的每一个离散 token（从索引 0 到 |V|-1），都在向量 z 中分配到一个实数值标量。这个数值代表模型给该候选 token 打出的原始未归一化分数。

参数绑定（Weight Tying）说明： 在 Vaswani 等人（2017）1 (Vaswani et al., §3.4) 的原版 Transformer 架构中，输出投影矩阵 W_vocab 与输入端的嵌入矩阵 E ∈ R^(|V| × d_model) 共享权重，即令 W_vocab = E^T。此时，预测下一个 token 的过程在代数上等价于计算当前隐藏状态 h_n 与词表中各静态词向量的点积得分。

1.2 Softmax 归一化与概率分布

由于未归一化分数向量 z 中的元素是任意实数，既可能为负数，加和也不为 1，无法直接作为概率使用。通过 Softmax 函数，我们可以将其归一化为标准的离散概率分布：

P(x_(n+1) = w_i | x_<=n) = exp(z_i) / sum_(j=1)^(|V|) exp(z_j)

由此，模型在当前步输出了一个覆盖全词表 |V| 的概率向量 p ∈ R^(|V|)，满足：

  1. 对任意词项 w_i，都有 0 < P(w_i) < 1；
  2. 全词表概率和为 1，即 sum_(i=1)^(|V|) P(w_i) = 1。

这正是语言模型的核心定义：根据上文历史 x_(1:n)，估计下一个 token 在词表空间上的条件概率分布 P(x_(n+1) | x_(1:n))。

2. 自回归生成循环：因果掩码与串行依赖

得到了下一个 token 的条件概率分布后，如果通过某种策略选出了一个具体的候选 token（记作 x^_(n+1)），一段完整的自然语言文本是如何被持续构造出来的？

这就是自回归（Autoregressive）文本生成。用户输入的起始文本称为提示词（prompt），模型接收提示词后启动逐步生成循环：

提示词输入: [x_1, x_2, ..., x_n]
        │
        ▼
┌───────────────────────────────────────────────┐
│ Transformer 前向传播 (含因果掩码 Causal Mask) │
└───────────────────────┬───────────────────────┘
                        ▼
           取末位隐藏状态 h_n -> LM Head -> Softmax
                        ▼
              词表概率分布 P(x_(n+1) | x_<=n)
                        ▼
                解码策略选取 token: x_(n+1)
                        │
       ┌────────────────┴───────────────┐
       ▼                                ▼
命中停止条件 (EOS / 达到最大长度)      未触发停止条件
       │                                │
       ▼                                ▼
    生成结束                    拼入序列: [x_1, ..., x_n, x_(n+1)]
                                        │
                                        └────── 重新循环

2.1 生成循环的逐步推演

整个生成过程以循环迭代的方式展开：

  1. 第一步：输入提示词序列 [x_1, ..., x_n]，模型执行一次前向计算，根据位置 n 的隐藏状态得到概率分布，解码器选定新 token x_(n+1)。
  2. 第二步：将 x_(n+1) 拼接到输入序列末尾，构成新的上下文 [x_1, ..., x_n, x_(n+1)]。
  3. 第三步：以长度为 n+1 的新序列再次执行模型前向计算，根据位置 n+1 的隐藏状态得到下一概率分布，选定新 token x_(n+2)。
  4. 循环往复：序列长度不断递增，直到满足终止条件为止。

联合概率公式反映了这种链式条件分解结构：

P(x_1, x_2, ..., x_N) = prod_(i=1)^N P(x_i | x_1, ..., x_(i-1))

2.2 为什么训练可以同层并行，而推理必须严格串行？

训练阶段：因果掩码（Causal Mask）与目标移位

在预训练（pretraining）阶段，模型针对已有的完整目标序列进行训练。为了让每个位置预测其紧邻的下一个 token，标准做法是将输入序列与目标序列错开一个位置（Shift Right）： 例如输入序列设为 [BOS, x_1, x_2, x_3]，对应的监督目标序列为 [x_1, x_2, x_3, x_4]（其中 BOS 为序列起始标记）。 此时，模型并不需要等待第一步算出 x_1 再去输入 x_1 算 x_2。整条长度为 4 的输入序列被一次性送入 Transformer。 为了防止前向计算时“提前看到”右侧未来的目标 token，注意力矩阵中引入了下三角因果掩码（Causal Mask）：对所有 j > i 的注意力打分注入 -inf，使得 Softmax 之后未来位置的权重严格为 0 1 (Vaswani et al., §3.2.3)。 因而在同一次前向传播中，模型在同一层的序列各位置上可以并行计算出对应的隐藏状态，并同时计算 4 个位置分别预测 x_1, x_2, x_3, x_4 的交叉熵损失（Cross-Entropy Loss）。需要指出的是，这种并行性限定在同一前向传播内的序列位置维度，网络深层之间的逐层传递以及优化器的反向传播梯度更新依然存在前后串行依赖。

推理阶段：严格的时间依赖

在实际生成文本时，第 n+1 个 token 尚未产生。模型必须先完成前 n 个 token 的全部多层矩阵乘法与注意力交互，拿到最后的 Softmax 分布并完成采样决定，才能获知下一个输入的准确离散 ID。 由于第 n+1 步计算的输入物理上依赖于第 n 步的输出结果，这一数据依赖链路无法跨越时间被并行消除。若要生成一个包含 100 个 token 的回答，模型底层就必须连续执行 100 次前向计算迭代。

3. 停止条件：生成过程何时结束？

在实际系统中，生成循环通常在遇到以下两种情况时退出：

  1. 生成特殊终止标记（End of Sequence，EOS）： 在分词器词表中，定义了专门的序列结束标记（例如 GPT 中的 <|endoftext|>）。如果在某一步采样中，该特殊标记被选中为最高概率或被采样命中，解码循环即判定模型已表达完毕，主动停止后续迭代并输出结果。
  2. 达到最大序列长度（Max Length）或上下文窗口上限： 如果模型持续不生成 EOS 标记，为了避免死循环或显存耗尽，系统设置有硬性截断长度（例如单次请求最多生成 512 个新 token，或者总长度达到 GPT-3 规定的 2048 个 token 上限 2 (Brown et al., §2)）。一旦触达阈值，生成过程被强制终止。

4. 解码策略：有了概率，怎样选出下一个 Token？

当模型在某一步给出了全词表 |V| 的概率分布向量后，下一步就是解码（Decoding）：如何根据这些数值选出具体的 token？

初学者往往直觉认为：只要每次都挑概率最高的那个词，生成的内容就一定最合理。然而在开放式长文本生成中，单纯最大化概率可能导致重复等文本退化现象（Holtzman et al., 2019）3。

4.1 贪心搜索（Greedy Search）及其退化问题

贪心搜索策略在每个时间步只挑选条件概率最高的那单一词项：

x^_t = argmax_(w ∈ V) P(w | x_(<t))
  • 计算优势：无需额外参数，计算极快，仅需一次 argmax 操作。
  • 神经文本退化（Neural Text Degeneration）： Holtzman 等人在《The Curious Case of Neural Text Degeneration》3 (§3.1, §6.3) 中通过实验指出：在开放式长文本生成中，贪心搜索容易陷入高频词死循环、重复短语以及内容停滞。
  • 原因剖析：人类自然语言的实际分布并不是由每步最高概率词串接而成的。高概率词往往对应语法功能词或高频通用词；单纯追求每步概率最大，会降低文本的多样性，并将生成过程诱导至重复循环状态。

4.2 集束搜索（Beam Search）在开放生成中的局限

集束搜索在每个时间步维护一个大小为 B（Beam Width）的候选路径集合，保留整体累积对数概率最高的 B 条序列。

集束搜索也用于机器翻译、文本摘要等受源文本约束的任务，这类任务的输出受到源文本强烈约束，存在相对明确的参考标准。

但在开放式自由生成（如故事续写、对话生成）中，Holtzman 等人（2019）3 (§3.1) 观察到：集束搜索并不能消除退化问题，反而容易出现重复与呆板的生成现象。累积概率最高的高分路径，常被大量高频重复词构成的序列所占据。

4.3 纯随机采样与不可靠长尾（Unreliable Tail）

按照模型预测的分布直接进行多项式抽样：

x^_t ~ P(w | x_(<t))

纯随机采样让非首位 token 也有被选中的机会，但不保证避免重复。然而，它面临着另一个问题——长尾噪声（Unreliable Tail） 3 (§4)： 自然语言词表通常包含数万个 token。在特定语境下，单个长尾候选的概率可能极低（例如处于 10^(-5) 数量级），但低概率长尾候选的累积概率质量仍可能不可忽视，其中不合语境的候选会增加生成失连贯的风险。 在自回归的多步采样中，一旦从长尾中抽出了与语境不符的异常 token，该词便会拼入后续前缀，增加后续生成逻辑断裂的风险。

4.4 温度采样（Temperature Sampling）

为了在确定性与随机性之间进行调控，温度调节（Temperature）被引入未归一化分数计算：

P(w_i) = exp(z_i / T) / sum_(j=1)^(|V|) exp(z_j / T)

其中参数 T > 0 为采样温度：

  • 当 T = 1.0 时：保持原始模型的未调整概率分布；
  • 当 T -> 0 时：未归一化分数之间的差距被成倍拉大，概率迅速向最大值聚集，采样行为逼近贪心搜索；
  • 当 T > 1.0 时：未归一化分数之间的相对差距被缩小，概率分布趋向平缓均匀，输出的多样性增加，但出现不合逻辑词汇的概率也随之上升。

局限性：温度 T 是一个预先设定的全局超参数。但在实际生成过程中，模型的置信度随上下文动态变化：有的语境下后继词高度确定，分布应当陡峭；有的语境下有多种通顺候选，分布天然平缓。固定温度无法自适应上下文的动态熵变。

4.5 Top-k 采样及其截断缺陷

为了抑制长尾噪声，Fan 等人（2018）提出了 Top-k 采样：每一步仅保留概率最高的 k 个候选 token，将其余候选概率置零并在保留集合内重新归一化。

  • 特点：截断了长尾中的低分词，有助于降低胡言乱语的风险。
  • 固定窗口的局限（Rigid Cutoff） 3 (§5.2)： 固定数值 k 无法灵活适配动态变化的候选空间：
    • 在平缓语境下（Flat Distribution）：可能有数十个 token 均符合文意，但固定 k 会截断后续潜在的合规表达；
    • 在陡峭语境下（Peaked Distribution）：可能仅有 1 到 2 个 token 合乎逻辑，但固定 k 依然保留了多余的尾部词，使不恰当候选仍有被抽中的可能。

4.6 核采样（Nucleus / Top-p Sampling）：按累积概率动态截断

为了改善 Top-k 固定截断大小的局限，Holtzman 等人（2019）提出了核采样（Nucleus Sampling，又称 Top-p 采样） 3 (§6)。

核采样的核心思路是：不再固定候选 token 的数量 k，而是设定候选集合累积概率质量的阈值 p（例如设定 p ∈ [0.9, 0.95]）。

具体算法流程如下：

  1. 将词表中所有 token 按预测概率从大到小降序排列：P(w_((1))) >= P(w_((2))) >= ... >= P(w_((|V|)))；
  2. 选取满足累积概率达到阈值 p 的最小候选子集 V^(p)： 
    V^(p) = { w_((1)), w_((2)), ..., w_((k')) }
其中 k' 是满足 sum_(i=1)^(k') P(w_((i))) >= p 的最小整数
  3. 将集合 V^(p) 之外的候选 token 概率置为 0，仅对核集合 V^(p) 内的候选词重新归一化： 
    P'(w) = P(w) / sum_(w' ∈ V^(p)) P(w'),  若 w ∈ V^(p)
        0,                               否则
  4. 从重新归一化后的新分布 P'(w) 中随机抽取下一个 token。

动态弹性的调节效果：

  • 当设定累积概率阈值 p = 0.95 且模型分布较为集中时（例如第 1 个候选词概率不足 0.95，但前 2 个候选词的累积概率达到或超过 0.95），核集合 V^(p) 会动态缩小为 2 个 token，从而降低长尾噪声被抽中的风险；
  • 当语境较为发散、候选分布相对平缓时，核集合 V^(p) 会随分布自适应扩充容纳更多候选 token，避免过早截断潜在的合理表述。

5. 极简数值教学示意：解码策略演算流程

教学示意：本节数据属于人工构造的教学演算用例，非真实大模型的真实参数或实测输出。数据在本文内部保持数学自洽与可复算性。

假设词表大小极小，仅包含 |V| = 5 个词项。模型当前步经 LM Head 算出的未归一化分数为：

z = [2.0, 1.0, 0.0, -1.0, -2.0]

第一步：计算基础 Softmax 概率分布

计算各分量指数 exp(z_i)：

  • exp(1.0) ≈ 2.7183
  • exp(0.0) = 1.0000
  • exp(-1.0) ≈ 0.3679
  • exp(-2.0) ≈ 0.1353

未舍入指数分母求和：

sum_(j=1)^5 exp(z_j) ≈ 7.389056 + 2.718282 + 1.000000 + 0.367879 + 0.135335 ≈ 11.6106

计算各词项基础概率 P(w_i) = exp(z_i) / sum exp(z_j) 并记录累积概率（四位小数显示）。两表按相同词表行顺序分别展示未归一化分数与计算所得概率：

第二步：不同解码策略下的处理与重归一化

1. 贪心搜索（Greedy Search）

直接取概率最大项：

w^ = argmax P(w) = "模型"  (P = 0.6364)

输出结果严格确定为 "模型"。

2. Top-k 采样（设 k = 2）

只保留概率最高的 2 个 token："模型" 与 "系统"。其余清零。 按未舍入值计算，两项概率之和约为 0.8705。 重新归一化后的新分布：

  • P'("模型") = 0.636409 / 0.870530 ≈ 0.7311
  • P'("系统") = 0.234122 / 0.870530 ≈ 0.2689 从上述二元分布中随机抽取。

3. 核采样 Top-p（设阈值 p = 0.90）

按降序检查累积概率：

  • 第 1 项 "模型"：累积 0.6364 < 0.90；
  • 第 2 项 "系统"：累积 0.8705 < 0.90；
  • 第 3 项 "网络"：累积 0.9567 >= 0.90。

累积质量在此处跨过 0.90 阈值，核集合锁定为前 3 个 token：{"模型", "系统", "网络"}。后 2 项被排除。 按未舍入值计算，前三项概率之和约为 0.9567。 重新归一化后的新分布：

  • P'("模型") = 0.636409 / 0.956659 ≈ 0.6652
  • P'("系统") = 0.234122 / 0.956659 ≈ 0.2447
  • P'("网络") = 0.086129 / 0.956659 ≈ 0.0900

采样将从这 3 个词项中展开。需要指出的是，第三个候选 token "网络" 在此被保留下来，完全是因为累积概率需达到预设阈值 p = 0.90 的数学规则，这并不代表该候选词在真实任务语义上必然合理。

6. 机制边界辨析：生成策略解决与未解决的问题

在了解了下一个 token 概率生成的运作过程后，需明确以下几个关键的工程与机制边界：

1. 生成循环以既有前缀逐步推进，通常不回写已输出内容

自回归文本生成循环的核心特点是：在每一步计算中，模型根据当前已经累积的前缀序列预测下一个 token 的条件概率分布；一旦某个 token 被采样选定并拼入上下文，后续步骤就会以包含该 token 的扩展前缀继续前向计算，通常不再回头修改或重新采样已生成的上文。

2. 局部采样偏差对后续生成的连贯性影响

在自回归推理过程中，生成序列的连贯性高度依赖前面的各个 token。Holtzman 等人（2019）3 (§4) 指出，如果采样策略在某一步不幸抽中了低概率的离奇词或质量不佳的候选项，该词汇就会作为既成事实进入后续上下文，进而破坏后续文本的连贯性，甚至引发更严重的生成退化。

3. 解码策略不更新模型参数，亦不保证事实正确

温度调节（Temperature）、Top-k 和 Top-p 仅在推理阶段对已计算出的分数与概率分布进行截断和重塑，并不涉及模型权重参数的更新。

  • 改变采样参数可以调节输出文本的多样性与风格，但并不保证输出事实的准确性；
  • 当错误候选项在未归一化分数中处于高位时，它仍然具有被选中的较高概率；反之，若截断阈值设置过小，正确的候选 token 也可能被意外排除在外。解码算法本身无法替代模型参数本身的训练质量。

总结

大语言模型生成文本的过程，是一组紧密衔接的数学与工程链条：

  1. 向量映射：顶层最后一个 token 的隐藏状态 h_n 经由可学习的线性 LM Head 矩阵映射为词表大小的未归一化分数（logits），再经 Softmax 归一化为标准的离散条件概率分布；
  2. 自回归循环：在解码阶段，每次迭代仅生成一个 token，拼入序列后再驱动下一次前向计算；这种串行依赖构成了推理的核心延迟瓶颈，与训练阶段利用因果掩码实现的全序列同层并行截然不同；
  3. 退化与采样权衡：单纯的确定性最大概率搜索（贪心与集束搜索）在开放生成中易导致高频死循环与文本退化；直接按原分布采样则可能抽中长尾中的不合语境候选；
  4. 动态核截断：核采样（Top-p）通过动态累积概率质量阈值构建动态截断窗口，提供了一种按累积概率自适应平衡候选范围的解码方法。

理解了自回归模型如何一步步预测出下一个 token，紧接着的核心问题便是：这个多层神经网络内部的权重参数最初是如何被训练出来的？预训练的损失函数如何定义、优化算法如何驱动参数学习？这将在本系列的下一篇中展开探讨。
