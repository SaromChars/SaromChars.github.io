提示与少样本示例对输出的影响：上下文学习与参数更新的区别

2022年3月21日
|

在传统的深度学习与自然语言处理管线中，让模型“掌握一项新任务”通常对应于明确的参数优化过程：采集该任务的标注数据集，定义目标损失函数，通过反向传播（backpropagation）计算梯度（gradient），并在优化器的驱动下对神经网络内部的权重矩阵进行物理修改。无论是全量预训练（pretraining）还是下游微调（fine-tuning），参数更新始终是模型获取特定任务行为特征的主流手段。

然而，以 GPT-3 为代表的大语言模型（large language model，LLM）展现了一种截然不同的评测行为：

  • 在测试推理（inference）时，模型权重保持完全固定，不进行梯度计算与参数更新（在当前推理中增量参数变化 Δθ = 0）；
  • 无需为新任务训练专用权重切片，仅在提示（prompt）中提供任务说明，或者附带若干输入输出示范；
  • 模型在前向传播（forward pass）过程中展现出对提示上下文的高度敏感性，在许多下游任务中能够顺应示范给出的输入输出范式，在英法翻译、简单加法、语法修饰以及生造词造句等任务上产生与上下文相关的生成结果。

这种在推理时固定模型权重、仅凭输入上下文中的提示与示范便改变输出分布的行为，被称为上下文学习（In-Context Learning，ICL）。

模型权重保持固定，提示中的少量示例仍可改变前向计算的隐藏状态及输出的条件概率分布。这种能力究竟是模型在推理时现场习得了新机制，还是识别并唤醒了预训练阶段内化的语言模式？本文以 OpenAI 在 GPT-3 论文（Brown et al., 2020）1 中披露的分析框架与实验数据为基准，系统探讨上下文学习的作用形式、规模关联与技术边界。

1. 范式谱系：从微调到少样本、单样本与零样本

Brown et al. (2020) 在论文第 2 节比较了微调、少样本、单样本和零样本四种下游任务设定：

传统微调范式：参数更新 (Weight Updates)
┌────────────────────────────────────────────────────────┐
│                   微调 (Fine-Tuning)                    │
│  - 依赖数千至数十万条特定任务标注数据                      │
│  - 计算反向传播梯度，直接修改预训练模型权重                  │
│  - 优势：特定基准指标通常较强                             │
│  - 代价：任务间权重隔离、长尾样本获取昂贵、容易过拟合窄分布 │
└────────────────────────────────────────────────────────┘

上下文学习评测设定：参数固定 (Weights Frozen, Forward-Pass Only, Δθ = 0)
┌────────────────────────────────────────────────────────┐
│                   少样本 (Few-Shot)                     │
│  - 在上下文窗口中提供 K 个示范 (通常 10 <= K <= 100)      │
│  - 仅执行前向计算，不计算梯度，不更新权重                  │
├────────────────────────────────────────────────────────┤
│                   单样本 (One-Shot)                     │
│  - 仅提供 1 个示范并辅以自然语言任务说明                  │
│  - 贴近人类日常沟通与工作指引（如示例说明）                │
├────────────────────────────────────────────────────────┤
│                   零样本 (Zero-Shot)                    │
│  - 不提供示范，仅提供自然语言任务描述                      │
│  - 使用最便捷，但易受任务格式与说明文字歧义影响            │
└────────────────────────────────────────────────────────┘

1.1 微调（Fine-Tuning）的优势与代价

在微调设定下，模型权重通过反向传播针对特定任务目标进行调整。虽然针对特定评测集能带来优异表现，但这一范式伴随着不可忽视的局限：

  1. 数据收集成本高昂：针对每一个现实长尾任务构建包含成千上万样本的高质量标注集往往不具可行性；
  2. 分布外泛化受限：高容量模型在狭窄任务分布上微调时，容易拟合训练数据中的虚假相关性（spurious correlations），在真实跨域场景中表现可能下滑 1 (§1, §2)；
  3. 部署维护复杂度：为每个下游任务维护一套独立的权重文件，在工程上极具管理负担。

需要指出的是，虽然上下文学习评测中保持模型权重完全冻结，但这属于评测与推理设定，并不意味着模型架构本身在物理上永久排斥微调——正如论文所指出的，超大模型与微调的结合依然是未来极具潜力的方向。

1.2 上下文学习的三种无梯度设定

在上下文学习设定下，模型参数在推理时保持恒定（Δθ = 0），任务形式主要由输入文本引导：

  • 少样本（Few-Shot）：模型在其上下文窗口（context window，GPT-3 架构统一为 2048 个 token；token 是模型处理的离散序列单位，亦称词元）内，接收若干个（通常在 10 到 100 个之间）由“输入上下文 + 期望补全”构成的示范，紧接着输入测试用例。少样本示范降低了针对狭窄微调集直接更新参数带来的过拟合风险，但输出依然受到预训练语料分布与具体示例选择的制约，示范并不能提供绝对的正确性或格式保证。
  • 单样本（One-Shot）：仅允许提供 1 个示范并附带任务说明。这种形式高度契合人类在众包标注或日常协作中接收指令的直觉模式。
  • 零样本（Zero-Shot）：完全不给示范，仅提供自然语言指令。这种设定对输入表述与任务格式的完备性要求极高，容易因人类提示词措辞歧义而面临评测上的困难。

2. 内部机理：自注意力与动态激活态的条件响应

权重固定时，示范文本可经由因果自注意力（Causal Self-Attention）影响后续位置的隐藏状态和输出分布。

2.1 从静态参数到动态激活态

自回归语言模型生成下一个 token 的本质是在固定参数 θ 下计算条件概率分布：

P(y | x_test, D_demo) = P_θ(y | [x_1, y_1, x_2, y_2, ..., x_K, y_K, x_test])

其中 D_demo = {(x_1, y_1), ..., (x_K, y_K)} 为输入提示中拼接的 K 组示范。

从前向传播的信息流动来看：

  1. 离散序列嵌入：输入的示范文本与待求解问题被分词器（tokenizer）按特定规则切分为离散的 token 序列（可基于子词、字符或字节等单位表示，并不等同于自然语言中的完整词），每个 token 映射为高维稠密嵌入（embedding）；
  2. 因果自注意力聚合：在多头自注意力（multi-head self-attention）层中，每个 token 映射为查询（Query，Q）、键（Key，K）和值（Value，V）向量。因果注意力掩码确保靠后的 token 只能单向感知其前方所有位置；
  3. 示范对后续隐藏态的调制：当网络计算到待测输入 x_test 及其生成位置时，该处的 Q 向量不仅与自身输入 token 计算注意力点积，还会直接与前方所有示范 token 产生的 K 向量进行加权交互，将对应的 V 向量信息流聚合至当前层及后续多层残差连接中。

为便于理解，这里可把上下文影响隐藏状态比喻成临时工作空间；这不是 Brown 已证实的机制。固定参数时，不同输入可以改变隐藏状态及输出条件分布，变化幅度与任务和提示有关。示范中的输入输出对为模型提供了前向计算的局部条件线索，使生成分布向贴合示范格式与任务要求的方向倾斜。

2.2 评估模式下的候选似然归一化

对于多项选择（Multiple Choice）与分类任务，上下文学习的评测既可以通过自由生成完成，也可以通过对比不同候选补全在语言模型下的条件似然概率来实现 1 (§2.4)。

在 GPT-3 的评测实现中，研究人员在提示末尾依次拼接各个候选选项，计算模型在每个选项上的对数似然。为了减轻候选词因长度差异产生的先验偏差，通常计算逐 token 的平均似然；而在 ARC、OpenBookQA 和 RACE 等任务上，论文进一步采用了无条件概率除法归一化：

Score(completion | context) = P(completion | context) / P(completion | answer_context)

其中 answer_context 是通用的问答前缀短语（例如 "Answer: " 或 "A: "）。需要强调的是，这一公式属于评测层面的启发式评分校正手段，旨在抵消某些通用词汇在无条件分布中的天然高频偏置，而非证明模型内部具备专门提取证据的认知单元。

3. 元学习假说：先验模式识别与现场适应的未决光谱

Brown et al. (2020) 在引言中引入了元学习（Meta-Learning）的双循环类比，探讨下一个 token 预测训练与推理时利用提示之间的关系。

3.1 外循环预训练与内循环上下文

论文将自回归预训练与推理交互类比为双层循环：

  • 外循环（Outer Loop）：在海量异构文本语料上进行无监督预训练。语料本身包含了大量天然具备结构化模式的段落（如英法双语对照词条、带答案的习题、格式统一的问答交流等）。为了最小化交叉熵损失，参数优化迫使模型发展出广泛的模式识别倾向；
  • 内循环（Inner Loop）：在推理阶段的单一序列上下文内发生。模型参数冻结，依靠输入序列中的提示与示范，在前向隐藏激活态中快速聚焦于特定子任务的生成轨迹。

3.2 现场从头学习还是先验模式识别？

模型在面对少样本示范时，究竟是在推理时“现场从头学习新任务”（learn de novo），还是仅仅在“识别并激活预训练中已经内化的模式”（task recognition）？

Brown et al. (2020) 在论文第 5 节明确指出：这一问题在理论上仍存在未解的模糊性（ambiguity），无法简单给出一锤定音的定论。实际上，不同任务在这一光谱上表现各异：

  1. 先验识别主导的任务：对于常见的机器翻译或事实问答，模型显然不可能仅凭上下文中的几个示例从头构建一门语言的语法体系或世界知识库。此时示范主要起到格式收拢与任务识别的作用，促使模型调用预训练阶段沉淀的表征能力；
  2. 依赖局部规则的质性合成任务：
    • 生造词运用（Novel Words）：在论文第 3.9.5 节与 Table 3.16 中，研究人员给模型提供虚构词汇的定义（如生造名词 Gigamuru、生造动词 farduddle、screeg 等）。任务先提供 1 至 5 个其他词汇定义的示范（广义任务维度为 few-shot），但针对当前目标词仅提供一次定义说明（特定词汇维度为 one-shot）。表 3.16 展示六例，其中首例用句由人编写作为条件，后续用句由 GPT-3 生成；作者认为这些输出正确或至少看似合理，其中 screeghed 用法略显生硬。需要注意，这些案例属于小样本定性展示，不能视作通用语法严谨性的绝对保证；
    • 符号与字符乱序任务（Word Scrambling）：在第 3.9.2 节的字符操作实验中，不同子任务表现出现剧烈分化。在随机插入多余字符的清理任务（Symbol Insertion）中，增加少样本示范确实显著改善了指标；但在单词倒序还原任务（Reversed Words）中，GPT-3 175B 的少样本准确率仅有 0.44%。该结果表明，在论文的倒序还原设定下，增加示例仍未使模型可靠完成任务；它不证明模型具备通用符号操作能力。

4. 规模趋势与评测实证

上下文利用能力并非所有尺寸语言模型的天然均质特性，而是与参数容量规模呈现出强烈的正向关联。

4.1 模型容量对上下文利用效率的影响

Brown et al. (2020) 构建了从 1.25 亿（125M）至 1750 亿（175B）共 8 种参数尺度的模型序列（Table 2.1）。在跨越数十项任务的评估中，呈现出以下客观特征：

  1. 大容量模型通常更能有效利用示范信息：图 1.3 中，较大模型的 few-shot 相对 zero-shot 增益通常更大。图 1.2 的字符清理任务显示，较大模型能更有效利用增加的上下文示例；较小模型（如 125M、350M）即使在上下文填入大量示范，指标提升依然较为有限；
  2. K 值的非单调性：论文在第 2.4 节指出，在上下文窗口允许范围内，增大示范数量 K 通常能带来改善，但并非在所有任务上都单调递增。最佳的 K 值往往需要根据具体任务在验证集上进行超参数搜索确定；
  3. 性能差距的分化：在参数规模较小时，Zero-Shot、One-Shot 与 Few-Shot 之间的表现差距往往相对较窄；而在超大模型上，Few-Shot 相比 Zero-Shot 经常拉开显著的性能增益。

4.2 典型基准数据设定与局限

在 GPT-3 评估的部分任务中，少样本上下文学习展现了逼近甚至匹配部分有监督微调系统的水平：

  • 闭卷问答（Closed Book QA）：在无外部知识检索支持的 TriviaQA 评测中，GPT-3 175B 在 Wikipedia split 的官方测试服务器（test server）上取得了 71.2% 的少样本准确率，达到了当时同类闭卷（closed-book）设定下微调系统的水准（需注意此表现限定于相同闭卷条件，且论文仅少数数据集提交了测试服务器，多数基准基于开发集评估）1 (§3.2)；
  • 阅读理解：在 CoQA 开发集上，GPT-3 175B 的少样本评估达到 85.0 F1（Zero-Shot 81.5，One-Shot 84.0）1 (§3.6)；
  • 基础算术：在三位数加减法（3-digit addition / subtraction）的少样本评测中，175B 模型准确率可达 80% 以上，而较小规模的模型在该项上的表现明显疲软 1 (§3.9.1 Table 3.9)。

4.3 数据污染（Data Contamination）分析的现实审视

针对超大无监督语料可能包含评测集文本的顾虑，论文第 4 节与 Appendix C 开展了针对各任务选定长度的 N-gram 重叠过滤分析，并构建了移除潜在重叠样本的“干净子集”（Clean Subset）。

客观审视其排查结果，必须指出：

  1. 重叠分析不能彻底排除死记硬背：虽然对 QuAC、SQuAD2 和 DROP 等阅读理解任务的抽样人工检查表明，重叠内容多为维基背景材料而问答对并未直接泄漏，但作者坦言，基于启发式 N-gram 的清洗无法完全保证排除所有污染影响；
  2. 干净子集存在统计偏差：在清洗后的子集上，部分基准表现出现显著波动（例如 Table C.1 中，DROP 在干净子集上相对于全量集下降约 21%，QuAC 相对上升约 20%，RACE-m 上升约 3%）。干净子集本身样本分布难保与原测试集完全一致，因此这一评估无法绝对排除记忆效应被统计偏差掩盖的可能性；
  3. 部分基准受重叠影响显著：由于数据过滤瑕疵，Wikipedia 语言建模任务与儿童图书测试（Children’s Book Test）因几乎完全包含于训练集中而被直接剔除、不予报告；PIQA 和 Winograd 任务因存在可测量的性能回退，在论文主表中被专门标注星号（*）以示潜在污染。

5. 机制边界与固有局限

尽管上下文学习提供了一种敏捷的交互机制，但将少样本提示等同于全能机制是严重的认知偏差。在当前模型架构下，它面临明确的技术边界：

5.1 单向因果自回归架构的结构约束

GPT-3 采用仅包含解码器（decoder）的自回归因果语言模型结构。在第 5 节中，作者指出单向掩码机制可能是一种潜在解释（could be a possible explanation），用于理解为何模型在某些双向对比任务中表现低迷：

  • 在自然语言推理（ANLI）以及词义上下文比对（WiC）任务上，GPT-3 的少样本表现接近随机猜测；
  • 在需要精细多步推理的长篇阅读理解上，单向逐 token 预测相比具备双向编码机制的模型依然存在明显差距。必须注意，这是论文提出的合理假说，而非经过严密受控消融实验最终确认的唯一起因。

5.2 提示词设定的敏感性

任务说明、示例选择、数量和排列形式都是提示与评测设定的一部分。Brown 在评测中固定这些条件，并针对部分任务在开发集选择 K；因此比较结果时，应记录所用提示和示例条件，不能仅比较模型名称。

5.3 上下文窗口容量与推理计算开销

  • 总长度硬约束：GPT-3 的 2048 个 token 上下文窗口必须同时容纳示范样本、任务描述、测试输入以及待生成的全部补全。材料能够放入窗口，只说明模型可以接收它，并不保证所有示例或相关信息都被有效利用。对于长篇文档或多步长文本任务，示范能够占用的容量受到严格限制；
  • 推理计算负担：输入数十个示范会导致前向传播必须承载更长的序列计算。GPT-3 架构中虽交替采用了密集注意力（dense attention）与局部带状稀疏注意力（locally banded sparse attention）以平衡效率，但长上下文带来的推理算力与显存消耗依然显著高于短提示。

5.4 状态非持久化特征

提示与示范的信息作用完全依附于当前的推理输入。一旦在新的请求中去除了这些提示词，前置示范便不再参与前向计算，模型本身不会因曾处理过这些示例而在权重中持久沉淀出该任务的规则。

总结

提示与少样本之所以能够改变大语言模型的输出，其表现为：模型参数保持固定，输入上下文仍可改变前向计算中的隐藏状态及后续输出的条件概率分布：

  1. 范式边界明确：微调通过反向传播修改权重，针对性强但受限于标注成本与泛化迁移；上下文学习评测在推理中保持参数完全固定（Δθ = 0），以文本示范引导输出；
  2. 底层计算机制：自注意力计算将示范信息与待测输入进行交叉加权，在前向计算中重塑了深层激活态（直观比喻为临时工作空间），但其微观认知逻辑仍属理论探索阶段；
  3. 元学习假说未决：大模型既在利用预训练语料沉淀的先验模式识别完成翻译与问答，又在简单生造词和特定字符规则上表现出局部的现场适应，但两者的真实界限仍有待深入研究；
  4. 规模驱动效应：超大参数规模通常能提升模型对上下文示范的利用效率，但示范数量与表现之间并非绝对单调递增，逆序等极端任务证明模型并不具备万能的符号推理能力；
  5. 客观技术局限：单向因果掩码的架构约束假说、数据污染排查中的统计不确定性、上下文窗口物理容量以及长提示带来的推理算力成本，共同界定了当前上下文学习的真实能力边界。

这些结果说明，固定参数并不意味着输出行为固定；示范如何被利用，以及其中有多少属于任务识别或局部适应，仍需结合具体任务研究。
