Rspamd 的贝叶斯分类与学习

2021年12月29日
|

在邮件系统的开发与集成过程中，两类具体问题常引发对统计分类管线的误判：邮件扫描结果中没有出现任何 BAYES 相关符号时，上层业务能否将其直接当作正常邮件（ham）处理？向统计服务提交样本学习请求若遭遇网络超时，调用方能否直接发起原地重试？

要回答这些问题，需要结合 Rspamd 2.7 源码 剖析统计子系统的真实逻辑。贝叶斯分类器（Bayesian classifier）在整体架构中扮演的是“度量与特征打分”角色，而不是最终的 SMTP 动作裁决者。理解分词器（tokenizer）生成的统计特征单位（token）如何在内存流水线中转换为概率信号，以及学习状态如何在键值存储中持久化，是构建自研邮件反馈控制面的基础。

分类流水线：从特征提取到概率符号

在 Rspamd 的架构中，邮件在进入分类阶段前已经由解码层拆解，各文本分块（text_parts）已包含解析好的词元列表（utf_words），并附带结构化元数据。统计流水线并不直接处理原始信件文本，而是接收这些已生成的词元数据进行投影。

特征生成与窗口关联

Rspamd 默认采用名为 osb 的分词器（详见 osb.c）。分词器接收文本部分已有的 utf_words，并结合邮件主题等元数据（meta_words）生成特征。OSB 分词器维护一个固定大小的滑动窗口，将窗口内的词组合计算散列值，生成 64 位无符号整数表示的特征 token。

在默认的 statistic.conf 配置中，min_tokens = 11 约束的是进入统计模型的特征 token 数量，而不是自然语言中的 11 个汉字或 11 个自然词。如果一封邮件的正文极短或缺乏足够的有效词对，分词后的 token 总量未达到阈值，分类流水线将直接跳过该邮件的统计分析。在默认配置中，autolearn 仅作为样例代码被注释，系统并未默认启用自动学习机制。

异步分类的三阶段调度

分类过程在 stat_process.c 中被划分为三个严格递进的阶段：

  1. 预处理阶段（RSPAMD_TASK_STAGE_CLASSIFIERS_PRE）：调用 rspamd_stat_preprocess 对任务分词，提取 token 数组，并生成当前任务的特征签名。
  2. 后端读取阶段（RSPAMD_TASK_STAGE_CLASSIFIERS）：调用 rspamd_stat_backends_process 向持久化后端（如 Redis）异步发起特征频次查询。
  3. 后置计算阶段（RSPAMD_TASK_STAGE_CLASSIFIERS_POST）：在后端返回结果后，调用 rspamd_stat_classifiers_process 执行最终概率计算与符号插入。
/* 由统计阶段调度源码删节的逻辑示意，不是完整可编译函数 */
rspamd_stat_result_t
rspamd_stat_classify (struct rspamd_task *task, lua_State *L, guint stage,
		GError **err)
{
	struct rspamd_stat_ctx *st_ctx = rspamd_stat_get_ctx ();
	...
	if (stage == RSPAMD_TASK_STAGE_CLASSIFIERS_PRE) {
		rspamd_stat_preprocess (st_ctx, task, FALSE);
	}
	else if (stage == RSPAMD_TASK_STAGE_CLASSIFIERS) {
		rspamd_stat_backends_process (st_ctx, task);
	}
	else if (stage == RSPAMD_TASK_STAGE_CLASSIFIERS_POST) {
		rspamd_stat_classifiers_process (st_ctx, task);
	}
	task->processed_stages |= stage;
	return RSPAMD_STAT_PROCESS_OK;
}

在后置计算阶段，分类器首先验证样本基础。在默认配置下，分类器要求正常邮件（ham）与垃圾邮件（spam）的学习样本量均分别达到 min_learns（默认各 200 次）。若任一类别的已学习计数不足，系统直接退出分类，不产生任何统计符号。此外，若后端在异步拉取 token 数据时发生网络超时或连接中断，finalize_process 返回失败，流水线会主动跳过该分类器。在开发与排错中必须明确：统计后端故障或特征不足导致的“无符号”，绝不能等同于邮件被判定为正常邮件（ham）。

概率组合与符号分值映射

当 token 频次成功取回后，计算核心进入 classifiers/bayes.c。Rspamd 并未采用朴素贝叶斯的简单概率连乘，而是对每个 token 在两类样本中的频次按实际学习样本数进行归一化计算：

/* src/libstat/classifiers/bayes.c 中单个 token 的概率计算 */
spam_freq = ((double)spam_count / MAX (1., (double) ctx->spam_learns));
ham_freq = ((double)ham_count / MAX (1., (double)ctx->ham_learns));
spam_prob = spam_freq / (spam_freq + ham_freq);
ham_prob = ham_freq / (spam_freq + ham_freq);

通过特征权重与平滑公式组合后，对经过筛选的有效 token 累加对数概率，最终导出整封邮件的综合概率 final_prob（取值在 0.0 到 1.0 之间）。

只有当 fabs(final_prob - 0.5) > 0.05，即模型输出与中间不确定状态（0.5）的偏离度超过 0.05 时，分类器才会向任务插入符号：

  • 当 final_prob > 0.5 时，插入 BAYES_SPAM；
  • 当 final_prob < 0.5 时，将概率对称翻转（1.0 - final_prob），插入 BAYES_HAM。

系统通过 rspamd_normalize_probability 将偏离程度转化为传入 rspamd_task_insert_result 的归一化权重。传递给符号结果的显示字符串为 (final_prob - 0.5) * 200.0 计算出的百分比（范围 0% 到 100%）。例如计算得到概率为 0.95，显示的百分比为 90.00%。此处的 90.00% 只是特征偏离中立状态的显示信号，而不是最终规则总分，更不是线上检测的准确率或实测命中率。该符号的分值随后进入评分管线，与其他规则（如 SPF、DKIM、DMARC、DNSBL）综合累加，交由动作引擎决策最终的 SMTP 行为。

学习状态管理：条件、去重与更新

统计模型的有效性依赖于持续学习。但在高并发的生产环境中，未经控制的学习请求会导致状态库被污染或损坏。

学习准入条件与 bulk 语义

在触发样本学习时，Rspamd 会在预处理阶段之后检查学习条件。在默认配置中，learn_condition 调用 Lua 模块 lua_bayes_learn.lua。需要说明的是，此处的 Lua 脚本是在 Rspamd 进程宿主内部的 Lua 状态机中执行的回调，并不是在 Redis 服务端运行的存储脚本。

该检查的核心逻辑是防过度学习：如果待学习邮件在当前贝叶斯模型中的推断概率已经极高（例如学习 spam 时已有 bayes_prob >= 0.95，或学习 ham 时已有 bayes_prob <= 0.05），则视为“模型已知模式”，直接跳过本次学习，避免无意义的计数放大。

当且仅当请求头包含 Learn-Type: bulk 时，系统才会跳过这一基于已有推断概率的门限限制。在自研邮件控制面中必须注意：Learn-Type: bulk 仅仅是跳过上述置信度重复检查，绝不代表绕过底层的数据校验、分词限制或请求授权；业务方切勿将其开放为免验通道从不可信前端透传。

缓存去重与反向学习（unlearn）

为防止同一邮件被重复投递学习，Rspamd 设计了专用的学习缓存（learn cache，详见 redis_cache.c）。学习缓存以特定散列作为主键，存储在 Redis 中。

学习缓存的主键并非邮件头中的 Message-ID。因为在实际垃圾邮件攻击中，Message-ID 极易被伪造或重复。Rspamd 在 rspamd_stat_cache_redis_generate_id 中，将邮件分词后得到的所有 token 哈希序列以及可选的 stat_user 变量拼接后进行哈希计算，生成一个完整的 Base32 编码签名（words_hash）。

在学习执行前（LEARN_PRE 阶段），系统向 Redis 查询该散列的状态：

  • 若该主键记录的值表示此前已按同一类别学习过，系统记录 RSPAMD_TASK_FLAG_ALREADY_LEARNED 并中断学习，返回忽略；
  • 若记录显示此前学习过相反类别（如原先学为 ham，现在请求纠错为 spam），系统打上 RSPAMD_TASK_FLAG_UNLEARN 标记。在后续执行中，系统会对旧类别执行有条件的减量操作，对新类别执行增量更新。但这两者并非跨操作的强原子更新，也不保证先后顺序的绝对连续性。

状态写入与外部控制面责任

在默认配置下，Rspamd 的 store_tokens = false，因此 Redis 统计库默认不存储明文 token 词面，仅保存散列键。在 redis_backend.c 中，学习过程的执行顺序具有明确的单向依赖关系：

  1. 在 LEARN 阶段，先向后端数据库发送 token 增量命令；
  2. 待后端写入确认后，进入 LEARN_POST 阶段，调用缓存写入命令（HSET）记录该邮件特征签名已被学习。

在源码实现中，缓存写入的回调函数 rspamd_stat_cache_redis_set 仅检查连接通信状态（c->err == 0），而完全忽略 Redis 返回的具体内容。同时，token 递增与 cache 记录是两个独立的网络交互，并非跨状态的原子事务。若网络在 token 写入成功后、cache 写入前断开，系统将无法保证跨故障的“精确一次”（exactly-once）学习。

为了在业务层安全驱动学习流程，自研控制面不能依赖 Rspamd 自动处理所有边界。以下为业务层可采用的作业数据结构教学设计示例（非 Rspamd 内置 API）：

{
  "feedback_id": "fb_20211229_00192",
  "tenant_id": "tenant_enterprise_a",
  "sample_ref": "s3://mail-vault/samples/20211229/hash_abc123.eml",
  "label": "spam",
  "actor": "user_audit_team",
  "source": "webmail_user_report",
  "classifier_config_version": "bayes_v2.7_20211201",
  "created_at": "2021-12-29T09:30:00Z",
  "status": "pending"
}

作业状态在流转中可严格维护为 pending、approved、submitted、applied、skipped、unknown、failed。针对上述机制，控制面必须落实以下约束：

  • unknown 状态禁止盲目重试：当向后端发送学习请求遭遇网络超时或断连时，状态应置为 unknown。此时服务端可能已完成计数递增，盲目重试会导致特征频次被双重累加；
  • 总学习数无法证明单样本：Redis 中的 learns_spam / learns_ham 仅代表全局递增趋势，不能作为单封邮件是否已成功应用学习状态的证据；
  • 纠错串行化：对同一 sample_ref 的重复举报或误报反向纠错请求，控制面必须通过锁或单一工作队列强制串行化执行；
  • 归档依据：控制面应持久保存原始举报授权记录、合法邮件样本引用与审核依据，供后续核对与审计。

后端存储与一致性约束

Rspamd 2.7 推荐使用 Redis 新存储架构（new_schema = true）。理解数据在 Redis 中的物理组织与持久化边界，有助于评估系统的高可用方案。

Redis 键模式与事务语义

在新架构下，Redis 的典型键与字段布局如下：

  1. 类别总学习数：保存在分类器前缀哈希中，字段为 learns_spam 和 learns_ham；
  2. 特征计数哈希：每个 token 作为一个独立的哈希表，键形如 <prefix>_<token_id>。默认情况下哈希表内部字段保存整数计数值，若分类器配置了浮点增量标志，则支持按配置使用 HINCRBYFLOAT 递增。字段 S 代表垃圾邮件频次，H 代表正常邮件频次；
  3. 学习缓存哈希：键为配置的 redis_object，字段为邮件特征的 words_hash，值为 1（spam）或 -1（ham）。

在写入学习数据时，Rspamd 在客户端将命令封装在 MULTI 与 EXEC 块中。根据 Redis multi.c 源码，MULTI/EXEC 能够保证该批次命令按顺序执行且不会被其他客户端的请求穿插。但其事务语义与关系型数据库存在本质差异：

  • 无运行时回滚：如果事务中某一条子命令在运行期间发生错误（如数据类型不匹配），已成功执行的子命令并不会回滚；
  • 非跨系统事务：MULTI/EXEC 仅作用于统计特征的增量写入，与后置执行的缓存写入（learn cache）是完全独立的步骤；
  • 非持久化刷盘保证：单凭 EXEC 的成功回复，不能证明此次学习在所选持久化策略下已可靠落盘；
  • 回调只查连接状态：rspamd_redis_learned 仅验证异步连接上下文是否存在通信错误，并不逐项校验 EXEC 返回的每条子命令结果。

持久化配置与数据丢失窗口

在 Redis 6.0.10 配置 中，提供了 RDB 快照持久化（Redis Database）与 AOF 追加日志（Append Only File）两种主要机制。默认配置为 appendonly no，仅启用周期性 RDB 快照。

若维持默认配置，当主机断电或进程崩溃时，丢失窗口取决于最近一次触发快照的时间间隔。若开启追加日志（AOF），不同的刷盘策略（appendfsync）代表着不同的风险窗口：

  • appendfsync no：完全由操作系统内核决定何时将数据写入磁盘，丢失窗口取决于系统负载与文件系统行为；
  • appendfsync everysec：后台线程周期性执行 fsync，通常对应约一秒的写入损失窗口，但具体仍依赖操作系统调度与故障情形；
  • appendfsync always：针对每次写入增加 fsync 调用频率，能显著收窄数据丢失窗口，但即便如此也不能完全承诺在极端硬件故障或内核崩溃下零数据丢失。

在设计容灾备份时必须注意：如果从备份中恢复 Redis，而学习总计数（learns）、单个特征哈希以及学习缓存（cache）三者的数据集恢复时间点不一致，将使贝叶斯模型的学习状态发生偏移。因此，统计库的备份策略必须一并捕获这三类状态，不能将统计库视作丢了也能由单点重新推断的普通无状态缓存。

教学案例：营销模板误报与时间切分评估

以下构建一个促销邮件模板误报推导案例，并给出基于时间切分的数据集验证方法（本案例用于系统机制推导与接口验证，所有指标为教学示例，非生产实测数据）。

场景背景与污染传导

某企业邮箱系统承载了大量标准化模板的促销通知邮件。由于部分用户连续点击“举报为垃圾邮件”，这些反馈未经前置聚合与审核，直接被提交给贝叶斯分类器学习。

推导其在模型内部的传导过程：

  1. 共用特征倾斜：该促销模板虽然正文变量不同，但包含了相同的版式结构、页脚声明与域名特征。随着此类举报被多次学为 spam，这些共用特征 token 在 Redis 中的 S 计数被逐步抬高；
  2. 后验概率偏移：此后，业务系统向其他用户发送基于同套模板骨架的正常通知（如发货提醒）时，分词器提取到相同的 token 组合。在其他统计条件相近时，这些共享特征可能使新信件的 spam 倾向增加，甚至产生 BAYES_SPAM 符号；
  3. 网关动作：BAYES_SPAM 符号的出现提高了整体垃圾评分，但最终该邮件是被直接放行、标记主题还是拒收，依然取决于 SPF/DKIM 认证结果、发信 IP 信誉以及网关配置的动作阈值策略。不能脱离规则链条将贝叶斯符号直接等同于邮件被拒。

控制面防护边界

要阻断此类误报传导，自研反馈控制面应落实以下防护措施：

  • 样本抽样与人工审核：对于大量相似的集中举报，不能直接全量灌入模型，需经过人工审核或可信标签校验。需要注意：SPF/DKIM 提供有关主机授权或域签名验证的信号，不能作为内容属于正常邮件（ham）的合法标签；
  • 租户频次与配额熔断：对单一来源或集中举报设置时间窗口计数上限，防止瞬间冲刷统计库；
  • 纠错提交：对已确认的误标样本，控制面串行提交原样本和纠正后的类别标签，利用学习缓存识别异类并触发 UNLEARN 路径；仍需检查学习条件是否跳过、后端是否返回未决结果，不能保证一批提交就完全消除污染。

基于时间切分的模型离线验证

在评估模型参数或验证去污染效果时，必须按时间时序切分数据集：

  • 历史区间训练集（如 T0 至 T1）
  • 近期过渡验证集（如 T1 至 T2）
  • 现网时序测试集（如 T2 至 T3）

验证流程与指标规范：

  1. 时序隔离与近重复隔离：按邮件活动或会话线程分组，避免同一营销波次的近重复邮件同时跨越训练集与测试集；
  2. 静态冻结评估：在验证集与测试集上执行打分评估时，必须关闭自动学习（autolearn）及外部人工学习输入，确保测试过程中模型状态完全冻结；
  3. 指标分层统计：将模型层信号与最终网关动作明确拆开，分类记录：
    • 模型层面：正常邮件错分为 BAYES_SPAM、垃圾邮件错分为 BAYES_HAM、因 token 不足未产生信号的比例；
    • 动作层面：网关最终产生的误杀动作（如拦截正常邮件）与漏放动作（如放行垃圾邮件）；
  4. 故障降级预期观察：以下验证步骤均属于教学设计推导，非线上实测。分类测试：在隔离测试环境中使 Redis 产生读取超时，观察系统记录后端错误、该分类器不产生统计符号，且其他规则继续完成评估；邮件最终被放行或暂缓取决于网关整体策略配置，不预设系统必然不崩溃。学习测试：对已提交的学习请求阻断后端确认回复，观察自研作业状态进入 unknown 并阻止原地重试；随后通过保留的反馈流水与受控状态核对再决定是否补偿重放。不能将普通分类时的失联直接等同于学习状态 unknown。
