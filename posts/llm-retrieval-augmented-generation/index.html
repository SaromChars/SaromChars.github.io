检索增强生成的外部材料、概率边缘化与引用边界

2022年3月28日
|

在前一篇关于事实幻觉的讨论中，我们分析了大语言模型（large language model，LLM）生成虚假陈述的根源：自回归模型的目标是在人类语料分布上最小化预测负对数似然，它关注上下文的统计共现与行文流畅，而这一预测目标本身并不提供事实核验保证。更严峻的是，当模型的知识完全以连续权重矩阵的形式隐式编码在全连接层与自注意力（self-attention）投影中时，系统面临两个天然瓶颈：一是知识更新代价极高，若现实世界发生变动，往往需要昂贵的全量或增量重新训练；二是决策缺乏溯源依据（provenance），模型无法对其输出的具体事实给出可供查验的权威段落。

面对开放领域的复杂知识需求，学术界最初普遍采用“检索后抽取”（Retrieve-and-Extract）模式。这种流水线先用检索器从外部语料库（如维基百科）中召回候选段落，再由阅读理解模型从段落中截取答案跨度（span）。然而，这种抽取范式存在明显的表达天花板：它无法对多份文档的零散线索进行自然重组，无法给出自由格式的解释或完整句子；一旦标准答案没有以连续词串的形式逐字出现在任何单一检索段落中，便不能通过直接截取该段落中的连续文本得到标准答案。

Lewis et al. (2020) 在论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》1 中系统提出了检索增强生成（retrieval-augmented generation，RAG）框架，将外部文本检索与生成纳入同一概率模型。本文以该论文的首发版本（arXiv:2005.11401v1）为核心依据，分析参数化记忆与非参数化记忆的结合方式、两种不同的概率边缘化路径，以及外部检索在现实生成中所面临的特有失败边界。

1. 记忆的双重解耦：参数化与非参数化系统

RAG 的核心构想是将语言系统的认知能力拆分为两个分工明确的子模块1 (§1)：

  1. 参数化记忆（Parametric Memory）：由预训练（pretraining）的序列到序列（sequence-to-sequence，Seq2Seq）模型承担。在 Lewis et al. (2020) 的实现中，选用拥有约 4.06 亿参数的预训练双向与自回归变体 BART-large1 (§2.3)。参数化记忆负责掌握语法结构、篇章逻辑、常识推理以及在逐个 token（模型处理的基本序列单位，亦称词元）推进时流畅输出自然语言文本的能力；
  2. 非参数化记忆（Non-Parametric Memory）：由存储海量离散文本切片的外部稠密向量索引库承担。论文选用 2018 年 12 月的维基百科全文转储（dump），将其切分为 21,015,324 个互不重叠的 100 词文本块（passages）1 (§3)。
RAG 双记忆混合系统交互拓扑：
                  ┌──────────────────────────────────────────────┐
                  │ 外部非参数化记忆 (Non-Parametric Memory)       │
                  │ 维基百科离散文本切片库 (2100 万切片向量索引)  │
                  └──────────────────────┬───────────────────────┘
                                         │ 稠密向量索引匹配 (MIPS)
                                         ▼
输入查询 x ───> 查询编码器 q(x) ───> 召回 Top-K 相关文本切片 z
                   (BERT-base)           │
                                         │ 对每个候选 z 分别拼接 [x; z] 编码
                                         ▼
                               ┌───────────────────────────┐
                               │ 参数化记忆 (Parametric)    │
                               │ BART-large 生成器 (406M)  │ ───> 按检索权重序列级/逐 token 边缘化 ───> 输出 y
                               └───────────────────────────┘

图：原始 RAG 推理数据流与双记忆拓扑（教学示意，仅展示在线推理数据流，端到端微调训练机制详见正文第 3 节）

为了让外部离散文本能够与连续神经网络对接，系统采用了基于稠密段落检索（Dense Passage Retrieval，DPR）的双塔编码器（encoder）架构1 (§2.2)：

  • 文档编码器：使用 BERT-base 模型将每个 100 词切片 z 映射为稠密向量嵌入（embedding）d(z)；
  • 查询编码器：使用另一个独立的 BERT-base 模型将输入查询 x 映射为同一特征空间的查询向量 q(x)；
  • 先验检索概率：文档 z 在给定查询 x 下的先验相关度，由两者向量的点积内积衡量：
p_η(z | x) ∝ exp(⟨d(z), q(x)⟩)

在离线阶段，系统利用 FAISS 向量库构建高维最大内积搜索（Maximum Inner Product Search，MIPS）索引；在线推理时，输入查询 x 能够在数毫秒内从 2100 万个候选切片中检索出先验概率最高的 top-k 个切片1 (§2.2)。这使得模型无需预先把全部百科事实硬背在参数中，而是按需检索外部材料。

2. 隐变量概率建模：序列级与词级边缘化

在端到端概率模型中，检索出的 top-k 候选文档 z 是未被直接观测的隐变量（latent variable）。生成目标文本 y 的条件概率通过对候选文档求和（边缘化，marginalization）计算1 (§2)。

两种结构假设的区别在于文档参与边缘化的粒度。

2.1 序列级模型（RAG-Sequence）

RAG-Sequence 假设：生成完整的整个目标文本序列时，始终受同一篇检索文档的支撑1 (§2.1)。换言之，模型在候选切片集合中挑选某一文档 z，一旦确定，整个答案序列 y = (y_1, ..., y_N) 的生成均以此文档为上下文条件：

p_{RAG-Sequence}(y | x) = ∑_{z ∈ top-k(p_η(· | x))} p_η(z | x) ∏_{i=1}^N p_θ(y_i | x, z, y_{1:i-1})

这一数学假定带来了特殊的解码计算特征：

  • 它无法分解为标准的单步词级别似然，因此不能通过一次简单的束搜索（Beam Search）完成解码；
  • 完整解码（Thorough Decoding）：针对 top-k 中的每个候选文档 z，分别执行一次独立的束搜索，生成假设集合 Y。由于某候选假设 y 可能仅出现在部分文档的搜索束中，系统需要对未产生该假设的文档补跑一次前向传播计算其概率，最后在所有候选文档上累加边缘似然；
  • 快速解码（Fast Decoding）：为了应对长文本生成带来的庞大假设空间，论文提出近似假设：若序列 y 在基于 (x, z) 的局部束搜索中未被生成，则近似认为 p_θ(y | x, z) ≈ 0，从而避免追加前向计算1 (§2.5)。

2.2 词级模型（RAG-Token）

与序列级不同，RAG-Token 假设：在生成目标序列的不同 token 时，模型可以动态切换所依据的检索文档1 (§2.1)。这意味着在生成第 i 个 token y_i 时，模型都对 top-k 个候选切片进行一次独立的混合加权：

p_{RAG-Token}(y | x) = ∏_{i=1}^N [ ∑_{z ∈ top-k(p_η(· | x))} p_η(z | x) p_θ(y_i | x, z, y_{1:i-1}) ]

在 RAG-Token 结构下，单步转移概率在每个时间步被合并为单一分布，因此可以直接套用常规自回归束搜索解码器，无需复杂的多束补算1 (§2.5)。

两种机制的边缘化时机对比：
RAG-Sequence (序列级混合):
  文档 z1 ──> 生成完整候选序列 y^(1) ──┐
  文档 z2 ──> 生成完整候选序列 y^(2) ──┼──> 序列概率加权求和 p(y|x)
  文档 z3 ──> 生成完整候选序列 y^(3) ──┘

RAG-Token (词级动态切换):
  生成 token 1: [z1, z2, z3 加权混合] ──> 输出 y_1
  生成 token 2: [z1, z2, z3 加权混合] ──> 输出 y_2
  生成 token 3: [z1, z2, z3 加权混合] ──> 输出 y_3

2.3 两种方案的技术特性对照

为清晰呈现两种机制在架构假设与工程代价上的差异，对比如下：

RAG-Sequence 与 RAG-Token 机制对比表：
┌──────────────────┬──────────────────────────┬──────────────────────────┐
│ 比较维度         │ RAG-Sequence (序列级)    │ RAG-Token (词级)         │
├──────────────────┼──────────────────────────┼──────────────────────────┤
│ 文档支撑假设     │ 整个答案由单篇文档解释   │ 不同 token 可由不同文档解释│
│ 解码算法复杂性   │ 需分文档束搜索与假设合并 │ 直接使用常规单次束搜索   │
│ 多源信息综合     │ 约束于单文档语义一致性   │ 允许不同词组合不同文档线索│
│ 输出多样性表现   │ n-gram 词元丰富度更高    │ 略低于序列级，但显著高于纯BART│
│ 典型优势场景     │ 事实边界单一的短问答     │ 复合事实题目生成（如 Jeopardy）│
└──────────────────┴──────────────────────────┴──────────────────────────┘

论文在第 4.3 节的智力竞猜题目生成任务（Jeopardy Question Generation）中分析了 RAG-Token 的跨文档线索组合行为1 (§4.3)。当输入实体为作家“海明威（Hemingway）”时，生成的题目同时包含了《太阳照常升起》与《永别了，武器》两部代表作的信息：

  • 当模型解码出书名首词 "Sun" 时，文档 2 的后验贡献极高；
  • 当解码第二部作品的首词 "A" 时，后验权重迅速转移为文档 1；
  • 论文作者推测（hypothesise），RAG-Token 能够通过在不同 token 处组合不同检索文档的线索来完成合成，但这并不证明其具备普适的多跳推理能力；
  • 一旦书名首词确定，后验分布在后续 token 处趋于平缓，表明模型在此类常见书名后续词的处理上依赖自身参数化记忆即可完成补全1 (§4.3, Figure 2)。

在生成多样性方面，论文在 MS-MARCO 与 Jeopardy 开发集上统计了生成文本的 distinct tri-gram 比例，表明引入检索增强后生成的 n-gram 丰富度显著优于纯参数化 BART1 (§4.6, Table 6)。

3. 端到端联合训练机制与参数边界

在传统的问答与信息检索结合方案中，通常需要昂贵的人工标注来指出“哪一篇具体文档包含了本题的黄金证据”。

RAG 实现了一套通用的端到端微调（fine-tuning）方法1 (§2.4)：

  1. 微调阶段免检索标注：在本轮下游 RAG 微调中，训练集仅包含标准输入-输出文本对 (x_j, y_j)（例如问题与最终标准答案文本），无需提供段落级黄金标签；需要强调的是，用于初始化检索器的预训练 DPR 双塔模型，此前在 Natural Questions 与 TriviaQA 上已经使用了答案匹配段落的强监督标签，因此系统并非从零开始完全脱离检索标注；
  2. 边缘对数似然优化：训练损失函数直接定义为目标序列的负边缘对数似然：
L(θ, η) = - ∑_j log p(y_j | x_j)

在反向传播过程中，梯度并不穿过离散的 MIPS 向量检索或 top-k 候选选取步骤；而是在当前已经检索出来的 top-k 候选集合上，生成似然通过不同文档的加权概率将梯度反传至查询编码器 η，进而调整查询映射向量；在推理阶段，所有模型参数均被固定。

  1. 工程权衡：冻结文档编码器与参数口径： 在先前的 REALM 模型中1 (§1)，训练阶段同时更新文档编码器，导致数千万维基文档的向量表示持续漂移，系统必须周期性地重新对全部文档做前向推理并重构 MIPS 索引，计算开销极其昂贵。Lewis et al. (2020) 在实验中发现，完全冻结文档编码器与 MIPS 索引，仅微调查询编码器与 Seq2Seq 生成器，便足以获得强大的适应能力1 (§2.4)。

在参数口径上需严格区分：RAG 整体架构包含 DPR 的 1.1 亿参数查询编码器、1.1 亿参数文档编码器以及 4.06 亿参数的 BART-large 生成器，合计约 6.26 亿参数1 (Appendix E)。但在下游微调中，文档编码器保持冻结，实际参与梯度更新的可训练参数量为 1.1 亿（查询编码器）+ 4.06 亿（生成器）= 5.16 亿。同时，非参数化记忆并非“零成本”，维基百科切片对应的 2100 万向量索引需要巨大的额外存储与内存开销（原论文记录达 153 亿个数值）1 (Appendix E)。

4. 实验验证：问答基准与索引替换

在多个权威基准测试中，RAG 展现了结合检索的性能特性。

4.1 开放域问答的性能表现

在 Natural Questions（NQ）、WebQuestions（WQ）与 CuratedTrec（CT）上，RAG 取得了新的最佳成绩；但在 TriviaQA 上，RAG 仅在与 T5 可比的官方 Wiki 测试切分上创下新高（68.0%），在开放域社区通用的测试切分上，DPR 取得了 57.9%，高于 RAG-Sequence 的 56.1%1 (§4.1, Table 1, Appendix B)。

实验具体测试条件为（§3.5）：RAG-Token 在测试时检索 15 篇候选文档，而 RAG-Sequence 在测试时检索 50 篇候选文档。NQ 测试集精确匹配（Exact Match, test EM）对比如下：

开放域问答准确率 (NQ 测试集 Exact Match, %)：
┌─────────────────────────┬──────────────┬──────────────┐
│ 评测模型方案            │ 模型类型     │ NQ 测试集 EM │
├─────────────────────────┼──────────────┼──────────────┤
│ T5-11B (Closed-Book)    │ 纯参数化生成 │ 34.5%        │
│ REALM                   │ 抽取式检索   │ 40.4%        │
│ DPR (BERT Reader)       │ 抽取式检索   │ 41.5%        │
│ RAG-Token (top-15)      │ 检索增强生成 │ 44.1%        │
│ RAG-Sequence (top-50)   │ 检索增强生成 │ 44.5%        │
└─────────────────────────┴──────────────┴──────────────┘

相比纯参数化模型，110 亿参数的超大规模 T5 在不使用外部检索时，NQ 准确率为 34.5%1 (§4.1, Table 1)。

此外，传统的抽取式模型（如 DPR 自身的 BERT Reader）依赖从文本区间直接截取答案，当且仅当正确答案存在于检索到的段落中时才可能得分。然而，在 NQ 测试集中检索段落完全不包含标准答案的子集下，RAG 凭借参数化记忆依然取得了 11.8% 的精确匹配正确率，而抽取式模型在这一子集下的准确率为 0%1 (§4.1)。

4.2 索引替换实验（Hot-swapping Indices）

非参数化记忆的一个显著特性，是可以在不重新微调模型参数的前提下调整外部知识库1 (§4.7)。

论文在受限的实验环境下验证了这一设想：分别基于 2016 年底与 2018 年底的维基百科转储构建两套离线向量索引，并针对在此期间发生变动的 82 位国家元首身份进行统一模板提问（例如 "Who is the prime minister of the UK?"）：

  • 当挂载 2016 年索引时，NQ 微调后的 RAG 模型对 2016 年任期事实的准确率为 70%；
  • 当保持全部模型参数不变，仅将外部非参数化索引替换为 2018 年版本时，模型对 2018 年事实的准确率达到 68%；
  • 两次回答中仅有 21% 的预测结果保持重合，年代错配时准确率下降至 4%–12%1 (§4.7)。

必须客观指出该实验的限定条件：替换已构建好的外部索引虽然能改变生成回答，但不能等同于模型自动掌握了最新且绝对正确的知识。生成结果的正确性与时效性仍高度依赖底层语料的时效性、检索召回精度以及生成器的忠实度；一旦需要增加或修改知识条目，仍必须使用固定的文档编码器进行离线向量编码并更新或重建 MIPS 索引，并不存在全自动的实时知识同步1 (§4.7)。

5. 局限与失败边界：当检索未能改善生成

尽管检索增强机制为生成提供了外部事实来源，但在具体场景与工程实践中，RAG 存在明确的结构性局限与失败边界。

5.1 检索崩溃（Retrieval Collapse）

在论文附录 F 中，研究人员报告了一种名为检索崩溃（Retrieval Collapse）的病态现象1 (Appendix F)：

  • 当尝试将 RAG 应用于弱事实约束、长文本生成的任务（如故事生成，Story Generation）时，检索器在反向传播训练中发生退化，对不同的输入查询均倾向于检索出相同的文档子集；
  • 检索器一旦发生崩溃，上下文中附带的检索文档便失去了有效区分度，生成器随之倾向于忽略检索段落，模型表现退化至等同于普通自回归生成器；
  • 论文作者推测，崩溃的原因可能是此类任务对显式事实知识的需求较弱，或者过长的目标序列导致回传给检索器的梯度信号缺乏针对性。

5.2 稠密检索与关键词匹配的场景错位

尽管稠密向量检索能够捕捉语义相关的文本，但在强调精确专有名词匹配、实体指代或严格真伪核查的任务中，其表现未必优于传统稀疏检索1 (§4.5)。

在针对事实核查基准 FEVER（3 分类任务）的消融测试中，研究人员将可微分的稠密 DPR 检索器替换为基于词频重叠的传统 BM25 检索算法1 (§4.5, Table 5)：

FEVER 事实核查开发集准确率消融对比：
┌─────────────────────────┬──────────────┬──────────────┐
│ 检索与模型配置          │ 检索器类型   │ 标签准确率   │
├─────────────────────────┼──────────────┼──────────────┤
│ RAG-Token-BM25          │ 稀疏词频匹配 │ 75.1%        │
│ RAG-Sequence (Learned)  │ 稠密向量可微 │ 74.5%        │
│ RAG-Token-Frozen        │ 稠密向量冻结 │ 72.9%        │
└─────────────────────────┴──────────────┴──────────────┘

注：FEVER 为单 token 输出的类别判断任务，在此设定下 RAG-Token 与 RAG-Sequence 数学等价，此测试仅反映检索器替换效果，不作为两种生成架构优劣的评判依据。

数据表明，在实体强相关的断言核查中，基于词频精准重合的 BM25 取得了更高的标签准确率（75.1% vs 74.5%）。这说明稠密向量嵌入并不在所有场景下都全面优于关键词匹配，当核心实体出现置换时，稠密检索存在误召回风险。

5.3 材料污染与虚假归因的工程风险

在工程推断中，引入外部检索同时带来了新的生成脆弱性：

  1. 材料污染与幻觉扩散：如果检索器召回了与问题无关或本身包含错误陈述的低质文档，生成模型并不能保证辨别真伪，反而可能利用其自回归流畅表达能力，将错误事实无缝融入输出，形成隐蔽性更强的虚假信息；
  2. 检索召回不等于事实证明：外部文档被召回并输入上下文，并不意味着模型输出的每一个词都获得了该文档的真实支持；文档在模型中仅作为隐变量参与加权，无法直接视为严谨的引用证据；
  3. 空文档分支未显示收益：论文附录 D 尝试引入“空文档（Null document）”概率以建模无需依赖有效检索材料的情况，但这不等同于拒答机制，且实验发现为该分支学习嵌入、静态偏置或预测网络均未带来性能改善1 (Appendix D)。在有些查询上，模型仍可能倾向于检索固定的一组文档并依赖参数化记忆生成，这不构成答案正确或证据充分的保证1 (§4.2, Appendix D)。

总结

检索增强生成（RAG）探索了一条将外部非参数化记忆与参数化生成相结合的技术路线：

  1. 结构分工与参数口径：将语言表达保留在生成器参数中，将具体百科事实委托给外部向量索引；微调阶段仅更新查询编码器与生成器（5.16 亿参数），文档编码器与 MIPS 索引保持冻结以节约重构开销；
  2. 两类概率边缘化方案：序列级（RAG-Sequence）以单篇文档支撑完整序列，适于短文本事实生成；词级（RAG-Token）允许动态混合不同文档线索，但对复杂推理的适用性仍需谨慎评估；
  3. 索引替换的真实边界：在受限问答实验中展示了解耦更新的可行性，但并不构成对全局世界知识实时自动同步的保证，知识维护仍需依赖离线编码与索引更新；
  4. 不可忽视的工程失败模式：在弱事实任务中需警惕检索崩溃；在强实体匹配中稀疏检索仍有优势；召回外部材料并不自动等同于严格的事实核对与精准溯源。
