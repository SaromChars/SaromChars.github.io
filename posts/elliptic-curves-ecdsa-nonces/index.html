椭圆曲线与 ECDSA：密钥、签名和随机数

2018年9月11日更新于: 2026年11月7日
|

在前一篇关于 Diffie-Hellman 与 ECDH 的讨论中，我们见证了椭圆曲线在密钥协商中的机制。承接 ECDH 之后，椭圆曲线密码学（elliptic curve cryptography，ECC）不仅能用来协商秘密，还广泛用于数字签名——椭圆曲线数字签名算法（Elliptic Curve Digital Signature Algorithm，ECDSA）。[RFC 6090 §1]

与部分确定性签名相比，标准 ECDSA 方案对签名过程中的临时数（nonce）有着严格的要求。在 ECDSA 中，nonce 的不当复用或生成偏差，会给私钥带来严重的泄露风险。

基础结构：点与标量

在椭圆曲线代数体系中，所有运算围绕两个核心元素展开：标量（Scalar） 与 曲线上的点（Point）。[RFC 6090 §2]

  1. 有限域与曲线点： 曲线定义在有限素数域 GF(p) 上，满足非奇异方程（例如 Weierstrass 形式 y2 = x3 + ax + b mod p）。实数轴上的切线与弦割几何法在有限域中被抽象为严格的模 p 坐标代数加法运算。方程的所有有限域解连同一个作为单位元的无穷远点构成一个阿贝尔群。
  2. 标量与标量乘法： 设基点 G 生成的子群阶数为一个大素数 n（素数阶保证群内非零标量均存在模 n 逆元）。标量是介于 [1, n-1] 之间的整数。把基点 G 自身连续执行点加 d 次，即为标量乘法： 
    Q = d * G = G + G + ... + G (共 d 次)
  3. 公私钥的本质：
    • 私钥： 是一个保密的标量整数 d ∈ [1, n-1]。
    • 公钥： 是私钥标量与基点相乘得到的曲线坐标点 Q = (x_q, y_q)。

由私钥标量 d 计算公钥点 Q 可通过倍加算法高效完成；但在合适参数下，从公开的点 Q 反求标量 d 依赖于椭圆曲线离散对数问题（elliptic curve discrete logarithm problem，ECDLP）的数学计算困难性。

ECDH 与 ECDSA 的职责划分

同样是基于椭圆曲线标量乘法，ECDH 与 ECDSA 承担着截然不同的职责：

  • ECDH（密钥协商）： 双方各自用自己的私钥标量去乘对方的公钥点，利用 d_a * (d_b * G) = d_b * (d_a * G) 得到相同的坐标点。它是一次对称求交操作，本身不包含身份背书，算法规范可参见 RFC 6090 §4。[RFC 6090 §4]
  • ECDSA（数字签名）： 签名者使用私钥标量 d 对外部消息的哈希摘要进行代数约束，生成一对整数 (r, s)；任何持有公钥点 Q 的人均可检验该约束是否成立（在 RFC 6090 中，§5.4 规范了等价的 KT-I 签名，并在 §7.2 阐明了其与 ECDSA 标准在数学和功能上的等价性）。[RFC 6090 §5.4] · [RFC 6090 §7.2]

ECDSA 签名与验签的核心机制

在标准签名流程中，设所选基点阶数为大素数 n，签名者持有私钥 d ∈ [1, n-1]。待签署消息经过哈希后，若哈希位长超过 n 的二进制位数，保留最左侧的 bitLength(n) 位，再转换为整数 z；否则使用全部哈希位转换为整数 z：[RFC 6979 §2.3.2]

  1. 选取临时数（nonce）k： 每次签名必须生成一个严格在 [1, n-1] 内均匀分布的秘密整数 k。
  2. 计算曲线临时点： 计算 R = (x_1, y_1) = k * G。
  3. 计算第一签名分量 r： 
    r = x_1 mod n （若 r = 0 则重新生成 k）
  4. 计算第二签名分量 s： 
    s = k^(-1) * (z + r * d) mod n （若 s = 0 则重新生成 k）
    (注：因为 n 为素数且 k ∈ [1, n-1]，乘法逆元 k^(-1) mod n 必然存在。)
  5. 最终输出的签名为一对整数 (r, s)。

验证端逻辑： 验证者收到 (r, s)、公钥点 Q 和消息摘要 z 后：

  1. 校验 r, s ∈ [1, n-1]。
  2. 计算 w = s^(-1) mod n。
  3. 计算曲线点： 
    P = (z * w mod n) * G + (r * w mod n) * Q
  4. 若 P 为无穷远点，或 P 的 x 坐标模 n 不等于 r，则签名无效；否则签名验证通过。

随机数 k 的复用与偏差风险

ECDSA 的安全性深度依赖于临时随机数 k 的保密性与独立性：

1. 随机数复用直接推导私钥

设签名者使用同一私钥 d 对两个消息签名。如果签名逻辑因伪随机数故障错误复用了同一个 k，且两个消息的有效摘要满足 z1 ≠ z2 mod n：

  • 两次签名对应的曲线临时点 k * G 完全相同，因此 r1 = r2 = r。
  • 两个签名分量分别为： 
    s_1 = k^(-1) * (z_1 + r * d) mod n

s_2 = k^(-1) * (z_2 + r * d) mod n

  • 两式相减： 
    s_1 - s_2 = k^(-1) * (z_1 - z_2) mod n
  • 由于 z1 ≠ z2 mod n，必然有 s1 ≠ s2 mod n。攻击者可对 (s1 - s2) 求模 n 逆元，直接算出 k： 
    k = (z_1 - z_2) * (s_1 - s_2)^(-1) mod n
  • 一旦获得 k，即可从公开签名与摘要中推导出长期私钥： 
    d = r^(-1) * (s_1 * k - z_1) mod n

2. 随机数偏差（Bias）带来的隐患

临时数 k 甚至不需要被完全复用。RFC 6979 §1 指出，哪怕 k 的生成过程存在轻微的统计偏差，在特定的偏差模型和收集到足够多的签名样本后，攻击者依然可能利用数学方法推导并恢复出私钥 d。[RFC 6979 §1]

RFC 6979：确定性 Nonce 的机制与安全边界

为了避免因外部随机数发生器故障导致 k 被复用或出现偏差，RFC 6979 规范了 确定性 ECDSA（Deterministic ECDSA）：[RFC 6979 §1] · [RFC 6979 §3]

  • 工作机制： 签名时不再每次向操作系统请求新鲜随机数，而是将签名私钥 d 与 消息摘要 Hash(M) 作为输入，通过基于 HMAC 的确定性伪随机生成过程（规范包含内部密钥状态初始化、循环更新与拒绝采样）计算出落在 [1, n-1] 范围内的 k： 
    k = RFC6979_Derive_k(private_key, hash(message)) /* 概念示意，具体执行见 RFC 6979 §3.2 */
  • 消除运行时外部随机源故障： 正确实现 RFC 6979 可以免于签名阶段因外部随机数生成器失效而引发的 Nonce 复用或偏差问题。对于相同的私钥和输入消息，生成的 k 和签名完全确定；在 HMAC 的伪随机函数假设下，不同输入导出的 k 难以预测。该方案生成的签名格式与标准验签逻辑完全兼容，验证端无需任何修改。[RFC 6979 §1] · [RFC 6979 §4]

确定性签名的安全边界

尽管确定性方案解决了签名运行时的 Nonce 随机源故障，但并不意味着整个方案不需要随机性或能消除所有攻击：[RFC 6979 §4]

  1. 私钥生成仍需要密码学安全随机源与足够熵： 确定性 Nonce 仅作用于签名计算阶段。最初生成用户的长期私钥 d 时，依然必须依赖具有足够熵的安全随机源。如果私钥本身的生成缺乏熵，系统仍将崩溃。
  2. 物理侧信道与实现风险： 标量乘法 k * G 若在底层运算中存在时间差或功耗泄漏，攻击者依然可能通过侧信道嗅探出 k 的信息。在某些防御侧信道的工程实现中，甚至需要引入额外的随机盲化（Blinding）技术来对抗物理探测。[RFC 6979 §4]

参考资料与固定版本来源

  • RFC 6090 §1: Introduction
    D. McGrew, K. Igoe, M. Salter. Fundamental Elliptic Curve Cryptography Algorithms, February 2011. 总结了椭圆曲线密码学的基本算法与标准代数定义。
  • RFC 6090 §2: Mathematical Background
    复习了有限域模运算背景以及椭圆曲线上的加法与标量乘法法则。
  • RFC 6090 §4: Elliptic Curve Diffie-Hellman (ECDH)
    规定了基于椭圆曲线标量乘法的密钥协商计算步骤。
  • RFC 6090 §5.4: KT-I Signatures
    给出了 KT-I 签名分量 (r, s) 的生成算法与验签计算步骤。
  • RFC 6090 §7.2: Equivalence of KT-I and ECDSA
    阐明了 RFC 6090 中规范的 KT-I 签名算法与 ANSI X9.62 ECDSA 标准的数学与功能等价性。
  • RFC 6979 §1: Introduction
    T. Pornin. Deterministic Usage of the Digital Signature Algorithm (DSA) and Elliptic Curve Digital Signature Algorithm (ECDSA), August 2013. 剖析了传统 ECDSA 随机数 k 的偏差隐患，提出确定性 Nonce 的背景。
  • RFC 6979 §2.3.2: Bits to Integer
    规定了消息哈希位串向模 n 整数截断与转换的具体规则。
  • RFC 6979 §3: Generation of k
    详细规定了由私钥和消息摘要确定性派生 k 的执行流程与拒绝采样规则。
  • RFC 6979 §4: Security Considerations
    分析了 PRF 假设边界，指出私钥生成仍须安全随机性，并指出侧信道泄漏等物理威胁依然存在。
