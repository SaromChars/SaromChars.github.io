哈希的单向性与加密的可逆性

2018年8月27日更新于: 2026年11月7日
|

在探讨密码学工具时，“加密”和“哈希”常常被混为一谈。有人会说“用 MD5 或 SHA-256 把密码加密一下存入数据库”，也有人觉得“既然哈希算出来之后无法逆向解出原文，那它肯定比能解密的算法更安全”。这些说法混淆了保密传输与单向映射的根本职责。

哈希函数（hash function，其输出称为摘要，digest）并不是加密算法。加密的设计目标是在拥有密钥的前提下，可逆地恢复被保护的明文；而安全哈希函数的设计初衷是把任意长度的数据压缩成固定长度的指纹，并提供严苛的单向性与抗碰撞能力。

消息摘要与安全哈希的三大性质

加密体系围绕保密性展开：发送方用密钥加密明文生成密文，加密需要让持有正确密钥及所需参数的一方恢复明文。

哈希函数（Cryptographic Hash Function）则完全不同。以 RFC 6234 规范的 SHA 系列（如 SHA-256、SHA-512）为例，哈希函数接收任意长度（例如小于 264 或 2128 比特）的输入消息，经过填充、分块与迭代压缩，输出固定长度的散列值（通常称为消息摘要，Message Digest）。这一过程天然丢失了长度信息和冗余信息，从数学映射上看是多对一的不可逆压缩。[RFC 6234 §1]

密码学上合格的安全哈希函数，并不只是“把字符串弄乱”，而是必须满足以下三项核心安全性质：

  1. 抗原像性（Pre-image Resistance / 单向性）： 给定一个摘要值 h，在计算上无法找到任何输入消息 m，使得 Hash(m) = h。在理想 n 位哈希、目标不受较小候选集限制时，通用穷举搜索的计算复杂度数量级约为 2n。
  2. 抗第二原像性（Second Pre-image Resistance / 弱抗碰撞性）： 给定一个特定的输入消息 m1，在计算上无法找到另一个不同的输入消息 m2（m1 ≠ m2），使得 Hash(m1) = Hash(m2)。
  3. 抗碰撞性（Collision Resistance / 强抗碰撞性）： 在计算上无法找到任意两个不同的消息 m1 和 m2（m1 ≠ m2），使得它们产生相同的摘要值 Hash(m1) = Hash(m2)。受生日悖论影响，理想情况下寻找碰撞的复杂度为 2n/2。[RFC 6151 §2]

任何在传输过程中对原始消息的微小篡改，都会以极高概率导致输出完全不同的摘要，从而在摘要可信或经认证的前提下让完整性校验或数字签名发现异常。[RFC 6234 §1]

MD5 的碰撞与原像：签名禁用与校验讨论的边界

理解这三项性质的区别，有助于看清密码学标准的演进边界。

在 2011 年发布的 RFC 6151 中，针对 MD5 的安全性评估给出了明确界定：

  • 抗碰撞性彻底瓦解： 针对 MD5 的碰撞攻击已经可以在普通个人电脑上数秒至一分钟内完成，攻击者甚至构造出了具有相同 MD5 摘要的伪造 X.509 证书。因此，凡是依赖抗碰撞性的场景（最典型的就是数字签名），必须坚决淘汰 MD5。[RFC 6151 §2.1]
  • 抗原像性依然维持极高代价： 尽管学术界对 MD5 提出了快于暴力穷举的原像攻击，但其复杂度依然高达约 2123.4。这类一般原像攻击的代价依然很高，不能据此推出弱口令难以猜中。[RFC 6151 §2.2]

如果仅仅因为“无法逆向还原”就称一个算法安全，就会掩盖碰撞攻击带来的灾难。在数字签名体系中，攻击者先寻找两个内容不同但摘要相同的合法/恶意文件对，诱导签名者对合法文件签名，再将签名转移到恶意文件上。此时即使单向性完好，抗碰撞性的破裂也直接摧毁了签名的可信度。

哈希单向性与口令的离线字典猜测

工程中最常见的误区，是将“不可逆”等同于“输入绝对保密”。

设想用户登录系统时设置了一个密码。如果直接使用 SHA-256(password) 作为存储凭证，看似密码没有明文保存在数据库中，攻击者也无法直接逆向反解出 password。

但是，不可逆推并不等于不可被暴力猜测验证：

  1. 有限候选空间的顺向验证： 若候选口令集合较小（例如若候选口令只有一百万个，攻击者可逐个计算摘要并比对；这里的一百万仅为教学机制示意，不是用户口令分布实测），攻击者顺向正向计算一遍即可完成全部比对。
  2. 高效计算特性： 通用哈希函数（如 MD5、SHA-1、SHA-256）设计用于数据完整性校验与基础摘要，其计算本身是高效的。面对攻击者本地离线穷举，无需任何数学逆向，只需不断正向计算候选口令并比对即可。
  3. 彩虹表与查表反查： 攻击者无需对算法进行数学解密，只需预先计算常见候选词汇的哈希值建立映射字典（或彩虹表），或者直接离线穷举候选词典。一旦数据库泄漏，攻击者对每个哈希值进行匹配，就能在短时间内还原弱口令。

抗原像性讨论的是在相应攻击模型下寻找原像的计算难度，不承诺低熵输入保密。当输入空间局限在有限的常用候选集时，顺向枚举验证使得不可逆性形同虚设。

因此，直接使用通用哈希存储密码，无法抵御离线字典攻击。

适用边界与后续机制演进

总结而言：

  • 加密（Encryption）： 依靠密钥保护机密性，必须是可逆的。没有密钥不能读，持有正确密钥及参数可以解密。
  • 哈希函数（Hash Function）与摘要（Digest）： 依靠数学压缩和单向性提供确定性指纹，用于完整性校验和数字签名，不可逆。
  • 普通哈希不能解决的场景：
    • 防篡改不等于防伪造： 普通哈希不包含密钥。如果攻击者篡改了消息的同时重新计算了哈希，接收方无法察觉消息来源是否合法。解决这一问题需要引入消息认证码（message authentication code，MAC），如基于哈希的消息认证码（HMAC），下一篇将深入剖析。
    • 密码防盗： 口令存储需要的是刻意增加计算成本、消耗计算内存、并为每个用户增加独立随机扰动的算法（如加盐与慢哈希/KDF），后续文章将详细探讨口令哈希与密钥派生的设计。

参考资料与固定版本来源

  • RFC 6234 §1: Overview of Contents
    D. Eastlake 3rd, T. Hansen. US Secure Hash Algorithms (SHA and SHA-based HMAC and HKDF), May 2011. 说明了安全哈希函数的定义、输出长度与抗原像/抗碰撞特性。
  • RFC 6151 §2: Security Considerations
    S. Turner, L. Chen. Updated Security Considerations for the MD5 Message-Digest and the HMAC-MD5 Algorithms, March 2011. 阐明了消息摘要函数的抗碰撞、抗原像与第二原像属性。
  • RFC 6151 §2.1: Collision Resistance
    详细说明了 MD5 碰撞攻击的实际进展及其在数字签名和 X.509 证书领域的危害。
  • RFC 6151 §2.2: Pre-Image and Second Pre-Image Resistance
    记录了截至 2011 年 MD5 抗原像攻击的理论复杂度（约 2123.4），说明了单向性与抗碰撞性的独立性。
