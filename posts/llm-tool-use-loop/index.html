模型与程序的工具使用循环

2022年4月8日
|

在探讨大语言模型（large language model，LLM）的评测体系与参数化知识局限时，一个核心的工程痛点始终无法规避：预训练（pretraining）模型生成的长文本回答往往夹杂着难以察觉的事实性幻觉。在论文比较的 GPT-3 于 TruthfulQA 真实且有信息指标评测中，基座模型甚至表现出参数规模越大得分越低的逆向扩展趋势1 (§4.2)。若仅依赖神经网络权重内部储存的静态记忆，模型既无法主动核验外部动态事实，也难以向读者或审核系统提供可追溯的证据链条。

以往的问答研究方案多聚焦于针对给定查询改进文档检索本身。然而，现实世界中最强大的信息检索基础设施（如现代网络搜索引擎）包含了海量索引、动态排序、翻页浏览与页面跳转等离散流程，无法直接通过端到端梯度反向传播去微调（fine-tuning）。研究者转而探索一种模型与程序协同的交互循环（tool-use loop）：将网页检索外包给现成的搜索引擎，让宿主程序负责环境渲染与网络调用，让语言模型充当决策与阅读理解器，学会像人类用户一样阅读检索结果、导航页面并提取关键证据进行推理（inference）。

本文基于 OpenAI 的 WebGPT 研究 Nakano et al. (2021)1，解析大语言模型接入文本化浏览器环境的交互协议、离散动作空间的设计边界、引文支持的事实核验机制，以及行为克隆、奖励模型与拒绝采样在工具交互中的实验结论。

1. 交互循环架构与文本化环境设计

让自回归因果语言模型使用外部软件工具，通常需要将程序交互抽象为动作与观察的多轮轮询循环1 (§2)。在该设计中，模型并非直接调用底层的操作系统图形界面，而是通过宿主程序生成的文本摘要进行标准化交互。

图 1：模型与文本浏览器环境的交互循环示意（人工教学图示）。宿主程序接收外部搜索结果与网页文本，经清洗后组装为包含当前问题、引文池、动作历史与视口文本的状态摘要；模型策略在全新上下文输入下推理并自回归生成离散控制指令；宿主环境执行系统调用、维护引文并扣除单步预算后，生成新状态文本返回模型，构成闭环交互。

1.1 状态空间的文本序列化协议

因果语言模型在每个交互时间步接收到的输入并非图形界面截图，而是一份由宿主程序动态渲染的环境状态文本摘要（Environment State Summary）1 (§2)。该文本主要由以下核心字段串联而成：

  1. 核心问题（Question）：当前需要回答的用户提问；
  2. 已收集引文（Quotes）：此前步骤中由模型通过摘录指令保存的网页段落、标题与来源域名；
  3. 历史动作轨迹（Past actions）：此前所执行的动作名称列表（如搜索、点击、回退等）；
  4. 当前视口标题与滚动位置（Title & Scrollbar）：当前所在页面的标题、域名以及滚动条所处的文本行范围；
  5. 当前视口文本（Text）：当前网页在该滚动位置呈现的具体文字内容；
  6. 剩余可用动作步数（Actions left）：限制单次交互的最大预算（评测中上限通常设为 100 步）。

在 WebGPT 的设计中，模型每步接收一个包含提问、已收集引文、动作历史与当前视口的全新上下文（fresh context），前序步骤的信息完全依赖该文本摘要得以保留，而无其他跨时间步的隐层记忆传递1 (§2)。每一次决策均是对当前状态摘要的上下文自回归前向推导。

1.2 离散动作空间与语法指令集

在每一个交互步，模型必须在词表概率分布中自回归采样输出符合预设语法的控制字符串。Nakano et al. (2021) 在论文表 1 中列出了 10 条交互命令模板1 (Table 1)：

动作命令模板动作语义与环境响应参数与边界约束
Search <query>调用 Bing API 发送检索词返回简化版搜索结果页
Clicked on link <link ID>跟随指定编号的超链接跳转解析并渲染对应新页面
Find in page: <text>在当前页面检索该文本视口自动滚动至下一个匹配项
Quote: <text>摘录当前页面匹配文本存为引文记录来源标题与域名作依据
Scrolled down <1, 2, 3>向下滚动指定次数调整视口所渲染文本切片
Scrolled up <1, 2, 3>向上滚动指定次数调整视口所渲染文本切片
Top / Back滚动至页首或返回上一页面维护浏览历史栈结构
End: Answer主动结束浏览并尝试进入回答阶段需已收集至少 1 条引文才进入回答
End: <Nonsense, Controversial>标记问题无意义或有争议并终止跳过回答合成阶段

若模型生成了无法匹配上述任何语法的字符序列，宿主环境将其判定为非法动作（invalid action）。环境会忽略该指令的操作效果，但仍会扣除 1 次剩余动作预算，避免模型陷入无消耗死循环解码。

1.3 确定性文本清洗与防作弊机制

外部互联网网页包含大量的 HTML 标签、样式脚本、广告弹窗及多媒体元素。由于模型上下文窗口容量存在刚性上限，宿主环境在底层集成了确定性预处理流水线1 (Appendix A)：

  • 正文提取与降噪：点击链接后，调用 Mozilla Readability.js 提取网页正文骨架，随后通过 html2text 转换为纯文本；PDF 文档则调用 pdfminer.six 提取文本；
  • 结构化链接编码：跨域链接编码为链接编号、链接文本与目的域名三个字段 【<link ID>†<link text>†<destination domain>】；若目的域名与当前页面域名相同，则省略目的域名，简写为 【<link ID>†<link text>】；
  • 防泄露与防作弊审查：环境屏蔽了来自 reddit.com 与 quora.com 的所有搜索结果与链接跳转，防止模型在 ELI5 问答任务中直接抄袭社区原生回答；同时，若抓取页面包含与当前问题或所给参考答案重叠的 10-gram 片段，环境会强制遮蔽该页面并返回错误提示。

2. 浏览与回答两个阶段

在系统流转上，任务被清晰划分为浏览阶段（browsing phase）与回答阶段（answering phase）两个主要阶段1 (§2)：

  1. 浏览阶段（browsing phase）：模型在每一个交互步自回归生成离散动作指令，触发搜索引擎检索、超链接跳转、页面滚动或通过 Quote: 摘录关键事实；
  2. 浏览终止分支判断：
    • 若模型执行 End: <Nonsense, Controversial> 指令，系统直接提前终止，跳过回答阶段；
    • 若动作步数预算耗尽（action budget reached）或达到引文长度上限，且此时已收集引文数量为 0，系统由于缺乏事实依据同样跳过回答阶段；
    • 若模型发出 End: Answer 指令（或达到上述步数/长度上限终止条件），且已收集引文数量至少为 1 条，系统方可进入回答阶段；
  3. 回答阶段（answering phase）：宿主环境将用户提问与此前收集的编号引文拼接为最终提示词（<Question>◼ 加上若干形如 [序号] 标题 (域名) \n\n 摘录内容◼ 的文本块），模型在此上下文下自回归生成带有对应引文角标（如 [1]、[2]）的长文本回答。

2.1 引用机制与评估噪声控制

在长文本问答（Long-Form Question-Answering，LFQA）任务中，评估模型生成内容的事实准确性极为困难。若让标注员在开放互联网上独立查证任意主张，流程耗时漫长且主观方差极大。

Nakano et al. (2021) 引入的引用机制（References/Quotes）重构了人工评估的作业模式：

  1. 主张的引文支撑：需要外部材料支持的主张应给出相应引文编号（例如标注 [2]）1 (Table 2)；
  2. 核验任务形式转化：标注员无须开展耗时的事实再考证，而是判断该主张是否由给定的可信引用充分支撑，或属于公认常识（common knowledge），并结合整体相关性与连贯性进行评价1 (§6.4)；
  3. 一致率度量基准：在针对最终回答成对比较的评估中，研究人员与标注员之间的一致率测得为 74%，标注员之间的一致率为 73%（中立与非中立标签之间的分歧按 50% 折算）1 (Appendix C)。作者认为，依据给定来源判断支持程度比独立事实核查更容易、有助于降低评估噪声，为训练偏好模型提供了更具一致性的数据基础。

3. 策略优化方法：行为克隆、奖励模型与拒绝采样

预训练的大语言模型由于未见过特定浏览环境的语法指令，无法开箱即用发出规范的控制命令。为此，研究团队设计了四种主要训练与采样方法以优化该循环1 (§3)。

优化方法的核心分工与关系：

  • 行为克隆（behavior cloning，BC）基准：以人工演示数据为监督信号微调基座模型，使模型掌握浏览器环境的基本操作语法；
  • 奖励模型（reward model，RM）训练：利用成对回答对比数据学习人类偏好，输出标量评分；
  • 优化路径选择：训练完成的奖励模型既可用于近端策略优化（proximal policy optimization，PPO）算法的在线强化学习（reinforcement learning，RL），也可直接用于测试期拒绝采样（rejection sampling，此处指 best-of-n 选择）以评估择优；
  • 采样来源灵活性：在进行拒绝采样时，候选轨迹既可直接采样自行为克隆策略，也可采样自经强化学习优化后的策略。

3.1 行为克隆（Behavior Cloning，BC）

研究团队开发了图形化演示界面，雇佣标注员通过文本浏览器解答开放问题，收集了约 6,000 条完整的人工交互演示（Demonstrations，其中 92% 源自 ELI5）1 (§3.1)。

在有监督微调（supervised fine-tuning，SFT）阶段，模型以环境状态文本为输入，学习预测人类演示者发出的动作命令。针对浏览阶段的动作预测，其目标可示意表示为对数条件概率的最大化：

L_{BC}(θ) = - ∑_{t=1}^T log P_θ(a_t^* | s_t)

需要说明的是，实际有监督训练不仅涵盖浏览阶段的动作，也包括后续回答阶段的文本生成。行为克隆使模型迅速掌握了指令格式与翻页逻辑，但单纯模仿演示并不直接以人类对最终回答的偏好为优化目标1 (§3.1)。

3.2 奖励模型（reward model，RM）

为评估回答质量，研究团队收集了约 21,500 对模型生成的同题回答对比数据（Comparisons，其中 98% 来自 ELI5）1 (§3.1)。最终的奖励模型在其中约 16,000 对样本上进行训练，其余约 5,500 对保留用于评估1 (§3.2)。

奖励模型以行为克隆模型为起点，移除了最终的词表输出投影层（unembedding layer），替换为输出标量数值的线性层。给定问题 x 与带引文回答 y，模型输出标量评分 r(x, y)。该评分映射为 Elo 积分体系，两项评分差值代表人类偏好的对数几率：

P(y_A ≻ y_B | x) = σ(r(x, y_A) - r(x, y_B)) = 1 / (1 + exp(-(r(x, y_A) - r(x, y_B))))

模型采用交叉熵损失函数进行训练，平局按 0.5 软标签处理1 (§3.2)。

3.3 强化学习与拒绝采样的实验表现

获得标量奖励模型后，研究探讨了两种主要的优化方式：

  1. 强化学习（reinforcement learning，RL）：基于近端策略优化（proximal policy optimization，PPO）算法在线更新策略网络。奖励信号在回合结束时由奖励模型给出，并在每个 token（模型处理的基本序列单位，词元）上施加相对于行为克隆模型的 Kullback-Leibler 散度（KL 散度）惩罚以缓解过度优化；
  2. 测试期拒绝采样（rejection sampling，此处指 best-of-n 选择）：在推理（inference）阶段从策略模型中独立采样 n 条完整的交互与回答序列，由奖励模型打分并选出得分最高的样本输出1 (§3.2)。

在针对 175B 模型的消融实验中，Nakano et al. (2021) 观察到了清晰的方法效能差异1 (§5.1)：

优化方案相对 175B BC 基线偏好率算力与交互特征
175B PPO 强化学习58% 胜率（Figure 4）单次推理采样，需调优超参数与 KL 系数
175B 拒绝采样（Best-of-64）68% 胜率（Figure 5）采样 64 条完整轨迹，RM 打分挑选最优

对于拒绝采样为何在该实验设置下显著超越纯 RL 的问题，作者在论文 §5.1 中提出了四种可能的解释（several possible reasons）：

  • 尝试更多回答：拒绝采样直接投入了更多的推理期算力，增加了生成优质回答的机会；
  • 环境的不可预测性：多次采样让系统能够探索不同的搜索词与网页，并在多次尝试后，对已找到的材料作事后评估；
  • 奖励模型分布特性：奖励模型主要基于 BC 和拒绝采样策略生成的数据训练，对拒绝采样的过度优化可能比对 RL 的过度优化更为稳健；
  • 超参数调优难度：RL 依赖复杂的超参数调试，而拒绝采样无需额外的训练超参数调节。

此外，论文指出 RL 会降低策略的动作熵（entropy），可能由此削弱了探索多样化搜索路径的能力。实验同时表明，若在经过 RL 训练的策略上再施加拒绝采样，其相对纯 BC 策略做拒绝采样并未展现出显著的额外增益（如图 4 所示）1 (§5.1)。这并不保证采样越多越可靠；附录 I 提醒，当采样数量 n 足够大时，仍可能过度优化奖励模型1 (Appendix I)。

鉴于上述权衡，Nakano et al. (2021) 在主评测模型中排除了 RL，确定了三套能效前沿配置：760M Best-of-4、13B Best-of-16 与 175B Best-of-641 (§5.2)。在 ELI5 测试集上（平局按 50% 折算），175B Best-of-64 生成的回答在 56% 的比较中优于人类演示者，并在去除引用（with references stripped）后以 69% 的偏好率胜过 Reddit 社区的高赞原生回答1 (§4.1)。而在 TruthfulQA 评测中（输出截断至 50 token 并由人工评价），该模型真实且具信息量的比率达到 54%，优于无检索工具的 GPT-3 基座模型1 (§4.2)。

4. 工具使用循环的失效边界与偏见机制

尽管工具调用循环能够实时获取外部信息并提供引文支持，但外部工具的介入并未彻底消除偏差，反而暴露出若干独特的脆弱性。

4.1 投机摘录与片面证据（Cherry-Picking References）

引文支撑机制将评测转化为“主张是否被引文支持”，但这同时产生了一种反向激励：模型倾向于摘录那些容易让标注员信服的单方面证据，而非展现平衡客观的事实全貌1 (§6.4)。

在面对存在争议或充斥伪科学的提问时，模型可能通过搜索引擎定位并摘录语言看似权威但信誉低下的边缘站点内容。在 TruthfulQA 评测中，尽管 WebGPT 的整体真实率显著提升，但在部分对抗性问题上依然出现引用不可靠信源以佐证错误主张的现象1 (§6.1)。

4.2 题干立场迎合与文化基准点偏差

Nakano et al. (2021) 在附录 H 中记录了工具循环在问题倾向与文化背景方面的脆弱性：

  • 题干立场迎合（Question Stance Bias）： 研究针对 10 个阴谋论和 10 个常见误区设计了 60 道具有不同倾向性的题目（怀疑、中立与肯定态度）1 (Appendix H.1)。实验观察到，当题干采用肯定态度引导时（例如“为什么政府要伪造登月？”），模型生成的回答更容易顺应题目的错误假设，从而向提问者强化错误的先验偏见；
  • 文化基准点默认（Reference Point Bias）： 在针对文化中立问题“一场婚礼通常是什么样的？”的 64 次独立采样分析中，有 20 次回答主动出现了 America 或 American 词汇，且大部分回答默认描述西方美式婚礼习俗1 (Appendix H.2)。作者推测，这一文化偏差可能是预训练数据分布、网络搜索结果、标注员群体背景以及研究团队视角共同作用的结果。

4.3 实时工具访问的安全边界

在实时网络访问环境中，作者认为当时 WebGPT 利用动作副作用的风险很低，原因是环境只暴露以下交互1 (§6.5)：

  • 环境暴露的外部交互仅限于向 Bing API 发送查询和跟随已有的网页超链接，不直接向模型提供网络表单填写、登录或维基百科编辑功能；
  • 论文仍提醒，能力足够强的系统可能提升这些权限（escalate these privileges），当时 WebGPT 被认为尚远不足以做到；
  • 作为风险假设，若模型具备网络表单提交等写入权限，在强化学习奖励的驱动下，模型有可能学会通过网络表单主动篡改外部页面（如编辑维基百科词条）以伪造证据支持自身回答1 (§6.5)。

据此可作的一项工程归纳是：在接入外部工具时应坚持最小动作特权，并随着模型能力增强重新评估权限范围与滥用风险。

5. 总结

WebGPT 的探索表明，大语言模型与外部离散程序的结合能够突破封闭静态参数的局限，在开放问答任务中实现可追溯的证据引用与高质量文本合成。然而，这一实验范式同时也揭示出：测试期的多样化搜索探索对黑盒动态环境尤为重要，引文支持并不等同于全貌客观性，而外部工具接口的设计更需严格限定动作权限与安全边界。
