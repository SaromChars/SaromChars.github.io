LoRA 的低秩适配

2022年4月22日
|

在预训练大语言模型（large language model，LLM）的工程落地中，主流范式通常是在通用文本语料上完成大规模预训练（pretraining），再面向下游特定任务执行微调（fine-tuning）1 (§1)。然而，随着模型规模跃升至百亿乃至千亿参数（例如具备 1750 亿参数的 GPT-3 175B），传统的全量微调（full fine-tuning）遭遇了严苛的开销瓶颈1 (§1)：

  1. 训练显存开销居高不下：在反向传播与参数更新过程中，自适应优化器（如 AdamW）需要为每个可训练参数维护对应的一阶动量与二阶方差状态。在千亿规模模型上，优化器状态占用的显存（VRAM）往往达到静态模型权重的数倍，通常需要借助大规模 GPU 集群进行分布式切分1 (§3.1)；
  2. 多任务独立副本存储与部署负担重：全量微调会改动模型的全部权重。若业务需要同时服务多个下游独立任务，每个定制化模型都需要保存一份完整的模型权重副本（如 GPT-3 175B 半精度权重约 350GB），带来庞大的存储需求与模型切换 I/O 成本1 (§1)。

为了缓解参数存储与服务部署的压力，Hu et al. (2021) 提出了低秩适配（low-rank adaptation，LoRA）1 (Abstract, §1)。本文基于该论文的固定版本（arXiv:2106.09685v1），分析 LoRA 的数学构造、与早期参数高效微调方案的差异、低秩有效性的实验分析，以及在部署中的适用条件与物理边界。

1. 现有参数高效方案的折衷与缺陷

在 LoRA 提出之前，针对大模型的参数高效微调主要有两条探索路径，但它们各自伴随着特定的系统折衷1 (§1)：

1.1 串联适配器（Adapter Tuning）与推理延迟

以 Houlsby et al. (2019) 为代表的 Adapter 方案，在 Transformer 架构（一种基于自注意力机制与前馈网络的序列建模架构）的自注意力（self-attention）模块与前馈网络（feed-forward network，FFN）后串联插入紧凑的瓶颈模块，通常包含降维线性变换、非线性激活函数与升维线性变换1 (§4)。

虽然 Adapter 减少了待训练参数量，但这种人为增加网络深度的设计延长了前向传播路径。由于包含非线性激活函数，这些外置模块在部署时无法与原权重矩阵合并，导致每次推理（inference）都必须执行额外的串行计算，引入了不可忽视的推理延迟1 (§1)。

1.2 前缀微调（Prefix-Tuning）与上下文窗口的挤占

以 Li & Liang (2021) 为代表的前缀微调（prefix-tuning）方案，选择在输入嵌入（embedding）层或各层激活状态中加入连续的可学习虚拟 token（词元，模型处理的基本序列单位）1 (§4)。

该方案虽然冻结了主干模型，但存在两处局限：

  • 挤占有效上下文长度：虚拟 token 占用固定的位置编码（positional encoding），减少了模型原本用于承载下游提示词与长文档的可用序列长度1 (§1)；
  • 扩展性受限：论文实证显示，单纯增加虚拟前缀 token 数量（例如在 GPT-3 上超过 32 或 256 时），模型性能会出现下降。作者推测这可能是因为过多人工连续 token 导致输入表征分布偏离了预训练数据分布1 (§5.2, Figure 2)。

2. LoRA 的核心思想：内在秩假设与旁路分解

Aghajanyan et al. (2020) 指出，预训练语言模型具有较低的“内在维度（intrinsic dimension）”，在低维子空间中重参数化仍能有效学习1 (§1), 1 (§3)。Hu et al. (2021) 据此推测：语言模型在适应下游任务时的权重更新量同样具有较低的“内在秩（intrinsic rank）”1 (§1)。

2.1 低秩分解与参数量对比

设预训练模型中某一密集权重矩阵为 W0，其维度为 d × k。

在传统微调中，参数更新量 ΔW 具有同形状 d × k，且不施加低秩约束，全量更新需要为所有元素计算并保存梯度与优化器状态。

LoRA 则保持原始权重矩阵 W0 冻结，不更新 W0，也不维护其参数梯度和优化器状态（反向传播中输入梯度仍需经由 W0 传递）；同时将更新量约束为低秩矩阵乘积1 (§3)：

ΔW = B · A

其中：

  • A 的维度为 r × k；
  • B 的维度为 d × r；
  • 秩（rank）r 为超参数，满足 r ≪ min(d, k)。

在此定义下，待训练参数量从单个权重的 d × k 缩减为两矩阵之和 r × (d + k)，单层参数规模比例为：

参数比例 = [r · (d + k)] / (d · k)

以一个人工构造的教学参数为例：若某层权重维度为 d = k = 1024，设定 r = 4，原矩阵包含 1024 × 1024 = 1,048,576 个参数，而低秩分解仅需训练 4 × (1024 + 1024) = 8,192 个参数，仅占原权重的约 0.78%（约 1/128）。该比例对应被适配的具体矩阵，并非全模型固定比例。

2.2 训练缩放与前向计算

依据 arXiv:2106.09685v1 原文 §3，LoRA 在训练时引入固定缩放系数 s = 1/r，有效权重增量为 s · ΔW = s · B · A，将增量乘积乘以 s 以保持输出量级相对稳定1 (§3)。修改后的前向计算公式为：

h = W0 · x + s · B · A · x

在训练中，输入向量 x 分别送入主干冻结路径与旁路分解路径。旁路分支经过低维瓶颈投影与缩放后，与主干输出按坐标逐项相加（coordinate-wise sum）。

2.4 初始化设计与权重衰减

参数初始化设计如下1 (§3)：

  • 矩阵 A：采用均值为 0 的高斯分布随机初始化；
  • 矩阵 B：初始化为全零矩阵（B = 0）。

因此在训练第 0 步，由于 B = 0，未缩放增量 ΔW = B · A = 0，有效增量满足 s · B · A = 0，模型初始输出与原始预训练模型一致。这种初始化避免了初始随机增量对既有输出的扰动，但零更新本身不构成对后续训练收敛性或泛化能力的保证。

此外，作者指出对 A 和 B 施加常规权重衰减（weight decay）类似于把更新拉回预训练权重，并推测这与受限参数空间可能带来正则化优势；但该论文并未开展隔离实验来系统验证其对灾难性遗忘的具体防范效果1 (§3)。

3. 合并后的推理与任务权重存储

LoRA 的线性分解特性在部署与存储中具备以下特征：

3.1 离线权重合并消除推理延迟

由于旁路矩阵之间未插入非线性激活函数，在部署单一固定任务时，可将训练所得的增量在离线阶段直接合并入基础权重1 (§3)：

W_deployed = W0 + s · B · A

合并后的矩阵 W_deployed 维度依然为 d × k。在模型服务执行前向推理时，计算图结构与原生模型完全一致，不包含任何外置旁路分支，因此在稳态推理中不会引入额外的层间延迟或显存访存开销。

3.2 任务因子存储与动态切换

需要注意，虽然稠密乘积 B · A 的维度仍为 d × k，但磁盘与显存传输中仅需保存低维分解因子 A 与 B1 (§3.1)。

以下为论文在 GPT-3 175B 上适配注意力矩阵 Wq 与 Wv（半精度 FP16）时的资源对比与算例：

方案与配置待训练参数量存储文件体积
全量微调 (Full FT)175,255.8 M (~175B)约 350 GB / 任务
LoRA (r = 4)18.8 M (约 0.011%)约 35 MB / 任务
LoRA (r = 8)37.7 M (约 0.022%)约 70 MB / 任务

条件说明：论文实验在训练全量微调与 LoRA 时分别使用了 96 块与 24 块 NVIDIA Tesla V100 GPU；论文报告的训练显存占用分别约为 1.2 TB 与 350 GB。对于 100 个下游任务，LoRA 在该算例下的总存储需求为 350GB + 100 × 35MB ≈ 354GB，显著低于全量微调所需的 100 × 350GB = 35,000GB。

当在多个下游任务间动态切换时，服务端可保留基础模型，通过减去旧任务增量并加上新任务增量实现切换：

W_taskB = W_taskA - s_A · B_A · A_A + s_B · B_B · A_B

切换过程涉及矩阵乘法与完整权重的加减，会小幅增加峰值显存占用；论文将该切换开销描述为不超过一次模型前向传递1 (§3)。

4. 适配位置与秩的实验

在 Transformer 的自注意力模块中，存在查询（query，Wq）、键（key，Wk）、值（value，Wv）与输出投影（Wo）四个权重矩阵。

4.1 适配权重组合的实验

论文在 GPT-3 175B 上固定 18M（约 35MB）的参数预算，测试了适配不同注意力矩阵的效果1 (§6.1, Table 3)：

适配权重与秩配置WikiSQL 验证准确率 (%)MultiNLI-m 验证准确率 (%)
仅 Wq (r = 8)70.491.0
仅 Wk (r = 8)70.090.8
仅 Wv (r = 8)73.091.0
仅 Wo (r = 8)73.291.3
同时适配 Wq, Wk (r = 4)71.491.3
同时适配 Wq, Wv (r = 4)73.791.3

条件说明：实验基于 GPT-3 175B，96 层全层适配，参数预算均为 18M；WikiSQL 评估指标为逻辑形式验证准确率（标准差约 ±0.3%），MultiNLI-m 为匹配验证集准确率（标准差约 ±0.1%）。

实验显示，在相同参数预算下，同时适配 Wq 与 Wv（各分配 r = 4）在两个数据集上取得了最佳或并列最佳的结果。这表明在此类任务中，将参数预算分散到多个关键注意力投影矩阵比单独给某一个矩阵分配较大秩更为有利。

4.2 不同秩的子空间分析

论文在固定适配 Wq 与 Wv 的前提下，对比了不同秩 r 对任务效果的影响1 (§6.2, Table 4)：

设定秩 rWikiSQL 验证准确率 (%)MultiNLI-m 验证准确率 (%)

条件说明：适配对象为 GPT-3 175B 的 Wq 与 Wv，评估标准与上述标准差一致。

数据表明，在测试的下游任务中，即使将秩压缩至 r = 1 或 r = 2，模型依然取得了与更大秩相当的准确率。为探究该现象的内在机制，作者开展了子空间分析1 (§6.2, Eq. 4)：

  • 奇异值分解与子空间重叠：对不同秩（r = 8 与 r = 64）训练得到的矩阵 A 进行奇异值分解（singular value decomposition，SVD），再用其右奇异向量计算基于格拉斯曼距离的归一化子空间相似度。以第 48 层为例，r = 8 与 r = 64 共享了相似度大于 0.5 的 1 维子空间，而其余维度的重合度显著偏低。作者推测这些方向包含了较多训练积累的噪声，支持了低秩更新足以表达任务所需信息的假设1 (§6.2)；
  • 特征放大效应假说：将 W0 投影至 ΔW 的低秩子空间（计算 U^T · W0 · V^T，其中 U 与 V 为奇异向量矩阵），通过弗罗贝尼乌斯范数（Frobenius norm，用于度量矩阵整体数值规模的范数）进行对比。在 GPT-3 第 48 层 Wq、r = 4 的配置下，范数比值 ||ΔW||_F / ||U^T · W0 · V^T||_F 达到约 21.5（6.91 / 0.32）。作者据此提出一种可能解释：低秩增量矩阵并非重复 W0 中的主导奇异方向，而是选择性放大了预训练模型中原本存在但未被强调的下游任务特征1 (§6.3, §G.4)。

5. 适用条件与物理边界

在工程应用中，LoRA 存在明确的适用范围与边界：

  1. 多任务混合批处理的实现约束： LoRA 的零推理延迟依赖于将 s · B · A 离线合并入 W0。如果线上同一批次（batch）中混合了针对不同下游任务的请求，由于各任务的 A 和 B 矩阵各不相同，在常规矩阵乘法算子下无法直接共用同一次标准前向计算，需采用分批前向或针对性开发的专用推理内核1 (§3)；
  2. 领域与语言差异的边界思考： 小秩 r 不一定适用于所有任务或数据集。论文作者在 §6.2 脚注 4 中给出了思考实验：若下游任务采用与预训练语料完全不同的语言，更新整个模型参数的表现可能会优于极小秩的 LoRA1 (§6.2, Footnote 4)；
  3. 基础模型前向显存依然不可省略： LoRA 削减的是训练更新阶段优化器状态和梯度占用的显存，并在存储上降低了多任务的检查点体积。但在实际推理部署时，基础权重 W0（如 GPT-3 175B 的 350GB 静态权重）仍需完整加载进显存中，该方案并不改变基底模型本身的参数量与精度要求。

6. 总结

LoRA 通过将参数更新量分解为两个低秩矩阵的乘积，并引入固定的训练缩放因子，显著减少了下游任务的待训练参数量与检查点存储体积。其线性结构支持在部署阶段将低秩增量静态合并入基础权重，从而在稳态推理中避免了外置模块引入的额外延迟。

然而，LoRA 所需的秩与实际效果仍需在具体模型和任务上验证；在服务运行中，基础模型的常驻显存开销依然存在，且多任务混合批处理受限于矩阵合并机制。合理评估任务特征、选择适配矩阵与秩超参数，是应用低秩适配的关键考量。
