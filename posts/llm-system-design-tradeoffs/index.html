模型、检索与验证的组合

2022年5月13日
|

在构建针对特定问答或推理任务的语言模型应用时，单纯依赖模型参数化记忆（parametric memory）往往面临两重困境：一是模型在预训练或微调阶段学到的事实知识难以灵活更新，面临知识陈旧与语料冗余的风险；二是自回归语言模型（autoregressive language model）倾向于以流利句式输出虚假事实，且无法向用户提供可靠的证据出处。

为了缓解事实错误并提供溯源依据，工程与研究通常将语言模型与外部检索及验证机制组合。Lewis 等人（2020）在论文《Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks》（arXiv:2005.11401v1）中确立了检索增强生成（retrieval-augmented generation，RAG）的端到端框架1 (§1)；随后 Nakano 等人（2021）在论文《WebGPT: Browser-assisted question-answering with human feedback》（arXiv:2112.09332v1）中进一步将交互式多步网页检索、引文抽取与人类偏好验证相结合2 (§1)。这两种方案代表了不同交互深度与系统设计的取舍。

1. 单次密集检索与参数化生成的端到端结合

在经典知识密集型自然语言处理任务（如开放域问答）中，早期方案常采用流水线分离模式：先通过关键词或向量检索召回文档，再由抽取式模型切出答案片段。这种结构无法进行自由文本生成与综合改写。

1.1 RAG 的混合记忆结构

Lewis 等人提出的 RAG 架构将参数化生成模型与非参数化记忆（non-parametric memory）融合为一个统一的概率框架1 (§2.1)：

  1. 非参数化检索组件：基于密集段落检索（dense passage retrieval，DPR）的双编码器（bi-encoder）架构，使用向量内积衡量输入查询 x 与文档段落 z 的语义匹配度： 
    p_eta(z | x) ∝ exp( <d(z), q(x)> )
    其中 q(x) 与 d(z) 分别是由 BERT-base 模型生成的查询与文档密集向量表示，文档库通过最大内积搜索（maximum inner product search，MIPS）构建索引1 (§2.2)。
  2. 参数化生成组件：采用预训练自回归编码器-解码器（encoder-decoder）模型 BART-large（约 4 亿参数），将输入文本 x 与检索得到的段落 z 拼接，计算目标输出 y 的条件概率 p_theta(y_i | x, z, y_{1:i-1})1 (§2.3)。

1.2 序列与 token 边缘化

为了在生成阶段综合利用检索召回的 Top-K 个文档，RAG 围绕 token（模型处理的序列单位，亦称词元）与完整输出序列提出了两套边缘化（marginalization）建模机制1 (§2.1)：

RAG-Sequence (完整输出序列由同一候选文档引导，采用 Top-K 近似求和):
p_RAG-Seq(y | x) = sum_{z in top-k(p_eta(. | x))} p_eta(z | x) * prod_{i=1}^N p_theta(y_i | x, z, y_{1:i-1})

RAG-Token (每个 token 可由不同候选文档引导，采用 Top-K 近似求和):
p_RAG-Token(y | x) = prod_{i=1}^N sum_{z in top-k(p_eta(. | x))} p_eta(z | x) * p_theta(y_i | x, z, y_{1:i-1})

在 RAG-Sequence 模型中，检索出的每个候选文档独立引导生成完整输出序列，模型在整序列级别对 Top-K 个候选文档加权求和。在解码时，由于每个文档展开的束搜索（beam search）候选假说集合可能不同，完整推断（Thorough Decoding）需要对每个未在特定文档束中出现的候选序列追加一次前向计算以精确累加边缘概率。

为了降低推理计算量，实践中也可采用快速解码（Fast Decoding），对于总候选集合中的候选序列 y，若它未在某个文档 z 对应的束搜索中生成，就将该文档条件下的 p_theta(y | x, z) 近似置为 0，从而省去对应补算1 (§2.5)。

在 RAG-Token 模型中，生成过程在每个 token 处对所有 Top-K 文档进行概率混合，允许模型在生成单句时从不同参考段落中综合抽取事实。解码时可直接将单步混合概率代入标准自回归束搜索中1 (§2.5)。

1.3 训练边界与索引更换

在训练流程上，RAG 在下游任务微调时无需文档匹配的人工监督标注，仅最小化输出序列的负边缘对数似然：

Loss = - log p_RAG(y | x)

其中 p_RAG(y | x) 依据所选的序列或 token 边际概率公式展开。

由于训练时动态更新包含数千万段落的文档索引计算代价极高，论文作者在下游任务微调时将文档编码器及预先计算的向量索引完全固定，在反向传播中仅微调查询编码器参数 eta 与生成器参数 theta1 (§2.4)。

这种解耦使非参数化记忆具备一定的索引可更换（hot-swapping）能力。在原论文实验中，作者先使用兼容的文档编码器离线构建不同时期的维基百科索引（例如 2016 年与 2018 年版本），在针对 82 位变动国家领导人的测试集中，仅通过替换底层向量索引便使模型生成了符合新时期的回答，而无需重新训练生成器参数1 (§4.7)。但这种更换要求新文档库采用完全兼容的表示方式，且面对全新领域分布时仍须独立检验检索召回与生成的适配情况，并不等同于无维护成本的任意知识更新。

2. 交互式多步浏览与外部引文机制

单次密集检索可用于开放域单跳问答，但面对长篇开放式问答（long-form question-answering，LFQA，如 Reddit ELI5 数据集）时，往往暴露出能力瓶颈：单一查询无法捕捉复杂探索路径，静态维基片段难以覆盖即时网络信息，且生成文本中仍可能混入未经核实的内容。

2.1 文本浏览器环境与操作动作

Nakano 等人提出的 WebGPT 将任务抽象为一个基于文本的网页浏览器交互环境2 (§2)。微调后的 GPT-3 模型并不直接一次性输出长篇答案，而是通过与搜索引擎 API 循环交互来逐步搜集材料。

模型在每一步接收环境当前状态摘要（包含问题、当前光标所在网页文本、历史动作与已摘录引用），并从一组离散动作空间中选择执行一条指令2 (§2, Table 1)：

操作指令交互目标与行为说明状态转移结果
Search <query>调用搜索引擎接口获取检索列表刷新并显示包含网页标题与摘要的结果页
Clicked on link <ID>沿对应编号链接进入具体网页将当前视图切换为所选网页的正文内容
Scrolled down/up / Top滚动视口或直接回到页面顶部更新光标位置，加载后续或前置网页段落
Quote: <text>从当前网页中抽取证据片段记录该摘录、网页标题与域名至引文列表
End: Answer终止浏览，进入最终回答生成阶段将提问与全部摘录拼接，交给模型撰写回复

与单次检索相比，这种设计将信息搜集拆解为由模型主导的主动探索序列（交互步数可达 100 步）。模型可以根据初次检索返回的结果调整后续查询关键词，点击不同页面对比信息，最终完成多步材料汇总2 (§2)。

需要注意的是，WebGPT 为模型设定的工具交互权限非常受限2 (§6.5)：环境仅允许向搜索引擎发出文本查询以及访问已有网页链接，不提供填写网页表单、提交数据或编辑外部页面的接口。正如论文作者所指出的，若模型拥有表单编辑权限，其策略完全可能通过修改维基百科页面来人为伪造看似可靠的引用依据。在工程系统中，将模型与外部检索工具组合时，必须严格限制其数据读取与环境写入权限，模型输出的操作建议不能等同于无约束的通用工具执行能力。

2.2 引文抽取与事实核查客观化

在开放式长文本问答中，直接评估一段生成内容的事实准确性（factual accuracy）十分困难，评估者需要独立进行背景调查，容易导致标注分歧2 (§6.4)。

WebGPT 引入了引文抽取机制（references extraction）：

  1. 模型在浏览时必须显式调用 Quote 命令将相关网页原文存入引文列表；
  2. 只有在至少收集到一条引文的情况下，模型才被允许进入回答生成阶段；
  3. 模型生成的最终文本必须就近标注引用角标（如 [1], [2]），并在文末附上对应网页标题与出处2 (§3.1, Table 2)。

这一机制将原本模糊的“整篇回答是否真实”转化为更易判定的“回答陈述是否得到所附引文支持”。人类评估者主要比对陈述与引文片段，降低了判断难度，为后续训练奖励模型提供了噪声相对较低的偏好标签2 (§6.4)。但引文抽取本身并不保证外部来源绝对客观真实，模型依然可能摘录片面甚至错误的内容。

3. 验证机制与对齐策略的选择

在获取外部材料后，如何确保系统不仅学会操作工具，而且在答案质量、事实准确性与推理成本之间取得平衡？WebGPT 比较了多阶段的训练与验证对齐策略2 (§3.2)。

3.1 行为克隆、奖励模型与强化学习

整个系统涉及四项技术环节，但并非线性的必经训练管线2 (§3.2)：

  1. 行为克隆（Behavior Cloning，BC）：利用人类示范员在浏览器中解答问题的约 6,000 条轨迹进行监督微调，使预训练 GPT-3 模型掌握浏览指令的格式与搜索习惯2 (§3.1, §3.2)。
  2. 奖励模型（Reward Model，RM）：收集约 16,000 条模型生成回答的成对对比样本，由人类根据相关性、连贯性与引文支持度标出偏好，训练输出标量 Elo 评分的交叉熵（cross-entropy）奖励模型2 (§3.2)。
  3. 可选的强化学习（Reinforcement Learning，RL）：以 BC 策略为起点，在浏览器交互环境中利用近端策略优化（Proximal Policy Optimization，PPO）算法优化轨迹，奖励信号为最终状态由 RM 给出的得分减去逐 token（each token）与 BC 模型的相对熵（Kullback–Leibler divergence，KL 散度）惩罚2 (§3.2)。
  4. 推理期拒绝采样（Rejection Sampling / Best-of-n）：对于给定问题，从策略模型中独立采样 n 条回答候选（每条候选拥有各自完整的浏览探索轨迹与摘录引文），交由 RM 评分，选择评分最高的一条作为最终输出2 (§3.2)。该方法无需继续更新参数，但会增加推理阶段的计算开销。

WebGPT 在主评测中主要采用 BC 配合拒绝采样的组合，并为简化流程排除了 RL2 (§4)。

3.2 拒绝采样相对强化学习的收益

在实验对比中，单纯依靠 RL 带来的改进相对有限；而在拒绝采样设定下，RL 甚至未能提供显著的额外增益2 (§5.1, Figure 4)。

对比组合比较基准与任务设定胜率表现（平局计 50%）
175B RL vs. 175B BC强化学习微调 vs. 行为克隆基线58% 偏好胜率
175B Best-of-64 vs. 175B BC拒绝采样 (64 候选) vs. 行为克隆基线68% 偏好胜率
175B Best-of-64 vs. 人类示范员拒绝采样模型 vs. 人类使用浏览器解答56% 偏好胜率

如表 2 所示，175B 的 Best-of-64 模型相比纯 BC 模型取得了 68% 的人类偏好胜率；在针对人类示范员撰写答案的独立对比中，该模型也获得了 56% 的胜率。

论文作者对“为什么拒绝采样在此类任务中表现突出”提出了几点分析推测2 (§5.1)：

  • 推理期探索的事后评估优势：网络搜索环境具有较强不确定性，拒绝采样允许模型尝试多条不同方向的独立浏览路径，并在掌握完整网页材料后由奖励模型进行事后评估（hindsight evaluation），从中挑选依据更充分的候选；
  • 奖励模型的脆弱性与策略熵衰减：RL 在与同一个奖励模型反复迭代时容易过度拟合该模型的评分漏洞，且 RL 优化会降低策略分布的熵（entropy），损害浏览探索的多样性；
  • 基线微调的收敛程度：在细致调优 BC 训练轮数与采样温度后，原本 BC 与 RL 之间的性能差距已经被大幅缩小。

3.3 算力与参数规模的帕累托前沿

拒绝采样的代价是推理计算开销随采样数 n 线性增加。Nakano 等人利用一个独立划分训练的 175B 验证奖励模型（validation RM）作为人类偏好代理，分析了模型参数量与采样数 n 在固定推理算力预算下的权衡关系2 (§5.2, Figure 8)：

实验表明，在论文设定的不同推理算力预算下，适度采用较小参数量模型搭配中等规模的拒绝采样，在代理评分上通常比直接单次运行大参数模型更具算力效率。论文从计算前沿中选取了三组典型组合：

  • 7.6 亿参数模型配合 Best-of-4 采样；
  • 130 亿参数模型配合 Best-of-16 采样；
  • 1750 亿参数模型配合 Best-of-64 采样。

作者指出，这三组模型分别对应不同的算力预算层级，而非在同一预算下的小模型对比。此外，过大的采样数容易诱发奖励模型的过度优化风险，盲目增加候选数并不能无限制提升输出质量。

5. 系统的失败边界与设计权衡

结合上述两篇文献的实证探索，将模型、检索与验证机制组合为实用系统时，必须正视其固有的失败模式与边界约束：

5.1 自动化偏见与引文局限

在 WebGPT 中，带有详细引文标注的回答在人类评测中获得了较多青睐2 (§4.1)。然而，论文作者指出，引文的引入伴随着自动化偏见（automation bias）的次生风险2 (§6.2)：

  • 用户往往容易假定“带有引用标注的内容必然是真实的”，从而放松对陈述本身的警惕；
  • 但在测试反常识事实的 TruthfulQA 基准中，即使是表现最佳的 175B Best-of-64 模型，其真实且有信息量的回答比例在作者测试中也仅为 54%（答案被截断至 50 个 token）2 (§4.2)；当面对领域外分布的问题时，模型仍可能错误引用不可信来源（如论坛谣言或占卜网页）为错误观点背书。

5.2 提问立场偏见与证据挑选

当提问带有预设立场时，系统容易表现出提问立场偏见（question stance bias）与证实偏差（confirmation bias）2 (§6.3, Appendix H)：

  • 模型为了在交互中达成“陈述受引文支持”的目标，可能会主动搜索迎合提问偏见的关键词，进而选择性摘录（cherry-picking）符合该倾向的局部网页；
  • 这可能作为诱因导致奖励模型给出较高偏好分，进而在最终输出中强化提问者的初始假设，忽略了反面证据。

5.3 任务场景下的系统权衡

面对具体业务任务，两种机制的工程考量如下：

考量维度单次向量检索 (以 RAG 为代表)交互式多步探索 (以 WebGPT 为代表)
知识检索方式单次向量内积检索，依赖本地向量索引库多步调用外部搜索引擎接口，动态翻阅网页
事实溯源支持隐式注意力融合，正文无显式引文角标绑定显式抽取网页原文片段并绑定文中标注角标
索引更新约束需用兼容编码器离线构建并替换文档向量索引依赖外部搜索接口实时结果，受网络变化影响
推理计算需求开销取决于输出长度、Top-K文档数及解码策略；无需浏览器动作往返包含多次环境 API 交互循环，多候选推理开销大

从系统设计的角度来看，两篇论文分别展示了不同需求与资源约束下的解决方案：当任务面向知识相对固定、响应时间敏感的垂直问答时，基于离线索引的单次 RAG 提供了清晰的组件边界与更可控的前向计算开销；而当任务面向开放式长篇探究、需要显式提供核验依据时，以 WebGPT 为代表的多步交互、引文抽取与偏好重排机制展现了更强的证据组织能力。然而，这种机制依然受制于外部搜索环境的不确定性、证据挑选偏差以及推理阶段的算力消耗，在实际工程组合中仍需根据任务严谨性与资源预算进行针对性验证与选型。
