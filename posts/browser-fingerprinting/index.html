浏览器指纹的原理与防御

2022年6月8日更新于: 2026年11月10日
|

清空 Cookie 并重置本地存储后，在隐私窗口中打开同一网页，服务端是否还能判断两次访问来自同一个浏览器环境？答案是脚本和服务端可以通过客户端环境特征推断两次访问可能来自同一个浏览器环境。

传统的客户端状态追踪依赖保存在本地的持久化标识符，例如 Cookie、localStorage 或 IndexedDB。用户可以手动清除这些状态，隐私窗口会隔离普通会话的存储，存储分区（storage partitioning）也会按站点分开持久化数据。浏览器指纹识别（browser fingerprinting）则绕开了在客户端写入标识符的做法：服务端通过收集客户端在环境配置、操作系统、图形堆栈及音频实现中暴露的细微差异，将其组合映射为一个相对稳定的特征向量。[W3C Fingerprinting Guidance §1.1]

这种技术被广泛应用于反欺诈、机器人识别、风控检测以及跨站广告追踪。理解浏览器指纹的有效性与防御边界，需要从信息熵的度量模型出发，结合各层 Web 接口的实际差异与浏览器防御机制进行分析。

信息熵与特征度量

浏览器指纹的核心不是某个全局唯一的硬件序列号，而是由多个低辨识度特征组合而成的高辨识度向量。衡量特征区分能力的基础工具是香农熵（Shannon entropy）。

设某个离散特征 X 具有 n 种可能的取值，每种取值的出现概率为 P(xi)，则该特征所包含的信息熵定义为：

H(X) = -∑i=1n P(xi) log2 P(xi)

熵的单位是比特（bit）。对于某个具体观测值 x，其自身的信息量为 -log2 P(x)；取值越罕见，提供的信息量越大。当多个特征严格统计独立时，联合特征集的信息熵等于各独立特征熵的代数累加；但在实际浏览器环境中，由于用户代理（User-Agent，UA）、字体列表、Canvas 与 WebGL 均高度依赖底层操作系统与硬件，特征之间存在显著相关性，联合熵通常低于简单相加的数值。[Eckersley 2010 §3]

在 Peter Eckersley 针对 470,161 个浏览器样本的 Panopticlick 实验中，受测样本指纹分布熵的估计下界为 18.1 比特，样本唯一率为 83.6%。该实验明确指出其受测群体来自自选参与且对隐私保护较为关注的技术人员，不能直接等同于现代大众浏览器的通用平均值。[Eckersley 2010 §4]

在评估指纹辨识能力时，需要区分两组不同的数学概念：一是集中编号分配所需的理论编码空间，二是随机抽样下的概率碰撞。

若由中心化服务预先掌握所有设备，并在规模为 N 的设备池中为每台设备分配互不重叠的二进制编号，最少需要 ⌈log2(N)⌉ 比特的地址空间。例如当 N = 1010 时，log2(1010) ≈ 33.2，向上取整最少需要 34 比特。

但在无中心协作的浏览器指纹场景中，客户端特征是分散抽样的。在简化假设下，设各设备特征独立同分布且在 M = 2H 个状态中完全均匀分布，某台特定设备在 N 台设备中不与任何其他设备发生碰撞的概率为 (1 - 1/M)N-1。当特征空间大小与设备规模相当（即 M ≈ N）时，该特定设备不碰撞的概率仅约为 e-1 ≈ 36.8%。而在现实环境中，浏览器特征分布高度非均匀，少数主流配置占据极大比例，这使得特征向量仅能提供统计意义上的区分度，而无法提供确定性的身份判定。

被动特征与客户端提示

浏览器指纹的采集方式通常分为被动采集（passive fingerprinting）与主动探测（active fingerprinting）。被动采集指服务端仅从接收到的网络请求元数据中提取信息，主动探测则由页面脚本调用客户端 API 进行主动测量。[W3C Fingerprinting Guidance §3]

早期的典型被动特征包括 User-Agent、Accept、Accept-Language 与 Accept-Encoding 等 HTTP 请求标头。其中 User-Agent 字符串曾详细包含操作系统版本、CPU 架构、浏览器渲染引擎及补丁编号，泄露了大量系统信息。[Laperdrix 2016 §3]

为了收敛被动信息泄露，Chromium 于 2021 年 9 月公布了用户代理缩减（User-Agent reduction）路线，计划逐步冻结 UA 字符串中的详细版本与构建标识，将次版本号等冗余信息统一归零。[Chromium UA Reduction 2021]

在支持 User-Agent Client Hints（UA-CH）的 Chromium 浏览器中，客户端提示（client hints，CH）被引入作为结构化替代方案。[Chromium UA Reduction 2022] 低熵提示（如包含品牌与主版本的 Sec-CH-UA、Sec-CH-UA-Mobile、Sec-CH-UA-Platform）默认随适用的安全上下文请求发送；高熵提示（如 Sec-CH-UA-Model、Sec-CH-UA-Full-Version-List）则在服务端通过响应标头 Accept-CH 显式声明后，可随后续请求发送。此外，页面脚本亦可直接调用 navigator.userAgentData.getHighEntropyValues() 异步获取高熵提示，该 JavaScript 调用的发起独立于服务端的响应标头。

Canvas 与图形管线的渲染差异

在前端脚本主动探测中，画布指纹（canvas fingerprinting）是应用广泛的采集机制。Keaton Mowery 与 Hovav Shacham 在 2012 年的研究中证实，HTML5 <canvas> 在不同设备上执行相同的绘图指令时，最终输出存在细微但确定的像素级差异。[Mowery 2012 §1]

探测脚本通常创建一个隐藏的 <canvas> 画布，绘制包含复杂字形、特定字体回退序列、连字（ligatures）、Emoji 以及带透明通道渐变色的图形。随后调用 canvas.toDataURL() 获取编码后的图片字符串，或调用 ctx.getImageData() 读取原始 RGBA 像素矩阵，再经由哈希函数（hash function）生成固定摘要。

// 画布指纹渲染数据提取示例
function getCanvasFingerprintData() {
  const canvas = document.createElement("canvas");
  canvas.width = 240;
  canvas.height = 60;
  const ctx = canvas.getContext("2d");
  if (!ctx) return null;

  // 绘制线性渐变几何背景
  const gradient = ctx.createLinearGradient(0, 0, canvas.width, canvas.height);
  gradient.addColorStop(0, "rgb(255, 0, 128)");
  gradient.addColorStop(1, "rgb(0, 200, 255)");
  ctx.fillStyle = gradient;
  ctx.fillRect(0, 0, canvas.width, canvas.height);

  // 绘制包含回退字体与透明度的文本
  ctx.textBaseline = "alphabetic";
  ctx.font = "14px 'Arial', 'Times New Roman', sans-serif";
  ctx.fillStyle = "rgba(0, 0, 0, 0.8)";
  ctx.fillText("Fingerprint <canvas> 1.0 😃 🏳️‍🌈", 10, 30);
  ctx.fillStyle = "rgba(255, 255, 255, 0.7)";
  ctx.fillText("Fingerprint <canvas> 1.0 😃 🏳️‍🌈", 12, 32);

  // 提取原始 RGBA 像素数据（避免 PNG 压缩实现的额外干扰）
  const imageData = ctx.getImageData(0, 0, canvas.width, canvas.height);
  return imageData.data; // 生产环境通常对该字节数组计算哈希（如 SHA-256）
}

渲染结果之所以在不同设备上出现分歧，由底层多层图形软件与硬件因素共同导致：

  1. 字体文件与光栅化引擎： 不同操作系统所搭载的基础字体版本存在字形差异；Windows 的 DirectWrite、macOS 的 Core Text 以及 Linux 下基于 FreeType 的光栅化算法，在字形轮廓提取与微调（hinting）处理规则上各不相同。
  2. 抗锯齿与合成管线： 文本边缘平滑算法涉及灰度抗锯齿与特定次像素滤波。离屏画布虽然不一定会直接采用 LCD 次像素排布抗锯齿，但不同图形库在处理半透明通道混合与边缘 Alpha 衰减时存在计算偏差。
  3. 图形后端与计算精度： 浏览器可通过 Skia 等绘图库及不同平台后端，采用 CPU 或 GPU 路径完成绘制。不同硬件芯片与图形驱动在执行渐变插值与浮点光栅化时存在细微的舍入与实现差异。[Mowery 2012 §1]

若使用 toDataURL()，浏览器内置 PNG 压缩器的实现差异也会叠加到最终字符串中；直接读取原始 RGBA 像素数组能更纯粹地反映渲染层面的特征。

WebGL 与硬件参数查询

网页图形库（Web Graphics Library，WebGL）进一步扩展了图形层面的硬件探测能力。通过创建 WebGL 渲染上下文，脚本可以直接查询底层图形驱动暴露的硬件标识与计算参数。

最常见的读取接口是 WEBGL_debug_renderer_info 扩展。调用该扩展定义的常量，可以获取经过驱动与浏览器处理后的显卡厂商与渲染器描述：[Khronos WEBGL_debug_renderer_info]

// WebGL 描述字符串查询示例
function getWebGLInfo() {
  const canvas = document.createElement("canvas");
  const gl = canvas.getContext("webgl") || canvas.getContext("experimental-webgl");
  if (!gl) return null;

  const debugInfo = gl.getExtension("WEBGL_debug_renderer_info");
  if (!debugInfo) return null;

  return {
    vendor: gl.getParameter(debugInfo.UNMASKED_VENDOR_WEBGL),
    renderer: gl.getParameter(debugInfo.UNMASKED_RENDERER_WEBGL)
  };
}

需要注意的是，该接口返回的并非操作系统内核底层的原始硬件寄存器值，而是经过操作系统、图形中间层（如 ANGLE）、软件虚拟化及浏览器隐私策略处理后的描述文本。[Laperdrix 2016 §3]

除厂商字符串外，脚本还可以查询底层硬件支持的参数边界，例如通过 gl.getShaderPrecisionFormat(gl.FRAGMENT_SHADER, gl.HIGH_FLOAT) 查询片段着色器的精度范围（rangeMin、rangeMax 与 precision），或在 WebGL 2 上下文中查询多重采样支持（MAX_SAMPLES）。通过离屏帧缓冲区渲染三维模型并调用 gl.readPixels() 亦可捕获渲染差异，但 Pierre Laperdrix 等人在附录 B 中报告，其 three.js 测试会随窗口调整而改变渲染上下文尺寸，因此结果不够稳定；这说明渲染指纹需要严格控制画布、视口与上下文尺寸，该实验并未证明固定尺寸离屏渲染同样受窗口变化影响。[Laperdrix 2016 附录 B]

音频上下文与计算差异

Web Audio API 同样可以被用于提取设备特征。音频指纹（audio fingerprinting）并不采集物理麦克风的输入，也不播放真实声音，而是测量数字信号处理在不同软件与计算架构下的浮点数运算表现。[Englehardt 2016 §6.4]

采集过程利用 OfflineAudioContext（离线音频上下文）。离线上下文直接在内存中执行音频信号处理，不受实时音频输出时钟的速率限制。下例为教学示意，使用正弦波振荡器输入：

// 离线音频特征生成示意（使用正弦波）
function getAudioFingerprint(callback) {
  const AudioContext = window.OfflineAudioContext || window.webkitOfflineAudioContext;
  if (!AudioContext) return callback(null);

  const context = new AudioContext(1, 44100, 44100);
  const oscillator = context.createOscillator();
  oscillator.type = "sine";
  oscillator.frequency.setValueAtTime(10000, context.currentTime);

  const compressor = context.createDynamicsCompressor();
  compressor.threshold.setValueAtTime(-50, context.currentTime);
  compressor.knee.setValueAtTime(40, context.currentTime);
  compressor.ratio.setValueAtTime(12, context.currentTime);
  compressor.attack.setValueAtTime(0, context.currentTime);
  compressor.release.setValueAtTime(0.25, context.currentTime);

  oscillator.connect(compressor);
  compressor.connect(context.destination);
  oscillator.start(0);

  context.startRendering().then(renderedBuffer => {
    const channelData = renderedBuffer.getChannelData(0);
    let checksum = 0;
    // 示例使用索引 4500 至 4999 处的数值绝对值累加作为校验和，不推广为通用采样窗
    for (let i = 4500; i < 5000; i++) {
      checksum += Math.abs(channelData[i]);
    }
    callback(checksum.toString());
  }).catch(() => callback(null));
}

不同浏览器的音频处理实现及其底层计算路径，可能产生细微的浮点输出差异。数学库、编译优化与处理器计算路径都可能参与其中；动态压缩器（DynamicsCompressorNode）在对非线性音频信号进行包络计算与增益缩放时，其内部计算会受浮点实现差异影响。最终渲染出的 PCM 原始波形在特定时间窗口内产生数值分歧。Steven Englehardt 与 Arvind Narayanan 在 OpenWPM 测量研究的 §6.4 中支持了正弦波离线压缩方案；本节代码中选取索引 4500 至 4999 处的数值取绝对值后累加作为校验和，属于本文的教学示例设定，不应等同于原论文的通用实现。[Englehardt 2016 §6.4]

字体检测与文本度量

本地安装的字体集合在指纹特征中往往具有较高的区分度。普通系统仅配备默认字体，而安装了特定软件套件、专业设计工具或多语言支持的设备，会载入特有的字体子集。

历史上，页面可通过 Flash 插件调用 flash.text.Font.enumerateFonts(true) 获取安装的字体列表；除了依赖插件，网页也可以通过 CSS 字体回退与文本度量（font metrics）的启发式探测技术来推断字体是否存在。[Fifield 2015 §2]

该技术的基本测量步骤如下：

  1. 构造一个包含特定宽度敏感字符的基准字符串，设置较大字号。
  2. 将该字符串分别声明为三种通用回退字体族（monospace、sans-serif、serif），放入保持布局的屏幕外隐藏容器中，记录基准宽度与高度（或使用 2D Canvas 的 ctx.measureText()）。注意，若设置 display: none 会使元素无法计算几何尺寸。
  3. 当检测目标字体（如 Consolas）时，将样式设置为 ‘Consolas’, monospace。
  4. 若目标字体未安装，浏览器回退至通用字体族，测量尺寸与基准值一致；若目标字体已安装，文本尺寸通常会发生偏移。

该方法属于启发式检测：不同字体在特定字符上可能具有相同的度量值，或者字符可能回退至其他系统字体，因此存在假阴性（False Negatives）与假阳性（False Positives）。此外，David Fifield 与 Serge Egelman 的研究主要论证了利用精细字符字形度量本身直接构建指纹的可行性，与暴力遍历字体字典存在方法论差异。[Fifield 2015 §3]

浏览器防御机制的技术路线

针对无状态特征收集，主流浏览器采取了不同的防御策略。这些策略通常不是互斥的阵营，各大浏览器往往根据自身定位组合使用：

1. 统一化（Uniformity / Bucketization）

以 Tor 浏览器为代表。其核心目标是缩小群体内个体的差异范围，使同一环境下的用户呈现高度趋同的特征：[Tor Browser 9.0 Letterboxing]

  • 视口外边框（Letterboxing）： 将页面视口限制在离散档位，并在内容区外保留边框留白，降低根据窗口尺寸区分用户的可能。[Tor Browser 9.0 Letterboxing]
  • 字体暴露收敛： 限制网页对本机系统字体的访问，尽量使用浏览器自带的打包字体。[Tor Fingerprinting Challenges]

统一化能够显著降低特定特征的辨识度，但牺牲了一定程度的网页兼容性与排版体验。

2. 确定性加噪（Farbling / Randomization）

以 Brave 浏览器在 2020 年公开的 Farbling 设计为代表。该方案不直接完全切断接口，而是通过在输出数据中注入微小扰动来干扰跨站追踪：[Brave Fingerprinting Defenses 2.0][Brave Issue 9186]

  • 基于会话与站点的扰动设计： 在调用 toDataURL、getImageData 或读取 Web Audio 缓冲区时，设计以当前会话与顶层站点（eTLD+1）为种子注入微小伪随机偏移。
  • 兼容性折中： 设计目标是在同一站点单次会话内保持返回结果相对稳定，兼顾正常页面功能；在不同站点间则呈现不同数据，以干扰无状态追踪。但这类加噪机制在实际应用中仍面临复杂页面的兼容性权衡，不能简单假设其完全不影响任何正常功能。

3. 高熵接口收敛与权限化

主流商业浏览器（如 Apple Safari 与 Google Chrome）更多采取收窄高熵接口暴露面的策略：

  • 限制不安全上下文： 在 2022 年 5 月 26 日公开的 Chrome 103 Beta 说明中，Chromium 宣布将移除不安全上下文中对 Battery Status API 的支持（影响普通 HTTP 页面以及嵌入在 HTTP 页面中的 HTTPS iframe）。[Chrome 103 Deprecations]
  • 降低计时精度： 规范允许浏览器出于防范侧信道与指纹识别的考虑降低时钟分辨率，例如通过降低计时 API 精度或加入抖动来削弱高精度时间戳。[W3C High Resolution Time Level 2 §7.1]
  • 字体与硬件访问控制： Safari 默认仅允许网页使用内置系统字体与已声明的 Web 字体，阻止对本地已安装字体的随意探测；各浏览器逐步将硬件信息转入受权限管控的机制中。[WebKit Tracking Prevention]

指纹漂移与对抗边界

在实际应用中，浏览器指纹并非长期稳定不变的物理硬件标识，它面临着指纹漂移（fingerprint drift）与技术对抗的局限。

指纹特征会随着用户日常操作发生渐进或突发改变：[Vastel 2018 §3]

  1. 软件升级与配置演进： 操作系统更新、显卡驱动更新以及浏览器版本的频繁迭代，都可能改变字体光栅化或图形驱动内部的微小计算行为，导致 Canvas 与音频的哈希值发生变更。
  2. 环境重配置： 接入外部显示器、调整系统缩放比例或安装新字体，可能改变屏幕、布局或字体相关的观测值，进而使包含这些特征的指纹发生变化。
  3. 有效生命周期： Antoine Vastel 等人在针对 FP-STALKER 的实测研究中指出，测试集大约有一半的受测浏览器实例在不到五天内便发生了至少一项指纹特征改变（§III 图 3）。参与特征中任一维度的改变便会打断完整的精确等值匹配；基于规则的关联算法（测试集平均追踪时长 42.3 天）与结合机器学习的混合算法（测试集平均追踪时长 54.48 天）虽然可延长关联追踪，但纯粹基于静态特征全量等值匹配的追踪在长周期下会快速衰减。[Vastel 2018 §3, §6]

此外，第三方隐私保护扩展往往陷入自暴露矛盾。部分扩展尝试在页面上下文中对 HTMLCanvasElement.prototype.toDataURL 等原生方法进行运行时替换（monkey patching）。正如 FP-Scanner 研究在 §4.2.3 中所检测到的，这种做法容易被脚本识别出覆写迹象；一旦防御工具本身的特征被脚本检测到，这种罕见性本身反而构成了高辨识度的新特征。[Vastel FP-Scanner 2018 §4.2.3]

在跨浏览器指纹识别（cross-browser fingerprinting）领域，浏览器之间采用不同引擎、图形后端或配置，同一台物理机在不同浏览器下生成的普通 Canvas 与原始音频哈希通常并不一致。Yinzhi Cao 等人于 NDSS 2017 发表的研究证实，通过挑选并处理底层特定特征（例如对音频频谱峰值分箱），仍借助 Web API 可以构建跨浏览器的关联模型，但这依赖经过专门设计的特征处理，单纯基于 Web 常用 API 的朴素哈希在跨浏览器场景下面临明确的有效边界。[Cao 2017 §2]

  • W3C Fingerprinting Guidance: Mitigating Browser Fingerprinting in Web Specifications
    Nick Doty. W3C Interest Group Note, 28 March 2019. 体系化阐述了无状态浏览器指纹的定义（§1.1）、特征暴露分类（§3）与规范设计中的隐私保护原则。
  • How Unique Is Your Web Browser? (Panopticlick)
    Peter Eckersley. PETS 2010, July 2010. 运用香农信息熵量化了 47 万个浏览器样本的特征分布，分析了特征组合在样本集中的辨识度。
  • Pixel Perfect: Fingerprinting Canvas in HTML5
    Keaton Mowery, Hovav Shacham. W2SP 2012, May 2012. 提出了基于 HTML5 Canvas 的绘图指纹技术，分析了字体光栅化、抗锯齿算法与图形管线对输出像素的影响。
  • Beauty and the Beast: Diverting modern web browsers to build unique browser fingerprints
    Pierre Laperdrix, Walter Rudametkin, Benoit Baudry. IEEE S&P 2016, May 2016. 大规模测量了现代桌面与移动端指纹分布，分析了 WebGL、字体与扩展特征的辨识能力及其实验局限。
  • Khronos WebGL Extension: WEBGL_debug_renderer_info
    Khronos Group. 规范了获取底层图形厂商与渲染器描述字符串的常量与查询流程。
  • Online Tracking: A 1-million-site Measurement and Analysis
    Steven Englehardt, Arvind Narayanan. ACM CCS 2016, October 2016. 针对全球前一百万网站展开全量测绘，分析了 Canvas、Web Audio API 与各类无状态追踪技术的实际应用情况（§4、§6.4 与附录 §12）。
  • Fingerprinting Web Users Through Font Metrics
    David Fifield, Serge Egelman. Financial Cryptography and Data Security 2015, January 2015. 论证了利用精细字符字形度量（font metrics）直接构建浏览器指纹的方法与信息熵分布。
  • Chromium: User-Agent Reduction Origin Trial and Dates
    Chromium Blog, 2021-09-14. 记录了冻结 User-Agent 字符串、分阶段推进 UA 缩减以收敛被动信息暴露的时间表。
  • Chrome Insider: User-Agent Reduction and Client Hints
    Chrome for Developers, April 2022. 阐述了 Chromium 中 User-Agent 缩减的执行机制与结构化 Client Hints 标头的使用要求。
  • Tor Browser 9.0: Letterboxing
    The Tor Project, 2019-10-22. 介绍了 Tor Browser 9.0 引入的视口外边框（Letterboxing）防护设计，通过离散视口档位与留白减少根据窗口尺寸区分用户的风险。
  • Browser Fingerprinting: An Introduction and the Challenges Ahead
    The Tor Project, 2019-09-04. 探讨了浏览器指纹技术与 Tor 浏览器在字体、Canvas 及统一化防御方面面临的技术挑战。
  • Fingerprinting Defenses 2.0 (Farbling)
    Peter Snyder. Brave Privacy Updates, 2020. 介绍了 Brave 在 2020 年公开的 Farbling 设计，通过基于会话与顶层站点注入伪随机微小扰动干扰跨站指纹追踪。
  • Brave Browser Issue #9186: Fingerprinting 2.0 implementation
    Brave Browser GitHub Issue, 2020. 记录了 Brave Farbling 机制的工程实现与兼容性权衡讨论。
  • Chrome 103: Deprecations and Removals (Battery Status API)
    Chrome for Developers, 2022-05-26. 记录了 2022-05-26 公开的 Chrome 103 Beta 说明中，将移除不安全上下文（普通 HTTP 页面及 HTTP 中的 HTTPS iframe）对 Battery Status API 支持的计划。
  • High Resolution Time Level 2: Clock Resolution
    W3C Recommendation, 21 November 2019 (§7.1). 规范指出为防范侧信道攻击与指纹追踪，用户代理可降低计时 API 精度或加入随机抖动。
  • Tracking Prevention in WebKit
    WebKit Engineering. 介绍了 Safari 在限制本地字体枚举、防范时序侧信道与收敛指纹接口方面的具体实现策略。
  • FP-STALKER: Tracking Browser Fingerprint Evolutions
    Antoine Vastel, Pierre Laperdrix, Walter Rudametkin, Romain Rouvoy. IEEE S&P 2018, May 2018. 基于长期实测数据量化了指纹漂移的时间规律（§III 图 3），评估了测试集下规则算法与混合算法的平均追踪时长（§VI）。
  • FP-Scanner: The Privacy Implications of Browser Fingerprint Inconsistencies
    Antoine Vastel et al. USENIX Security 2018, August 2018 (§4.2.3). 揭示了通过 JS 覆写 toDataURL 等方法试图防御指纹的扩展会被探测脚本反向识别的现象。
