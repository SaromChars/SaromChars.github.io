训练数据重复与评测污染

2022年5月9日
|

在探讨自回归语言模型（autoregressive language model）的预训练（pretraining）与规模扩展时，理论分析通常建立在训练数据独立同分布（independent and identically distributed，i.i.d.）且内容多样的假设之上。而在基于 Transformer 解码器（decoder）架构的大语言模型（large language model，LLM）工程实践中，随着语料从早期的数十兆字节扩增至数百吉字节，数据收集高度依赖无人工筛选的大规模网络爬虫网页（如 Common Crawl）。

由于海量网络文本缺乏逐篇人工审查，语料中充斥着模板网页、爬虫抓取伪迹、联合转载新闻以及聚合广告。Lee 等人（2021）在论文《Deduplicating Training Data Makes Language Models Better》（arXiv:2107.06499v1）中指出，若干常用自然语言处理数据集中约有 10% 的序列存在重复1 (§1)。论文观察到，未经去重的语料会使模型更频繁地复现训练文本，且训练集与验证集的重叠也会影响困惑度（perplexity）等关键评测指标。

1. 语料中的重复现象与验证集泄漏

构建预训练数据集时，常规流程通常包含简单的去重操作，例如过滤重复 URL、对段落进行精确哈希匹配或基于前 100 个字符进行布隆过滤器去重。然而，这些浅层过滤手段无法处理经过轻微格式重排或模板化填充的内容1 (§3, §5.2)。

1.1 模板文本与极端重复

在大规模语料库中，大量文档结构完全一致，仅在特定槽位（如地名、日期、产品编号、价格）有所变化。例如在包含约 3.6 亿网页文档的 C4 数据集中，研究者发现了一段由 61 个英文单词构成的婚礼设计广告文本：

"by combining fantastic ideas, interesting arrangements, and follow the current trends in the field of that make you more inspired and give artistic touches. We'd be honored if you can apply some or all of these design in your wedding. believe me, brilliant ideas would be perfect if it can be applied in real and make the people around you amazed!"

该段完全相同的文字在训练集中出现了 61,036 次，同时在验证集中也出现了 61 次1 (§1)。在更极端的聚类统计中，C4 内最大的单个近重复文档簇包含了多达 250,933 个样本1 (§5.1)。这类高频模板大多来自商业广告、壁纸下载站、停车优惠券页面和房产中介模板。

1.2 训练集与测试集的跨分割重叠

当网络抓取的原始语料被随机切分为训练集、验证集和测试集时，重复文本会同时落入不同子集，形成训练与测试集泄漏（train-test leakage）1 (§5.3)。

表 1：常见语料库中由近重复检测（NearDup）发现的重叠比例

数据集名称训练集内部近重复样本比例验证集含有训练副本比例
C4 (Common Crawl 过滤版)3.04%4.60%
RealNews (新闻聚合语料)13.63%14.35%
LM1B (十亿词语言模型基准)4.86%4.92%
Wiki-40B (维基清洗语料英语部分)0.39%0.72%

如表 1 所示，RealNews 验证集中有 14.35% 的样本在训练集中存在近似副本；即便是经历过多轮启发式清洗的 C4，其验证集中也有 4.60% 的样本与训练集存在近重复。

这种跨集泄漏直接影响评测的解释边界：当一个模型在测试集上表现出较低的困惑度时，评估者需要审慎核对该性能究竟来自语言建模的泛化能力，还是受到了重叠样本记忆的影响1 (§1)。

2. 识别与剔除重复的双轨机制

为了克服精确全篇匹配无法识别细微篡改的缺陷，Lee 等人提出了两套互补的去重算法：针对局部字面重复的精确子串去重（ExactSubstr），以及针对全篇结构相似的近重复文档去重（NearDup）1 (§4)。

2.1 基于后缀数组的精确子串去重

在自然语言中，由数十个词组成的连续序列如果字面完全相同，极大概率属于复制粘贴或共同引用，而非独立巧合。

ExactSubstr 算法将整个语料库的所有文档拼接为一条超长序列 S，并为该序列构建后缀数组（suffix array，记为 A）1 (§4.1.1)。后缀数组是将序列所有后缀按字典序排列得到的起始位置索引列表：

A(S) = arg sort ( all_suffixes(S) )

共享同一长度 k 前缀的后缀在排序后会汇聚为连续区间，因此算法只需对后缀数组进行一次线性扫描，检查相邻后缀的公共前缀长度即可找出全部重复子串。

通过统计匹配概率与子串长度 k 的关系曲线，研究者发现曲线拐点出现在 10 个 token（模型处理的序列单位，亦称词元）附近。人工抽查 25 个 token 的匹配未发现误报；为保持充足的安全余量，最终选取保守匹配阈值 k = 50 个 token1 (§4.1.3)。当跨数据切分发现匹配时，去重流程优先保留测试集或验证集中的内容，并从训练集中剔除重叠子串。

2.2 基于 MinHash 与编辑相似度的近重复文档去重

对于模板填充型文档，虽然单次连续字面匹配可能达不到 50 个 token，但整篇文档的大部分内容高度重合。NearDup 采用基于局部敏感哈希（locality-sensitive hashing，LSH）的最小哈希（MinHash）算法1 (§4.2)。

算法将文档 d_i 表示为连续 5-gram（5 元序列）的集合，用 MinHash 估算两篇文档的 Jaccard 相似系数（Jaccard index）：

Jaccard(d_i, d_j) = |d_i ∩ d_j| / |d_i ∪ d_j|

工程实现生成包含 9,000 个最小哈希值的签名，并将其划分为 r = 450 个桶（bucket），每个桶包含 b = 20 个哈希值。两篇文档在至少一个桶中产生哈希碰撞的理论概率为：

Pr(碰撞) = 1 - (1 - s^b)^r

其中 s 为真实的 Jaccard 相似系数。在产生碰撞的候选文档对中，进一步校验实际 Jaccard 系数是否大于 0.8；若满足条件，再计算编辑相似度（edit similarity）：

EditSim(x_i, x_j) = 1 - EditDistance(x_i, x_j) / max(|x_i|, |x_j|)

当且仅当两个候选样本的实际 Jaccard 系数与编辑相似度均高于 0.8 时，判定两者为近似重复。随后通过图的连通分量算法（connected components）构建文档簇，在每个簇内仅保留一份副本，剔除其余样本。需要说明的是，连通分量聚类并不保证同一簇内任意两篇文档之间都直接满足阈值。

根据 ExactSubstr 统计，在 C4 训练集中有 7.18% 的 token 被识别为长度至少 50 token 的重复子串的一部分；而在新闻语料 RealNews 中，这一重复子串覆盖比例达到了 19.4%1 (§5.1, Table 3)。

3. 重复样本与验证集困惑度

为了检验去重对语言模型训练的具体影响，研究团队基于 Transformer 解码器架构训练了包含 1.1 亿参数（Base 规格）与 15 亿参数（XL 规格）的模型，分别在原始 C4、NearDup 去重版 C4 以及 ExactSubstr 去重版 C4 上训练两个周期（epochs）1 (§6)。

3.1 验证子集表现与评测差异

在评估自回归模型时，困惑度通常是核心量化指标。研究者将验证集拆解为“无近重复的唯一样本子集”与“与训练集重叠的近重复子集”分别测算1 (§6.1, Figure 3)。

在论文的 C4 decoder-only 模型实验中，在无重复的唯一样本验证子集上，使用去重语料训练的模型与原始语料训练的模型困惑度相近；而在领域外基准 Wiki-40B 英语部分上，在 ExactSubstr 去重数据上训练的 XL 模型困惑度改善了接近 3 个点1 (§6.1)。但在与训练集重叠的验证子集上，由于未去重模型接触过这些样本，其困惑度被拉得更低，去重模型在该子集上的困惑度相对更高。

对比既有公开发布模型在不同验证子集上的表现，也可以观察到评测样本是否在训练集中存在副本对困惑度数值的影响：

表 2：既有模型在验证集重复与非重复子集上的困惑度对比

模型与训练语料验证集子集划分困惑度 (Perplexity)
Transformer-XL (LM1B)官方验证集基准21.77
Transformer-XL (LM1B)训练集近重复子集10.11
Transformer-XL (LM1B)无重复唯一样本子集23.58
GROVER-XL (RealNews 前 25k)验证集评测子集9.15

在表 2 中，由于 RealNews 验证集规模较大，评测仅取各条件前 25,000 条样本测算1 (§6.3, Table 5)。Transformer-XL 在近重复子集上的困惑度（10.11）明显低于其在唯一样本子集上的困惑度（23.58）。这说明在这些评测中，训练与验证集的重叠会显著影响报告的困惑度数值；在评估模型的通用语言建模能力时，有必要单独隔离并检查重叠样本，以获得更客观的泛化表现1 (§6.3)。

3.2 记诵现象显著降低

模型频繁记诵并输出训练集内容不仅挤占表达容量，还会增加潜在的信息泄露风险。研究人员使用 top-k 随机采样（k = 50）生成最多 512 个 token 的序列，评估了 1.5B XL 模型在 100,000 次无提示生成中的字面照抄行为1 (§6.2, Table 4)：

表 3：无提示生成文本中包含 50-token 训练集字面复制片段的 token 比例

训练数据集版本 (1.5B XL)训练 1 个周期后的记诵率训练 2 个周期后的记诵率
C4-Original (未去重基线)1.926%1.571%
C4-NearDup (近重复去重)0.189%0.264%
C4-ExactSubstr (子串去重)0.138%0.168%

在未去重的原始语料上，1.5B 模型的无提示生成输出中有超过 1%（1.571%–1.926%）的 token 属于字面照抄训练集的长片段（≥50 token）；而在经过去重处理的数据集上，该比例下降到约 0.14%–0.26%，记诵率下降了接近一个数量级（约 10 倍）1 (§6.2)。

而在前 32 个 token 的提示续写实验中（同样采用 top-k=50 采样生成最多 512 token），当提示语来自训练集重复样本时，未去重模型（XL-Original）有超过 40% 的生成文本与训练集原始续写达到编辑相似度大于 0.8 的近重复复现；去重后的模型该近重复续写率显著降低1 (§6.2, Figure 4)。需要指出的是，该指标衡量的是近重复续写比例，去重并未彻底消除记忆倾向，也不能直接等同于多样性或事实性的全面保证。

4. 算力开销与机制局限

在工程落地中，去重常被担忧是否会引入过高的预处理计算负担，或者对特定下游能力带来负面影响。

4.1 预处理与训练计算成本对照

论文给出的计算开销核算表明，在 CPU 上执行去重的开销相比大语言模型的预训练明显较小1 (Appendix B, D)：

  1. 后缀数组构建与扫描：在配置 96 核 CPU 与 768GB 内存的云主机上，构建 350GB C4 语料的后缀数组（磁盘占用约 1.5TB）耗时不到 12 小时（折合约 1,000 CPU 小时），后续去重扫描耗时不足 1 小时。
  2. MinHash 近重复计算：使用高度优化的分布式流水线处理全量 C4 耗电约 41.5 千瓦时（kWh）。
  3. 训练节省的净收益：由于剔除了冗余样本，经 NearDup 过滤后的 C4 语料体积缩减了约 3.9%，使得 1.5B 模型在 128 核 TPU v3 上的单周期训练时间减少约 2.5 小时，两个周期净节省约 5 小时算力（估算减少约 0.23 MWh 电力消耗）。

在论文给出的这组训练与能耗估算中，NearDup 的预处理计算开销（约 41.5 kWh）小于其所节省的训练能耗（约 0.23 MWh）。但该结论建立在特定的硬件与两周期训练设置下，并非对所有模型架构与训练制度的普遍保证。

4.2 漏检边界与机制权衡

尽管去重带来了诸多收益，但作者也强调了现有算法的适用边界与权衡约束1 (§7)：

  1. 两套方案各自的漏检盲区： ExactSubstr 设定了 50 个 token 的匹配下界，无法识别短于该长度的频繁重复句；若模板中变量字段穿插较密，字面连续匹配被截断，该算法也会漏检。NearDup 依据全篇整体相似度，若一篇长文章仅在中间逐字包含另一篇文献的一个 200 词段落，但整篇文档的 Jaccard 相似度与编辑相似度不足 0.8，该段落不会被识别为重复。
  2. 孤立敏感信息的局限性： 去重依赖于“在所用训练语料中重复出现”这一统计特征。如果特定个人隐私数据（如个人电话或证件号码）在训练集中仅出现过一次，去重流程无法将其识别剔除。防范单次隐私泄露仍需结合其他针对性的隐私筛查与合规过滤机制。
  3. 检索问答与引用出处的两难： 在文档检索（document retrieval）或闭卷问答（closed-book question answering）等任务中，准确记诵特定事实或文本本身是模型预期的能力；此外，网络文本中给出引用来源的声明语句往往高度雷同，盲目截除子串可能误将引用出处剥离而仅留下正文内容，这也是清洗时需要权衡的工程代价。
