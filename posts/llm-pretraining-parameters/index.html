预训练的参数更新：训练数据、损失函数与训练和推理成本

2022年3月14日
|

在前一篇探讨中，我们梳理了大语言模型（large language model，LLM）在推理（inference）阶段的文本生成闭环：模型隐藏状态通过语言模型头（language model head，LM Head）投影为词表维度的未归一化分数（logits），经由 Softmax 归一化为条件概率分布，并通过采样策略逐步生成下一个 token（模型处理序列的基本单位，可对应子词、字符或字节片段）。

但这套自回归生成流程能够输出合理自然语言的前提，是模型已经拥有了一组高度协调的多层网络参数。

如果网络权重仅处于刚完成初始化的随机状态，输入任何提示词，模型给出的预测概率分布都会接近均匀分布或无序杂乱的输出。在纯解码器（Decoder-only）架构的自回归 Transformer 中，无标注语料通过下一 token 预测为参数更新提供训练信号。本文结合公开文献的数学定义与工程记录，系统拆解预训练（pretraining）阶段的参数更新机制与计算边界。

1. 预训练目标：自回归因果语言建模与交叉熵损失

自回归语言模型的预训练主要采用自监督学习：原始文本本身既作为输入上下文，又提供了下一位置的监督目标，无需人工逐句标注任务标签。

1.1 条件似然与自回归因果损失

给定一段长度为 T 的离散 token 序列 X = [x_1, x_2, ..., x_T]（序列长度 T >= 2）。自回归语言建模不计算首 token 的损失，而是以 x_1 为已知上下文，最大化后续其余所有 token 条件概率的对数似然：

L_NLL(theta) = - sum_{t=1}^{T-1} log P(x_{t+1} | x_{<=t}; theta)

其中 theta 代表网络中所有可训练的参数集合，x_{<=t} = [x_1, ..., x_t] 代表第 t 个位置及其之前的上文历史。

在实际实现中，最小化上述负对数似然等价于在每个预测位置计算条件预测分布与真实目标 token 之间的交叉熵损失（Cross-Entropy Loss）。

对于输入位置 t（从 1 到 T-1）：

  1. 模型经过多层包含因果掩码的自注意力（self-attention）1 与前馈网络（feed-forward network，FFN）前向传播，得到该位置顶层的隐藏状态向量 h_t；
  2. 线性语言模型头将 h_t 投影到词表维度 |V|，得到未归一化分数向量 z_t；
  3. Softmax 函数给出该位置对后续 token 的预测概率分布 p_t，其中候选词表中第 j 个 token 的预测概率为：
p_{t, j} = exp(z_{t, j}) / (sum_{k=1}^{|V|} exp(z_{t, k}))
  1. 该位置对应的真实目标是后续下一个 token x_{t+1}。位置 t 产生的单步交叉熵损失为：
ell_t = - log p_{t, x_{t+1}} = - z_{t, x_{t+1}} + log(sum_{k=1}^{|V|} exp(z_{t, k}))

整条序列的平均标量损失值记为：

L = (1 / (T - 1)) * sum_{t=1}^{T-1} ell_t

预训练中参数优化的核心，正是通过优化算法寻找能使批次平均损失 L 降低的参数取值。

2. 反向传播与权重更新

在得到损失标量 L 之后，优化器通过微积分链式法则计算损失关于网络参数的梯度，以调整参数取值。

2.1 梯度的含义与局部下降方向

对于网络中任意一个可学习权重参数矩阵 W（例如注意力机制中的投影矩阵 W_Q, W_K, W_V, W_O、前馈网络矩阵或词嵌入（embedding）矩阵），链式法则通过向后传播误差敏感度计算损失关于该参数的总梯度：

g_W = dL / dW

需要明确的是：

  • 负梯度方向 - g_W 是当前输入批次目标函数在当前参数点的一阶局部最陡下降方向；
  • 在步长（学习率）足够小等理想条件下，沿负梯度更新能够降低当前批次上的计算损失；
  • 但这并不构成逐个样本预测概率单调改善的绝对保证：在更新后，特定单个样本或验证集损失完全可能出现波动或上升；
  • 在独立未归一化分数 z_t 的局部求导中，交叉熵损失表现为“真实目标 token 对应分值的导数为负，非目标 token 导数为正”；然而由于底层参数在全序列所有位置及不同 token 之间深度共享，参数更新后网络无法保证每一个输出分值都严格朝单一方向变化。

最基础的梯度下降参数更新示意式为：

W_new = W - eta * g_W

其中 eta > 0 为学习率。

2.2 极简一维前向与反向更新教学演示

为展示反向传播的算式逻辑，本节构造一个可完全手工复算的极简一维标量用例。

特别声明：本算例为方便读者跟踪算式而人工构造的教学演示用例，非真实大模型的真实参数或实测输出。计算过程采用逐步舍入数值展示，内部保持自洽与可复算性。

假设词表大小仅包含两个候选 token：索引 0 与索引 1。

  • 输入标量特征为 x = 2.0；
  • 模型包含单个可学习权重标量 w，初始设定为 w = 0.5；
  • 线性层计算索引 1 的 token 未归一化分数 Logit 为 z = w * x（为简化算式，设索引 0 的 token 得分恒为常数 0.0）；
  • 目标标签为 y = 1。

1. 前向传播计算

  1. 计算 Logit： z = 0.5 * 2.0 = 1.0；
  2. 计算 Softmax 预测概率（候选得分 [0.0, 1.0]）： exp(0.0) = 1.0，exp(1.0) ≈ 2.71828； 分母和为 1.0 + 2.71828 = 3.71828； 预测目标概率：P(y=1) = 2.71828 / 3.71828 ≈ 0.73106；
  3. 计算该样本的交叉熵损失 L： L = - ln(0.73106) ≈ 0.31326。

2. 反向传播求导

  1. 损失 L 对得分 z 的偏导数： dL / dz = P(y=1) - 1 = 0.73106 - 1.0 = -0.26894；
  2. 得分 z 对可学习权重 w 的导数： dz / dw = x = 2.0；
  3. 链式法则求得损失关于权重 w 的梯度 g： g = (dL / dz) * (dz / dw) = (-0.26894) * 2.0 = -0.53788。

3. 梯度下降参数更新

设定学习率 eta = 0.1，执行单步梯度下降更新：

w_new = w - eta * g = 0.5 - (0.1 * (-0.53788)) = 0.5 + 0.053788 = 0.553788

4. 下一步前向验证

使用更新后的权重 w_new = 0.553788 重新计算：

  • 新得分 z_new = 0.553788 * 2.0 = 1.107576；
  • exp(1.107576) ≈ 3.02701（精确值约 3.027012）；
  • 新预测概率：P_new(y=1) = 3.02701 / (1.0 + 3.02701) ≈ 0.75168；
  • 新损失值：L_new = - ln(0.75168) ≈ 0.28544。

在该单一简化样本中，负梯度更新使得该位置预测目标 token 的分值上升、损失下降。在真实大模型中，该操作是在由成千上万个 token 构成的批次上对全网参数并行累积完成的。

3. 现代预训练优化方案：以 GPT-3 为例

在大规模 Transformer 预训练中，优化算法的设计与超参数配置对训练的推进起着关键作用。

根据 Brown 等人（2020）在《Language Models are Few-Shot Learners》附录中的工程披露 2 (Appendix B)，GPT-3 全系列模型的预训练采用了以下统一的优化设置：

批次输入数据 ──► Transformer 前向传播 ──► 交叉熵损失 L
                                            │
                                            ▼ 链式法则反向传播
                                       计算参数梯度 g
                                            │
                                            ▼
                       全局梯度范数裁剪 (clip global norm <= 1.0)
                                            │
                                            ▼
           Adam 优化器 (维护一阶动量 m 与二阶原点矩估计 v)
                                            │
                                            ▼
                       学习率调度 (3.75亿 token 预热 + 余弦衰减)
                                            │
                                            ▼
                       解耦权重衰减 (weight decay = 0.1)
                                            │
                                            ▼
                                       更新模型权重 W

图：预训练参数优化更新流向（教学示意）

3.1 Adam 优化器设置

GPT-3 训练全程使用 Adam（adaptive moment estimation）优化器，超参数设定为：

  • 一阶动量衰减系数：beta_1 = 0.9；
  • 二阶矩估计衰减系数：beta_2 = 0.95；
  • 数值稳定常数：epsilon = 10^(-8)。

在算法内部，优化器为每个参数维护两组状态变量：

  • 一阶动量 m_t：梯度的历史指数滑动平均，记录更新方向的历史惯性；
  • 二阶矩估计 v_t：即梯度的二阶原点矩估计，并非中心化方差，用于按坐标自适应调节每个参数维度的等效更新步长。

3.2 解耦权重衰减（Weight Decay）

GPT-3 所有模型均使用数值为 0.1 的权重衰减系数 lambda = 0.1 提供轻量正则化 2 (Appendix B)。在解耦权重衰减（AdamW 形式）中，每步参数更新包含项 W * (1 - eta_t * lambda)，其收缩因子随当前学习率 eta_t 动态联动，约束模型权重的模长增长。

3.3 全局梯度范数裁剪（Gradient Norm Clipping）

为了控制极端异常输入或长序列突变引起的过大梯度，GPT-3 将全模型所有参数拼合而成的全局梯度向量二范数硬性限制在 1.0 以内 2 (Appendix B)：

若 ||g||_2 > 1.0，则 g <- g * (1.0 / ||g||_2)

需要说明的是，梯度裁剪仅约束反向传播算出的梯度数值范数上限，并不构成模型绝对不发生数值溢出（NaN）或损失发散的理论保证。

3.4 学习率调度与批次规模调度

训练过程中的步长与吞吐量由预设的时间表调度：

  1. 学习率线性预热（Linear Warmup）：在训练最前期的 3.75 亿 token（375 million tokens）中，学习率从 0 线性增加至预设峰值 2 (Appendix B)；
  2. 余弦退火衰减（Cosine Decay）：在随后的训练阶段（直至 2600 亿 token），学习率随余弦曲线平滑衰减至峰值的 10%，并在随后的训练中继续保持在 10% 阶段；
  3. 批次规模预热（Batch Size Schedule）：在训练最初的 40 亿至 120 亿 token 期间，批次大小从 3.2 万 token（32k tokens）线性递增至各模型的满额批次。对于 GPT-3 175B，满额批次大小为 320 万 token（3.2M tokens）2 (§2.1 Table 2.1)。

4. 训练与推理的成本核算：计算量与显存结构

在系统工程层面，预训练处理 token 与推理阶段生成 token 存在显著的计算量与显存状态差异。理解这种差异需要分别考察浮点运算次数（floating-point operations，FLOPs）模型与显存驻留构成。

4.1 计算量估算：稠密参数矩阵乘的 FLOPs 对比

在矩阵乘法中，一次乘累加（a * b + c）计为 2 次浮点运算（1 次乘法与 1 次加法）。

根据 Kaplan 等人（2020）对 Transformer 计算量的形式化推导 3 (§2.1) 以及 Brown 等人（2020）附录中的核算口径 2 (Appendix D Table D.1)：

在忽略嵌入层、注意力层两两位置交互（在模型隐藏维度 d_model 远大于上下文长度除以 12，即 d_model >> n_ctx / 12 时可作为次要项略去）以及层归一化和偏置项的前提下，纯稠密投影权重的前向与反向计算可粗略估算如下：

1. 前向传播（Forward Pass）

每个输入 token 经过各层稠密权重矩阵乘法，每个有效参数执行 1 次乘法和 1 次加法，每 token 的计算量粗略估算为：

C_forward ≈ 2 * N FLOPs / token

其中 N 为非嵌入层模型参数总量。

2. 反向传播（Backward Pass）

在训练反向阶段，网络需要计算两项导数：

  • 损失关于各层隐藏激活值的梯度（用于逐层向后反传）；
  • 损失关于各权重矩阵的梯度（用于计算参数更新量）。

这两项梯度的矩阵运算量分别与前向传播相当，因此反向传播每 token 的计算量粗略估算约为前向传播的 2 倍，即 4 * N FLOPs / token。

3. 训练每 token 粗略计算量

综合前向与反向过程，预训练中每处理一个 token 的稠密浮点计算量粗略为：

C_train ≈ C_forward + C_backward ≈ 6 * N FLOPs / token
维度推理阶段（Inference）预训练阶段（Pretraining，以 GPT-3 175B 为例）
每 token 粗略矩阵计算量约 2 * N FLOPs（前提：缓存历史 KV 计算）约 6 * N FLOPs（前向 2 * N + 反向 4 * N）
处理语料总量单次交互数千 token论文实验固定训练总量：3000 亿（300B）token 2
理论稠密总算力单 token 约 3.5 * 10^11 FLOPs300B tokens 理论估算约为 3.15 * 10^23 FLOPs（论文 Table D.1 报告非嵌入参数 174.6B，实际记录 3.14 * 10^23 FLOPs，约 3640 PFlop/s-days）2

推理计算的重要限定：上述推理阶段单 token 消耗约 2 * N FLOPs 的结论，严格建立在模型实现了 KV 缓存（Key-Value Cache）以复用历史注意力键值的前提下。如果推理实现没有保留历史 KV 缓存，每生成一个新 token 都需要将整个前缀重新前向计算一遍，计算量将随上下文长度累加而显著增加。同时，6 * N 对比 2 * N 的 3 倍比例仅是针对每个已处理 token 的浮点运算次数粗略倍数，不能直接等同于工程执行延迟、硬件电费或训练实现复杂度的实际倍率。

4.2 显存状态结构：假设混合精度配置下的静态状态核算

在推理阶段，显存主要由静态模型权重、当前会话生成的中间激活值以及随序列增长的 KV 缓存构成。但在预训练阶段，由于反向传播与优化器算法的存在，显存开销构成了多层叠加的物理负担。

核算口径说明：Brown 等人论文中并未完整列出其工程实现的具体混合精度字节下界。以下显存数值属于在工业界经典 FP16 混合精度训练配置假设下开展的教学估算（采用十进制 GB，即 1 GB = 10^9 字节），用于向读者解构未分片模型状态的内存构成：

未分片模型静态状态构成 (16 字节 / 参数):
┌────────────────────────────────────────────────────────────┐
│ 1. FP16 模型参数 (2 字节 / 参数)        -> 175B 需 350 GB   │
├────────────────────────────────────────────────────────────┤
│ 2. FP16 反向梯度 (2 字节 / 参数)        -> 175B 需 350 GB   │
├────────────────────────────────────────────────────────────┤
│ 3. Adam FP32 优化器状态 (12 字节 / 参数) -> 175B 需 2100 GB │
│    - FP32 主参数副本 (4 字节 / 参数)                       │
│    - FP32 一阶动量 m (4 字节 / 参数)                        │
│    - FP32 二阶原点矩估计 v (4 字节 / 参数)                  │
└────────────────────────────────────────────────────────────┘
静态状态总计: 2 + 2 + 12 = 16 字节 / 参数 -> 175B 静态基准需 2800 GB
  1. 模型参数（Model Weights）：采用 FP16 存储，占用 2 * N 字节。对于 175B 模型，参数本身需约 350 GB；
  2. 反向梯度（Gradients）：与参数尺寸完全一致，采用 FP16 存储，占用 2 * N 字节（约 350 GB）；
  3. Adam 优化器状态（Optimizer States）：在经典混合精度训练中，为了避免更新步长过小导致数值下溢，优化器维护 FP32（4 字节）的主参数副本、FP32 的一阶动量 m 以及 FP32 的二阶原点矩估计 v。优化器状态自身占用 4 + 4 + 4 = 12 字节 / 参数。对于 175B 模型，优化器状态需要约 2100 GB；
  4. 静态模型状态总和：将参数（2 字节）、梯度（2 字节）与优化器状态（12 字节）合并，单份未分片静态状态合计需要 16 字节 / 参数，对应 175B 模型基准占用约为 2800 GB（2.8 TB）；
  5. 动态激活值（Activations）：在反向传播计算梯度时，各层前向激活值必须参与求导。激活值不仅包含随隐藏维度线性扩展的中间张量，注意力矩阵还包含与上下文长度平方项（n_ctx^2）相关的二次开销。激活值的实际驻留取决于系统实现策略：激活重算（Gradient Checkpointing）以额外的重新前向计算换取保存量的显著降低；张量切分（Tensor Parallelism）则将特定层张量分布到不同设备显存中，但伴随跨设备通信开销，两者在工程权衡上并不等同。

4.3 单设备内存限制与模型并行

普通的标准数据并行（Data Parallelism）工作方式是在每台设备上完整复制一份全量参数、梯度与优化器状态，仅分摊输入数据批次。

从上述未分片静态基准可以看出，若单设备可用内存低于这套假设下的 2800 GB，且不进行内存卸载（Offload）或状态分片，则物理上无法容纳该完整副本。GPT-3 论文报告在实际工程中采用微软提供的高带宽集群，在矩阵乘法内部实施张量并行，并在网络层级之间结合流水线模型并行（Pipeline Model Parallelism）策略 2 (§2.1, §2.3)。具体硬件规模与组网方案取决于工程架构选择，不能由教学配置反推为绝对唯一的硬件门槛。

5. 预训练的参数更新与能力边界

在理解了预训练的机制与成本后，必须依据论文记录客观审视这项技术的实际能力边界：

1. 预训练优化的是文本上下文的统计拟合，而非自觉的逻辑真理

预训练损失函数只衡量模型在现有语料切片上下文中对后续 token 的预测准确度。

  • 梯度回传促使模型将语料中频繁出现的词共现模式、语法习惯与知识关联内化到高维参数矩阵中；
  • 但优化目标本身无法辨识文本内容的真实性。若海量互联网语料中本身包含偏见、歧视、错误事实或不一致信息，模型参数会同样拟合这些有偏差的统计分布 2 (§6.2)。

2. 参数冻结、提示上下文与知识时效

预训练完成后，模型的权重矩阵便不再因常规用户交互而发生反向传播更新。

  • 权重固定意味着模型无法自行获知训练语料截止日期之后发生的外部现实变化；
  • 但这并不意味着模型在推理时不能获取新事实：在上下文学习（In-Context Learning）2 (§2, Fig 2.1) 机制下，用户可以直接在提示词（Prompt）中输入最新材料与上下文示例，模型能够在不修改底层参数的情况下对这些动态输入的材料进行处理；
  • 同时，预训练结束也不意味着参数不可再次变动：在实际技术路线中，模型后续仍可进入继续预训练（Continual Pretraining）或有针对性的微调（Fine-Tuning）流程 2 (§2, §7)。

3. 数据去重与测试集污染（Contamination）边界

在评估海量语料预训练模型的泛化能力时，测试集污染是一个关键的方法论挑战。Brown 等人在 GPT-3 的数据审计中指出，由于原始网页爬取数据量极其庞大，部分下游基准测试集的文本可能被无意纳入预训练语料中 2 (§2.2, §4, Appendix C)。 对测试集与训练集进行严格的 N-gram 重叠度分析与去重过滤，是判断模型能力究竟来自通用泛化还是局部记忆的必要科学步骤。

总结

大语言模型的预训练过程，是一个在工程规模上贯彻微积分求导与数值优化的系统实现：

  1. 自监督目标：无需人工标注，利用单向因果掩码下的交叉熵损失，让文本序列自我提供监督信号；
  2. 反向求导链条：通过链式法则计算损失关于各层权重的梯度，指导参数沿局部下降方向调整；
  3. 优化方案协同：Adam 的一阶动量与二阶原点矩估计、解耦权重衰减、全局梯度范数裁剪与学习率/批次时间表调度，这些设置共同参与参数更新，并调节更新幅度与训练节奏；
  4. 成本结构差异：在忽略次要项的估算下，训练每处理一个 token 需约 6 * N FLOPs 矩阵计算，且单份完整静态模型状态（按 §4.2 的 FP16/FP32 假设，含参数、梯度及 Adam 状态）需约 16 字节 / 参数；推理在配备 KV 缓存时每生成新 token 需约 2 * N FLOPs 矩阵计算，两者在计算量规模与内存结构上存在本质的分水岭。

完成预训练后，模型掌握了丰富的语言续写统计规律，但并未经历针对特定指令任务的对话对齐。如何通过示范数据让模型学会按人类指令回答，以及如何借助人类偏好反馈进行进一步优化？我们将在后续关于监督微调（supervised fine-tuning，SFT）与基于人类反馈的强化学习（reinforcement learning from human feedback，RLHF）的讨论中继续展开。
